# A bounded graph core for computer algebra · `spec:nrz:cas-design`

This design fixes the first executable nrz-cas slice of (`spec:nrz:cas-concept`). One heterogeneous graph stores mathematical syntax, original occurrences, contexts, requests and checked identity applications. Budgeted arbitrary-precision rational arithmetic, deterministic bounded search, portable witnesses, scalar differentiation, Jacobians and rational square-free decomposition execute in the first slice. Integration, sums, series, limits, solving and spectra have typed representations and explicit unresolved outcomes. No numerical evaluation, physical interpretation or consumer migration is included.

The concept remains unchanged. In particular, positive logical path costs, exploratory expansion, calculus as the first route, retained conditions, complete original traversal and independent witness replay remain requirements. This document chooses engineering policies rather than adding mathematical completeness claims. Its new labels belong to NRZ in area nrz; the future package belongs to CAS in area cas.

## Package and admission · `sec:nrz:cas-design-package`

No existing engine crate is a dependency. The rational invariants and arithmetic contract remain local; num-rational is not used. Standard-library ordered containers and a small explicit binary codec require no serialization package, hash package or proof engine. Source verification against the installed dependency and the gate's exact lock bytes occurs in the CAS-foundation step (`step:nrz:cas-foundation`); this document does not claim a locally fetched petgraph API audit.

## Graph, syntax and source evidence · `sec:nrz:cas-design-graph`

**Definition (Storage and identifiers)** · `def:nrz:cas-design-storage`

Use `petgraph::graph::DiGraph<Vertex, Edge, u32>` as append-only storage. Nodes and edges are never removed or mutated after publication; a new context or changed expression is a new node. The compact directed multigraph permits ordered operands and multiple typed links between the same vertices. StableGraph's removal support is unnecessary. Expression edges form a DAG, proof-dependency edges form a DAG, and checked relation edges may form cycles, as required by (`def:nrz:cas-graph-model`). Traversal never interprets arbitrary graph adjacency as a mathematical proof.

Every published object has a private checked u64 logical serial, assigned consecutively in deterministic admission order within its kind. Private maps translate these serials to petgraph indices; the serial never contains or derives from an index. Batch order is source/declaration order, then child-before-parent structural order, then the ordered rule/match schedule. Overflow is refused before admission. Public handles carry an unforgeable store token plus the serial and kind; a private shared ownership token permits foreign-store rejection without a global counter. Runtime token identity is not mathematical identity and is omitted from Debug, ordering keys, witnesses and exports. Deserialization builds fresh handles after validating portable local references. Even structurally identical stores reject each other's live handles.

**Table (Vertex and edge vocabulary)** · `tab:nrz:cas-design-graph-kinds`

|Vertex|Payload and permitted links|
|------|---------------------------|
|Source|Immutable UTF-8 bytes, caller source key and admission ordinal; no mathematical conclusion.|
|Occurrence|Source/span or generated provenance, expression link and ordered child-occurrence links; distinct even when syntax shares.|
|Expression|Operator tag, sort, scope signature, scalar literal or symbol metadata; numbered Operand links.|
|Binder|Bound sorts, binder convention and optional display names; Body and numbered Bound links; display names do not determine meaning.|
|Context|Field, domain/branch policy, declarations and canonical assumption set; Declaration and Assumption links.|
|Condition|Typed predicate with ordered arguments and optional bound scope; PredicateOperand links.|
|Request|Operation, context, roots, target/ranking and effective limits; Input, InContext and Goal links.|
|Application|Rule/version, relation, substitution and direction; ConclusionLeft, ConclusionRight, Premise and InContext links.|
|Proof|Primitive application, composition or derived expansion; ordered DependsOn links and a proved judgment.|

Edges are an enum with the roles just named, a checked position where applicable and no arbitrary user-defined meaning. Every role has an endpoint-kind table checked at admission. Operand positions are consecutive from zero and unique for one expression; premise order follows the rule schema. Source provenance and original child links are never replaced by equality links. Relation metadata lives on Application vertices, so a multi-premise identity is one checked inference even though its storage has several edges. Read APIs return ordered records by role/position/logical serial and never rely on petgraph neighbor iteration order.

**Definition (Structural keys and sorts)** · `def:nrz:cas-design-interning`

Interning uses a BTreeMap keyed by exact structural records: operator discriminant and complete payload, mathematical sort, canonical semantic context header, scope signature, scalar/constant/declaration key and ordered child logical IDs. The complete payload includes exponents, branches, extents and selection conventions, so x² and x³ cannot collide. Identifiers are case-sensitive UTF-8 byte strings without normalization, limited by the byte budget; distinct declarations may have the same display name but have distinct caller keys. Scalar operations remain binary and ordered at construction. Associativity, commutativity, constant folding and cancellation require checked identities rather than changing the original syntax key. Equality of keys is structural sharing alone. No equality classes are merged.

Sorts are Integer, Scalar over a named field, Boolean, Function with an ordered signature, Matrix with scalar field and checked mathematical extents, and Set over a sort. Integer-to-scalar embedding is explicit. Extents are positive or zero integer literals or declared integer extent parameters with their predicates; positivity required by a particular operation becomes its condition. The first executable coefficient field is Q, embedded into real scalar expressions for real differentiation; complex and named field contexts are representable but their unimplemented algorithms return Unsupported. Matrix multiplication, scalar multiplication and entrywise operations have different tags. Rational and real scalar contexts do not equate matrix products by scalar commutativity. No physical dimensions, measures or axes occur here.

The expression vocabulary includes rational literals; free and bound variables; Pi and E as exact named real constants; Neg/Add/Sub/Mul/Div; integer and general powers with separate conventions; named functions with signatures; derivative and integral expressions; finite sums; formal or analytic series; limit expressions; predicates and solution sets; matrix literals/comprehensions, transpose, ordered multiplication and spectral selections; and algebraic-root requests. Operator nodes retain necessary domain and branch data. Unknown valid requests stay typed objects. An algebraic-root request stores a rational polynomial, its variable, field, multiplicity request and selection predicate or requested ordered-root index; it does not assert existence or a unique selected number before that condition has a proof. Pi is never stored as a rational approximation.

**Rule (Original occurrences and complete walks)** · `rule:nrz:cas-design-occurrences`

Admission accepts a flat, child-before-parent batch of expression and occurrence drafts. Each source occurrence has a source ordinal and an optional half-open byte span whose ends are UTF-8 boundaries within the retained source. A missing span is explicit; a generated occurrence has no source span and instead names its derivation. Reusing a source key with different bytes is invalid. Each original occurrence has one parent except roots; repeated syntax needs repeated occurrence vertices, even when their expression links coincide. The draft graph therefore cannot disguise a shared source occurrence as two visits. A source may be supplied by checked builders or the original-expression parser below.

A source may also enter through `source::parse_original(cas, source_key, text, declaration_header, budget)`, returning an `OriginalForm` through the same atomic source/expression/occurrence draft transaction. This source factory is now the declared original-expression parser; it creates no second expression type and supplies no traversal receipt or mathematical equality. Its text grammar, also stated in the CAS README, is:

```ebnf
expression     = sum ;
sum            = product, { ("+" | "-"), product } ;
product        = unary, { ("*" | "/"), unary } ;
unary          = ("+" | "-"), unary | power ;
power          = atom, [ "^", exponent ] ;
atom           = number | name, [ "(", [ sum, { ",", sum } ], ")" ]
               | "(", sum, ")" ;
exponent       = signed_integer | "(", signed_integer, [ "/", digits ], ")" ;
number         = digits, [ ".", digits ], [ ("e" | "E"), signed_integer ] ;
signed_integer = [ "+" | "-" ], digits ;
digits         = digit, { digit } ;
name           = (letter | "_"), { letter | digit | "_" } ;
digit          = "0" ... "9" ;
letter         = "A" ... "Z" | "a" ... "z" ;
```

ASCII whitespace may separate tokens; a number and each signed integer are contiguous. The complete input must match. Binary operators associate left; powers bind above unary signs and have exactly one literal exponent. A fraction denominator must be nonzero. Ordinary `1/2` retains `Div` and both original operands; decimals and scientific tokens become exact `Operator::Rational` values. A directly prefixed negative numeric token becomes a signed rational unless a power intervenes: `-2^2` retains `Neg(IntegerPower(2))`. Parentheses and unary plus widen the enclosed occurrence's span without adding an operator. Leading/trailing whitespace is outside the root span.

Names resolve by exact declaration key in the supplied admitted header, including inherited declarations; display names do not create aliases. Numeric literals use that header's scalar field, with no implicit sort coercion. Calls retain ordered arguments and their declared signature. Reduced exponents fitting `i64` use `IntegerPower`; all other exact rational exponents use `GeneralPower` with the header's explicit `Branch` and an original rational exponent operand. An integer exponent is operator payload, so it has no separate operand occurrence; a general exponent's occurrence span includes its optional parentheses.

The parser's recursive-descent productions suspend on explicit heap continuation frames. The existing `Budget` limits grammar/operand depth, total original occurrences, numeric literal bytes, source/name bytes, candidate storage, arithmetic and work before consumption; raising depth does not introduce native-stack recursion. `ParseError` borrows the source key and offending name, records the offending byte span and first unconsumed byte, and distinguishes stable syntax codes (`UnexpectedToken`, `UnclosedParenthesis`, `TrailingOperator`, `InvalidLiteral`, `InvalidExponent`), unknown names, non-callable names, arity and unchanged underlying `Fault` values. Failure leaves the store unchanged while retaining consumed work. Consumer migration and simplifier changes are outside this parser capability.

`walk_original(root, limits)` produces a deterministic postorder sequence with root-relative operand paths, binder-entry records and source locations, visiting every occurrence exactly once and every child position. It uses a bounded explicit stack. Canceled operands, zero factors and inactive syntactic alternatives are all visited. A quantified body is visited once as syntax, with its binder environment; there is no implicit sum expansion. Only a complete walk mints a root/store/generation-bound TraversalReceipt. Search and calculus requests on original roots require that receipt. Exhaustion gives a partial diagnostic sequence but no receipt. A receipt proves coverage, never physical validity (`rule:nrz:cas-conditional-witnesses`). Generated roots have a checked provenance receipt from their complete construction; exporting them as a new original input for a client requires a fresh occurrence materialization and walk.

Walk work is charged as frames and events are produced, with each reached immutable interpretation record charged once per walk. Its record charge is at least twice that record's logical payload, so a walk reaching the entire store retains the former conservative full-store floor. Unrelated records contribute no work. Staged payload checks cover the walk's own live frames, retained events, dependency frontier, visited-record set and encoding scratch.

**Construction (Capture-safe scope operations)** · `constr:nrz:cas-design-substitution`

Bound references use a de Bruijn depth and slot into an explicit stack of binder sort frames. Free references use declaration keys, never display names. A scope signature is the ordered stack of bound sorts; it participates in interning, so open terms from incompatible frames cannot share. Binder bodies see the new frame; a sum's bounds and a limit's approach point see the outer frame. Matrix comprehensions bind row and column slots in a specified order. These conventions fix off-by-one and shadowing behavior without a fresh-name oracle. Alpha-renaming changes occurrence display metadata only; it preserves the mathematical key.

Free substitution is simultaneous: traverse the old term, replace only the declared free keys, lift free-standing bound indices in each replacement by the current binder depth, and do not recursively substitute inside inserted replacements. Replacements must have the destination free declarations, sorts and initial scope signature. Bound instantiation replaces the selected depth/slot, shifts replacement references when passing nested binders and decrements references to frames removed by that instantiation. Every shift and decrement is checked and every visit charged. The CAS-foundation step (`step:nrz:cas-foundation`) executes free substitution and the generic checked scope machinery; it does not perform beta reduction, sum unrolling or integral substitution. A free variable called x inserted beneath a binder displayed as x remains free. The tests use different and equal display names, nested frames and deliberately dangling indices. This specializes the substitution requirement in (`credit:nrz:cas-rewriting-literature`) without importing an implementation.

**Definition (Canonical mathematical context)** · `def:nrz:cas-design-context`

A context key contains field/characteristic, real or complex domain convention, all power/logarithm branches, free declarations sorted by caller key with their sorts and function signatures, and a sorted duplicate-free set of assumption predicates with their declared hypothesis keys. Predicate terms use structural keys and de Bruijn scopes; conjunction is flattened and sorted, while disjunction and quantifiers retain structure. Different hypothesis provenance is not erased merely because predicates coincide. Predicate kinds include Defined, NonZero, Positive, NonNegative, IntegerRange, Differentiable, Equal, Symmetric and a typed named predicate for unimplemented facts. Contexts are immutable. The operation's bound frames are explicit alongside the context, not ambient mutable state.

The semantic header consists of the field, domain/branch conventions and declarations, computed before assumption terms. Expression keys include this header; the full context key then adds the assumption predicates built under it. This avoids a cyclic key definition. Two contexts differing only in hypotheses may share literal syntax, but applications, proof judgments, derivative caches and search states always name the full context. Such sharing never transports an equality or discharges a guard across those contexts. A changed function signature or branch convention changes the header and therefore the expression keys.

Canonicalization is syntactic, not a decision procedure for logical equivalence. `x>0` and a distinct assumption `x!=0` do not silently identify two contexts. A bounded condition checker proves rational signs, literal equalities, nonzero products/integer powers from nonzero factors, positivity implying nonzero, and recursive definedness for the executable scalar grammar. Exact assumptions discharge identical predicates only as hypotheses of Gamma; their provenance remains in the result. Direct contradictions, such as rational zero declared nonzero or both P and its explicit negation, produce InvalidContext. Unrecognized consistency stays Unknown, recorded in every result; discharged relative to Gamma never means that Gamma has a nonempty model. A residual predicate, an assumption and a derived proof are different evidence variants.

**Rule (Transactional admission and bounded storage)** · `rule:nrz:cas-design-transactions`

All public construction is staged. Validate a flat draft batch, its handles, sort/scope relations, acyclicity by backward references, spans, keys and predicted node/edge counts before assigning published IDs. Public draft admission checkpoints node and edge counts, retained payload, source and original-occurrence counters, and the bounded next-identifier map. An undo journal records new logical indexes, structural interning keys, source keys and occurrence-parent claims. On any error, including mid-batch Work exhaustion, remove appended edges and nodes in reverse order, undo those insertions and restore every checkpoint. No partially checked node or newly consumed serial is visible on failure; only the request's work counters and diagnostics change. No candidate mutation is observable through a callback. Admission work charges the pending encoded payload, a fixed counter-checkpoint allowance and the logical key probes and validation actually performed. It does not copy or charge unrelated retained records. Existing store occupancy plus pending payload and journal reservation still obey the unchanged storage ceilings. Private proof producers that actually fork a store continue charging their copy.

All input-controlled lengths, sums, products, indices and capacity requests are checked before allocation. Library-owned vectors use fallible reservation; capacity, u32 index and u64 serial limits are preflighted before calling petgraph insertion. Petgraph storage allocation and standard-library allocation failure can terminate the process under Rust's allocator contract; that environmental failure is not a recoverable mathematical outcome. The no-panic contract forbids input-triggered panic paths, recursive stack exhaustion, unchecked indexing, overflow and panic-based error conversion. It does not promise recovery from host termination or an allocator abort. Capacity-overflow inputs and all service-budget refusals are errors as values. This distinction avoids claiming that petgraph supplies a fallible allocator API it does not promise.

## Exact coefficients · `sec:nrz:cas-design-numbers`

**Decision (Budgeted arbitrary-precision rationals)** · `dec:nrz:cas-design-rationals`

Use a private sign plus coprime arbitrary-precision unsigned numerator magnitude and positive denominator, each stored in num_bigint::BigUint. Zero has positive sign and denominator one. Integers are the denominator-one subset; all public constructors reduce and check the invariant. The sign/magnitude choice makes negation independent of any machine signed-minimum case. Every number reports its measured component bits. The component-bit ceiling defaults to 4096 and the intermediate-bit ceiling to 8192; checked request overrides can raise or lower both without a fixed representation ceiling. Allocation lengths, limb counts and work estimates still require checked machine-size conversions. Values outside the active budget are resource refusals, not floating replacements or claims of mathematical undefinedness (`rule:nrz:cas-exact-domain-policy`).

Addition first divides denominators by their gcd, performs checked unsigned products and signed-magnitude accumulation, then reduces. Multiplication/division cross-cancel numerator/denominator pairs before checked products. Division by zero is InvalidArithmetic; intermediate or final magnitude overflow is Exhausted with ArithmeticRange and the operation location. Every bigint operation preflights a conservative result-bit bound against intermediate_bits and reserves work proportional to a conservative quadratic limb-operation bound before calling the underlying operation. Actual measured result bits are checked as well; a reduced admitted component must satisfy component_bits. Clones, digit conversion and comparisons are charged by measured size. A conservative preflight may refuse a route whose eventual cancellation would fit, which is an explicit resource refusal. A mathematically representable result can still be refused if this bounded route needs an oversized intermediate. Euclidean gcd consumes a step for each remainder. Ordering uses Euclidean continued-fraction comparison instead of overflowing cross multiplication; each division is charged. Powers use checked repeated squaring with a bounded integer exponent, and preserve domain conditions when acting on expressions.

The literal reader accepts an optional sign, decimal digits, an optional decimal point and signed decimal exponent, or a signed integer numerator followed by a slash and unsigned nonzero integer denominator. It rejects mixed forms, malformed syntax, zero denominators and non-ASCII numeric characters. It counts bytes before scanning, checks decimal exponent magnitude before forming powers of ten, strips harmless decimal zeros where possible and performs exact reduction. No float is parsed. Serialization uses the sign and canonical length-prefixed little-endian magnitudes, so decimal spelling does not alter number identity.

**Argument (Reference coefficient capacity)** · `arg:nrz:cas-design-number-capacity`

For H_3 through H_8, the literal coefficients are 1/(i+j-1), with denominators at most 15. This comfortably represents every entry; no claim follows that all characteristic coefficients, roots or elimination intermediates fit. Those spectral requests remain symbolic (`ex:nrz:cas-hilbert-integral`). Kahan's rational parameters are 4/5 and 3/5. At order 40 the last diagonal is (4/5)^39, whose reduced numerator and denominator need 79 and 91 bits, respectively; the other nonzero entries also fit. Its square has denominator 5^78 requiring 182 bits and numerator 4^78 requiring 157 bits. Both now fit comfortably under the default 4096-bit component ceiling, and exact repeated multiplication is in scope. Lowering component_bits to 181 refuses this reduction with ArithmeticRange; no floating substitute is produced. The symbolic geometric identity in (`ex:nrz:cas-matrix-fixture-sums`) does not require expanding that denominator. Wilkinson's displayed 2^54 fits as an integer.

Rump's unchanged fixture uses 1335/4 and 11/2 with a=77617 and b=33096. Repeated integer powers through b^8 and the displayed rational products and left-to-right sums need at most 123 numerator bits after the cross-cancellations above; denominators are one until the final a/(2b). For example b^8=1439474789212538429291115400277262336 and (11/2)b^8=7917111340668961361101134701524942848. The polynomial terms cancel to -2, giving -54767/66192. The fixture's identity under a²=(11/2)b²+1 separately explains that cancellation. This is a capacity argument for exact symbolic arithmetic, not an implementation of the fixture's floating evaluation convention. Larger substitutions or another grouping can refuse. Arbitrary-precision storage under the default size budgets therefore supports these input coefficients, the Kahan square and the finite Rump example. Larger exact reductions are limited by the declared component/intermediate/work budgets, rather than by an inherent machine-integer representation ceiling.

## Identities and proof kernel · `sec:nrz:cas-design-identities`

**Definition (Versioned rule schemas)** · `def:nrz:cas-design-rules`

A RuleSpec has an ASCII RuleKey, a positive u32 semantic version, a relation kind, ordered typed metavariables with binder depths, left/right conclusion templates, ordered premise templates, condition templates, permitted orientations and a closed checker tag. Templates are a flat DAG of operator patterns and metavariable references; there is no executable user callback or source-language eval. Pattern matching is structural and ordered, never matching modulo associativity or commutativity implicitly. Repeated metavariables must match the same structural term. The checker reconstructs the instantiated endpoints and side conditions from the schema, checks scopes and sorts, and verifies every premise. A caller's displayed endpoint or condition list cannot override that reconstruction.

Primitive schemas are compiled into the library and registered atomically by their closed checker tags. External callers cannot label an arbitrary equation primitive. Registration validates keys, versions, arities, bound references, relation compatibility and the complete supported checker/schema pairing; duplicate identical registrations are idempotent and conflicting reuse of a key/version is invalid. A registry snapshot has an ordered manifest of these exact definitions. Every request pins that snapshot. Adding or changing a rule creates a new snapshot, and changing mathematical meaning requires a new semantic version. An unrecognized version in a witness is Unsupported, not automatically mapped to the newest implementation.

RelationKind includes EqualOnDomain, Derivative with variable/direction, Jacobian with ordered variables, SquareFreeDecomposition with coefficient field/variable, Antiderivative, FiniteSum, SeriesCongruence with order/remainder convention, Limit with approach, SolutionSet with domain/completeness status, and Spectral with selection convention. Only EqualOnDomain has generic reversal and transitive composition in the CAS-foundation step (`step:nrz:cas-foundation`). Other relation compositions require a specific kernel rule; a derivative conclusion cannot be used as equality between a function and its derivative. Antiderivative and other future relations can be represented without a primitive capable of proving them. A point substitution instance of an equality remains equality with the substituted guards; it never proves a surrounding limit.

**Table (Trusted first-slice vocabulary)** · `tab:nrz:cas-design-primitives`

|Checker family|Version-one content and required evidence|
|--------------|-----------------------------------------|
|Equality structure|Reflexivity with endpoint definedness; symmetry; transitivity with identical middle term/context; ordered congruence at a checked operand path with reconstructed outer definedness.|
|Scalar field|Associativity and commutativity of scalar Add/Mul, distributivity, additive inverse, zero/one identities, quotient cancellation and integer-power recurrence; Q or admitted real scalar domain and every original partial operand defined.|
|Exact literals|Checked rational arithmetic and sign/zero comparisons; the checker recomputes them from the literal operands.|
|Finite polynomial jets|Equality of bounded sparse multivariate Q coefficient maps, treating permitted named constants as formal indeterminates; a finite coefficient/jet identity, not sampling or arbitrary function equality.|
|Rational identity|Clear denominators, retain the definedness/nonzero guards of both expression trees, and check the resulting polynomial identity by finite jets.|
|Conditions|An exact Gamma assumption, rational facts, positivity implying nonzero, nonzero products/integer powers, definedness closure for the executable scalar grammar and conjunction introduction/elimination.|
|Scalar derivatives|Constant, variable, Neg, Add/Sub, product, quotient and fixed integer-power rules, each with derivative premises for children and its real-domain conditions.|
|Derivative assembly|Equality transport of a derivative output, free substitution of an equality with all guards, and Jacobian assembly from one checked partial derivative per ordered row/column.|
|Polynomial multiplicity|Formal polynomial derivative, checked exact products/divisions, gcd certificates by divisibility plus Bezout identity, and square-free product certification with derivative gcd witnesses.|

These are the complete trusted mathematical families of the slice. Each concrete schema receives a distinct key such as `eq.distribute`, `diff.product`, `poly.jets-equal` or `poly.square-free`, version 1; the manifest enumerates the concrete keys, fixed ordered metavariables and orientations in the implementation. In particular there is no primitive that accepts a boolean supplied by a searcher, a claimed shortest path, a generic user theorem or an externally asserted derivative rule. Hypotheses about an unknown function can appear as conditions but cannot manufacture a missing differentiation algorithm. Scalar field identities are justified by field axioms; finite jets and the derivative/multiplicity rules have the arguments and references in (`constr:nrz:cas-derivative-equality`), (`constr:nrz:cas-differential-models`) and (`constr:nrz:cas-derivative-factorization`).

For default strict integer powers, n=0 requires a nonzero base, n>0 permits a zero base, and n<0 requires nonzero. There is no implicit value of zero to zero. Polynomial coefficient maps instead use the ring's empty monomial as one and omit exponent-zero factors when materializing an expression. A context can represent another explicit convention, but the CAS-foundation step (`step:nrz:cas-foundation`) will not apply the strict-power schemas in that context. The n=1 derivative is the child's derivative directly, avoiding an unnecessary zero-power restriction. The n=0 derivative retains the original nonzero guard. General expression-valued exponents, real logarithms and complex branches remain representable and unresolved for differentiation in this slice.

**Rule (Condition accounting and derived shortcuts)** · `rule:nrz:cas-design-proof-conditions`

An application records a judgment under Gamma with a canonical residual predicate set P, separately referencing Gamma assumptions and proof nodes that discharged other requirements. The condition checker returns Proven, Assumed, Refuted or Unknown. Assumed means proved relative to an explicit hypothesis in Gamma. Unknown becomes a visible residual when the request permits conditional results; Refuted blocks the application. A discharged result has no residuals, but still reports its assumptions and the context-consistency status. No search rank or cost comparison removes a predicate. Quantified definedness beneath binders is retained as a scoped predicate; the scalar checker does not replace it with a check at one index.

A derived shortcut is an endpoint/context/relation/residual tuple plus a previously replayed proof DAG with all primitive rule versions. The primitive leaves precede their users; expanding an existing shortcut visits its full acyclic dependency closure. A lemma cannot reference itself, a newer registration, or a proof that depends on itself. Admission replays first, then compares its configured positive cost with the current best known route for exactly that tuple under the pinned cost policy, excluding the candidate and anything depending on it. Admit only a strict improvement; absence of an incumbent is infinite cost. An incumbent is a known route, not an unproved claim that no cheaper route exists. Changing cost policy invalidates these improvement records and requires recomparison, while the mathematical proof remains reusable. Proof storage/replay is charged even for a cost-one lemma (`dec:nrz:cas-path-cost`).

## Search and finite resources · `sec:nrz:cas-design-search`

**Procedure (Two ordered queues)** · `alg:nrz:cas-design-queues`

A search state is the request operation/relation, current structural endpoint, context, canonical residual set and remaining task payload. Its best-known path carries checked cost, proof predecessor, peak unfolded expression size and total expansion credits consumed. Two BTreeSet priority queues contain references to the same pending labels: cost order `(cost, goal_rank, state_key, admission_serial)` and progress order `(goal_rank, cost, state_key, admission_serial)`. The default epoch pops four live cost labels then one live progress label; both quotas are positive request parameters. Empty queues donate their remaining slots to the other queue. A popped label is removed from both sets and expanded once unless a nondominated better label later reopens it. Stale references are charged and discarded.

Initialization derives definedness obligations from the complete original syntax, accounts for every partial operand and checks them under Gamma. The initial reflexive equality and residual set therefore already retain the original domain. A later cancellation cannot win a cleaner hypothesis class by forgetting where that domain came from. Refuted initial guards produce a refuted-domain blocker; unsupported condition reasoning retains explicit residuals rather than claiming them true.

For each expansion enumerate rule keys/versions, orientations, operand paths in lexicographic order and substitutions in structural order. A resumable cursor processes at most 32 match attempts per label visit by default. A still-live cursor returns to the queues with an increased admission serial, preventing one expression with many positions from monopolizing an epoch. Failed matches and conditions consume work. Existing checked outgoing applications are enumerated in this same stable order; new applications are staged, replay-checked and committed in batches. Never pick a direction by hash iteration or address. Both simplifications and allowed distributive/power expansions are generated. No generic rule introduces a fresh variable, arbitrary term or new assumption from an unbounded domain.

Within an identical state key, label A dominates B only when A has no greater cost, peak size, consumed expansion credits, proof depth or measured witness footprint, with at least one strict inequality. In addition, A's required proof/source/rule support must be a subset of B's; otherwise differing future dependency sharing makes dominance unsafe and both labels remain. Exact resource/support ties choose the lexicographically smaller proof encoding. A cheaper but more expanded route cannot erase a costlier route that retains enough expansion budget to complete. Keep the bounded nondominated set otherwise. Different contexts, relation payloads or residual sets never dominate each other. Derivative memoization additionally keys the differentiation variable, and Jacobian memoization retains row and column identities. Global work consumption is monotone across all labels; it is not restored by revisiting a state.

**Decision (Costs and task ranks)** · `dec:nrz:cas-design-search-policy`

The default `logical-v1` policy assigns weight 1 to equality structure, exact literal steps and condition introductions used as transitions; weight 2 to scalar field and scalar derivative steps; weight 4 to polynomial/rational identity transitions; and weight 8 to certified square-free construction. A checked derived shortcut defaults to weight 1. A multi-premise transition counts as one logical transition at its family weight; its supporting proofs consume replay work but do not masquerade as additional path edges. The proof report also records the expanded primitive-step count separately. A path sums u64 weights with checked addition. Neither cost nor that count measures time or numerical error.

An override supplies a versioned policy key and a complete positive weight table for the pinned registry, with each weight at most 1,000,000. Reusing a policy key/version with different contents is invalid. Weights and quotas are part of the request and canonical result; zero quotas, zero weights and missing entries are InvalidPolicy. Goal ranks use the following lexicographic tuples, then structural expression order. They compare candidates only within the same hypothesis class; request policy either retains the separate conditional classes or requires discharge. A best result never silently substitutes a better-ranked theorem with stronger assumptions.

|Request|Goal rank before the structural tie-break|
|-------|-----------------------------------------|
|Simplify or equality target|Target mismatch if given, unresolved scalar operations, unfolded size, depth.|
|Expand|Failure to reach the declared finite coefficient form, uncollected monomials, coefficient-map size, depth.|
|Differentiate or Jacobian|Number of pending requested derivatives, pending scalar simplifications, unfolded size, depth.|
|Square-free decomposition|Uncertified factors, unresolved multiplicity layers, total represented degree, size.|
|Integrate|Remaining antiderivative obligations, residual repeated-pole degree, size; no generator in the CAS-foundation step (`step:nrz:cas-foundation`).|
|Sum|Remaining antidifference obligations, unproved endpoint terms, size; no generator in the CAS-foundation step (`step:nrz:cas-foundation`).|
|Series|Unproved requested coefficients and missing remainder/congruence evidence, size; no generator in the CAS-foundation step (`step:nrz:cas-foundation`).|
|Limit|Unproved approach/domain obligations and remaining limit requests, size; no generator in the CAS-foundation step (`step:nrz:cas-foundation`).|
|Solve|Missing solution-set coverage and unverified candidate branches, size; no generator in the CAS-foundation step (`step:nrz:cas-foundation`).|
|Spectral|Unproved multiplicity/order/selection obligations, remaining spectral requests, size; no generator in the CAS-foundation step (`step:nrz:cas-foundation`).|

Expansion charge for one transition is the positive part of the increase in unfolded expression-node count. Path credits sum these charges without refund when a later step shrinks. Peak size is the maximum unfolded size on that path, including temporary candidates; DAG sharing does not make a gigantic expanded tree free. A saturating-at-limit traversal computes unfolded size without actually duplicating the tree. New shared graph records and proof records additionally consume storage limits. A refused oversized candidate consumes attempted work and is reported in the search statistics. If it could have supplied an otherwise unexplored route, ending the search reports Exhausted with the limiting reason and any best verified result, not an exhaustive absence of a proof.

Separate public calls start fresh work counters but retain store occupancy.

The ledger checks before consuming the next unit. Exactly the limit is permitted, limit plus one refuses, and arithmetic used to account for work itself never wraps. A byte comparison charges its inspected bytes; tree-map access also charges comparisons and one container operation. Sorting reserves a checked quadratic comparison bound on its already bounded input, rather than assuming a particular library sort implementation. Polynomial loops charge coefficient pairs and long-division iterations individually. Memory rows bound logical payload, not allocator metadata or resident-set bytes; the simultaneous old state, candidate state and working queues are all accounted for in their respective rows. This is finite service work, not a wall-clock deadline or a promise to use all requested capacity.

All checker invocations within one request share that single replay ledger, so checking successive candidates does not reset its allowance. Heuristic exploration cannot consume the checker's reserved work. Each candidate recorded as best has already replayed successfully; if later generation or replay exhausts, only a previously checked candidate may be returned. Immutable VerifiedWitness records do not need a redundant second replay merely to export them. A standalone replay call starts a fresh checker ledger.

A result envelope has a fixed small bounded error header available even when output_bytes is zero; no witness is emitted when it will not fit. The output limit covers optional payload, while the minimal status, reason, effective limits and fixed-size counters remain available. A best proof whose export does not fit is retained only by an in-store checked handle and explicitly marked NotExported; portable proof delivery requires a larger output budget. Formatting, measuring and canonical encoding still consume the relevant ledger and cannot loop after it is exhausted.

**Rule (Frozen-snapshot optimality)** · `rule:nrz:cas-design-optimality`

Heuristic exploration returns a best verified candidate and its actual cost; it makes no shortest-path claim. An explicit `certify_frozen_cost` request snapshots the currently admitted applications for one context/relation/residual class and pinned weight policy, expands each logical transition to its endpoint adjacency, and runs bounded Dijkstra to completion on that finite immutable projection. It reports the snapshot's canonical manifest, policy and shortest cost only if every reachable vertex was settled and every admissible edge checked. The manifest is the ordered endpoint/application records, not a clock or pointer. Adding a later application produces a new snapshot; an exhausted run supplies no optimality certificate. The mathematical witness remains independently valid without this search certificate. This is precisely the finite positive-weight claim licensed by (`credit:nrz:cas-dijkstra`), with no conclusion about ungenerated identities or best goal rank over all expressions.

The frozen claim is about paths through already admitted logical transitions, not about whether the original generator could discover that path with its expansion credits. Its schema explicitly states that distinction. A claim constrained by path-dependent generation resources would need an expanded resource-state graph and is not offered in the CAS-foundation step (`step:nrz:cas-foundation`). Replay and output limits still bound the certification call and may prevent certificate delivery.

## Portable witnesses and replay · `sec:nrz:cas-design-witnesses`

**Definition (Witness records and canonical bytes)** · `def:nrz:cas-design-witness-format`

A Witness contains format/semantic versions, the rule manifest actually used, mathematical context and declarations, exact endpoint terms, relation payload, canonical residuals, hypothesis references, optional original source/occurrence attachment, and a topologically ordered proof DAG with a designated final node. Primitive proof records contain key/version, typed substitution, operand position, ordered premise references and claimed endpoints; composition and derived records name earlier proofs. Rule-checker reconstruction is authoritative. Search costs, budgets and frozen-search claims live in a separate response envelope and have no authority in the mathematical checker.

Canonical format v1 is a binary stream beginning with the eight ASCII bytes `NRZCAS01`. Unsigned scalars and lengths are little-endian fixed-width u32 or u64 as specified by the record field; signed exponents use a sign byte followed by a u64 magnitude, with negative zero forbidden. A rational is one sign byte and two u32-length-prefixed little-endian unsigned magnitudes, required to be reduced and within the configured bit budgets. Magnitudes have no redundant most-significant zero byte; zero numerator uses length zero, sign zero and denominator one. The decoder checks announced byte lengths and bit bounds before constructing a bigint. Strings and vectors have a u32 byte/item length followed by their exact content, without padding. Optional values use one byte 0 or 1. Invalid tags, trailing bytes, nonminimal zero forms, duplicate set entries or out-of-order fields are rejected. There are no floats, platform-sized integers, native enum-layout bytes, unordered maps or serialized memory addresses.

Top-level order is header, used-rule manifest, context, declaration/condition/term tables, source/occurrence attachment, relation/endpoints/residuals, proof table and final proof index. Tables use u32 local indices; dependencies within a term or proof table point strictly backward. Cross-table references, such as a context's condition terms, are range/sort checked after decoding the bounded tables and before publication. Terms are emitted by deterministic child-before-parent traversal of ordered roots, deduplicated by structural key; proof roots are traversed in schema premise order. Declaration and assumption sets are sorted by canonical keys. The canonical root order is context predicates, conclusion left/right or ordered result entries, then proof terms and source attachments in source admission order. Unreferenced table records are rejected. A bounded re-encoding must exactly match input bytes, which rejects alternate table orderings as well as malformed scalar encodings. This does not equate witnesses that choose genuinely different valid proofs.

Wire operator tags are fixed by v1: Rational 0, Free 1, Bound 2, Constant 3, Neg 4, Add 5, Sub 6, Mul 7, Div 8, IntegerPower 9, GeneralPower 10, Call 11, Derivative 12, Integral 13, Sum 14, Series 15, Limit 16, Predicate 17, Set 18, Matrix 19, Comprehension 20, Transpose 21, MatrixMultiply 22, Spectral 23, AlgebraicRoot 24, MatrixMap 25, IntegerEmbed 26 and Entrywise 27. MatrixMap's subtag identifies determinant, trace, adjugate or inverse with distinct shape/domain checks. Entrywise carries a scalar-operation subtag and requires equal mathematical extents, with no implicit broadcasting. Other record enums likewise have explicit codec discriminants and exhaustive decoders; changing a field's meaning or a discriminant requires a new format/semantic version, not a Rust type reorder. Their implementation is a format table, not derived Debug output or a general-purpose object serializer.

**Procedure (Bounded independent checker)** · `alg:nrz:cas-design-replay`

Decode into unpublished flat records after checking the total byte limit and every announced count before reserving memory. Validate UTF-8, source spans, local-reference bounds, declaration uniqueness, scopes, arities, mathematical sorts and canonical context keys. Reject forward proof references and dependency cycles. Resolve every primitive by exact key/version against the checker registry. Reconstruct its substitution and endpoints, independently recompute exact arithmetic or coefficient facts, prove or explicitly retain every condition, and verify composition's middle term, relation and context. Rebuild the final judgment and compare it with the declared conclusion and residual set. Only then mint VerifiedWitness and publish any imported records. This checker never invokes the heuristic queues or accepts their memoized truth flags.

Condition statuses in imported bytes are claims to check: changing Unknown to Proven cannot discharge an obligation without a proof or exact Gamma assumption. Changing a coefficient, derivative variable, bound depth, premise index, branch, field, endpoint, source span or rule version must either be rejected or produce a different correctly proved judgment that fails the caller's expected-claim comparison. `replay(bytes, expected_claim, limits)` requires the caller to supply the mathematical claim it intends to accept; attachments can additionally be compared with caller-owned source bytes/keys. `inspect(bytes, limits)` may report what a valid witness claims but never silently treats that as the caller's desired statement.

No checksum is presented as proof or authentication. Canonical encoding plus mathematical replay detects corrupt syntax and invalid proofs; exact expected-claim/source comparison detects substitution of a different valid claim or input. An adversary can create a different valid witness for the same theorem, and that is intentionally accepted. No cryptographic authorship, external source identity or tamper-evident archive is promised by the codec. Resource exhaustion during replay produces no VerifiedWitness, even if a preceding prefix checked successfully. These limits implement (`rule:nrz:cas-conditional-witnesses`) rather than trusting the searcher's result.

## Calculus transforms and acceptance examples · `sec:nrz:cas-design-calculus`

**Procedure (Scalar derivatives and Jacobians)** · `alg:nrz:cas-design-differentiation`

The CAS-foundation step (`step:nrz:cas-foundation`) differentiates real scalar expressions built from rational/Pi/E constants, declared real scalar variables, Neg/Add/Sub/Mul/Div and fixed integer powers. A derivative request names a free variable in the context; the checker proves constants have derivative zero, the matching variable has derivative one and other variables have derivative zero. Postorder processing memoizes by expression/context/variable and constructs rule applications whose premises are the already checked child derivatives. Product order follows the original operands. Quotients add the denominator's nonzero guard; negative and zero powers retain their strict-power conditions. These expressions are smooth on the open set specified by their executable definedness guards, so no sampling or unstated regularity of an arbitrary function is needed. Other operators stay typed derivative requests and make the containing request Unresolved with the exact pending subrequests.

Derivative outputs are simplified only through checked scalar/finite-jet identities and condition accounting. In particular D(0 times an undefined expression) is not simply admitted as zero. Pending derivatives do not turn into inert constants. If any required child derivative is unresolved, a whole-output derivative witness is withheld; proved subderivatives may be returned as explicitly scoped progress evidence. Derivation caches reuse expressions and proofs, while original occurrences and their walks remain distinct. The checker can share arithmetic primitives with the producer, but it reconstructs the rule premises and does not consult the producer's success cache.

A Jacobian request contains ordered scalar output roots and an ordered list of distinct free variable keys. Repeated variable keys are invalid instead of silently creating duplicate columns. Compute every partial with the same context, reuse repeated subderivatives, and assemble a row-major exact Matrix result only after all required cells have derivative witnesses. The result preserves the supplied row/column keys. A named operating point is a simultaneous exact substitution into the Jacobian and its guards, checked by the equality-instantiation rule; it is not numerical evaluation. Different coordinates that happen to have the same nominal value retain separate columns. No covariance or uncertainty intrinsic is needed in the CAS (`constr:nrz:cas-differential-models`).

**Construction (Finite coefficient jets and square-free layers)** · `constr:nrz:cas-design-polynomials`

An internal polynomial is a sorted sparse map from bounded exponent vectors to Q coefficients, with zero coefficients removed and variables in canonical declaration order. It is a temporary checked view of graph expressions, not a second authoritative expression tree. Its coefficients are the compressed finite jets at zero divided by the multi-index factorials, using the argument in (`constr:nrz:cas-derivative-equality`). Conversion executes for the scalar polynomial grammar with nonnegative integer powers and the strict-power guards retained; named constants Pi/E can act as formal indeterminates for equality checking, not as unknown differentiation variables. Conversion of an unknown function, general power or variable denominator to a polynomial is Unsupported for that view. Rational identity checking builds numerator/denominator polynomial pairs and retains every original division guard before cross multiplication.

Expansion generation has a deliberately small basis: distributivity at ordered scalar positions, integer square expansion through multiplication, exact literal folding, collection to a sparse coefficient expression, and cancellation of common monomial factors of numerator and denominator. It does not require a multivariate rational-function gcd algorithm. Every generated equality is checked by field steps or the finite-jet/rational checker. The coefficient comparator is a bounded decision method for this represented polynomial fragment; it supplies no decision procedure for transcendental functions. Equality checker independence means independent reconstruction and fresh limits, not a claim that two copies of the same arithmetic implementation provide independent assurance; the law tests supply separate mathematical oracles.

For square-free decomposition require a univariate nonzero polynomial over Q. Normalize f=aF with a its nonzero leading coefficient and F monic. Differentiate F formally, compute monic C=gcd(F,F') by exact Euclidean divisions with extended coefficients, and set W=F/C. For multiplicity i beginning at one, compute Y=gcd(W,C), emit nonconstant Z_i=W/Y with multiplicity i, then set W=Y and C=C/Y. Stop when W=1. In characteristic zero, each iteration removes one layer from each remaining repeated factor, so the number of nontrivial iterations is at most degree(F). Each division is checked exact where required, and each gcd includes A U+B V=G together with U=G U1 and V=G V1. Normalize these identities consistently when making G monic. Fuel, degree and coefficient limits also apply inside the extended Euclidean algorithm.

The resulting theorem is f=a times the product of Z_i^i, with each emitted Z_i monic, nonconstant and square-free, and the emitted factors pairwise coprime. Replay checks the product coefficient identity, each certificate gcd(Z_i,Z_i')=1, and pairwise coprimality certificates; these facts uniquely describe the multiplicity layers without claiming irreducible factors. Divisibility plus Bezout proves a claimed gcd because every common divisor divides the Bezout combination and G divides both inputs. The derivative multiplicity argument proves why those coprime layers are square-free (`constr:nrz:cas-derivative-factorization`). A nonzero constant returns its scalar and an empty factor list; zero returns Unsupported with ZeroPolynomialMultiplicity. x²+1 may be one square-free factor over Q, and no complex splitting is attempted. The derivative and gcd are premises of this product theorem, never equality transitions from f to f'.

**Table (Represented requests beyond the executable slice)** · `tab:nrz:cas-design-deferred-operations`

|Request|Required payload and first-slice execution|
|-------|------------------------------------------|
|Integral|Bound variable, integrand, domain/components, indefinite or oriented endpoints and branch data; stores an antiderivative/definite-integral goal and returns Unresolved. The future route is derivative checking and Hermite reduction; no guessed primitive or constant is emitted.|
|Finite sum|Integer binder, body and half-open endpoints, including an empty range, with quantified definedness; represents the discrete-antiderivative goal and returns Unresolved without enumeration or geometric division.|

These operators are typed enough to construct every formula in (`tab:nrz:cas-reference-coverage`). Hilbert entries can be a two-index comprehension followed by real symmetric extremum requests and a scalar ratio. The Kahan finite sum and Wilkinson parameter power preserve integer binders and parameters. The pendulum covariance expressions are generic ordered matrix products with the external client's separately scoped covariance declarations. Kepler's positive square root is a branch-bearing power/function request. None of these representations pretends that the CAS-foundation step (`step:nrz:cas-foundation`) proves the integral Gram theorem, telescoping, full nonlinear covariance, root completeness or spectral order. The calculus routes and the three argued exceptions remain those in the accepted concept; adding algorithms later requires explicit admission and tests, not a fallback numerical answer.

**Example (Expansion, conditional cancellation and a pending limit)** · `ex:nrz:cas-design-quotient`

Build ((x+h)^2-x^2)/h with distinct original occurrences of x and h, in a real context with no nonzero hypothesis. Complete its original walk. The default bounded search must find an expansion/collection/cancellation route to 2x+h and replay an EqualOnDomain witness with residual h nonzero. A trace must contain an expression larger than its predecessor, so the test exercises exploration through expansion rather than merely comparing supplied endpoints. The finite-jet identity (2x+h)h=2xh+h² independently checks cancellation. Supplying h nonzero in Gamma makes the same equality discharged relative to that hypothesis. Substituting h=0 into the original quotient refutes its definedness and must not produce that equality. A Limit request as h tends to zero remains Unresolved; the concept's continuity argument is specified mathematics for a later limit rule, while direct differentiation of x² already produces 2x in this slice (`ex:nrz:cas-expansion-route`).

**Example (Derivative multiplicities)** · `ex:nrz:cas-design-square-free`

Build f=(x-1)^3(x+2)^2. Independent coefficient expansion in ascending degree gives [-4,8,-1,-5,1,1], and differentiation gives [8,-2,-15,4,5]. The monic gcd with f' is (x-1)^2(x+2), with ascending coefficients [2,-3,0,1]; f divided by that gcd is (x-1)(x+2). The accepted decomposition has scalar one, factor x+2 of multiplicity two and factor x-1 of multiplicity three, in increasing multiplicity order, with unit layers omitted. Replay must verify both the product identity and the derivative gcd certificates. Incorrect multiplicity, a missing layer, zero input, a multivariate input or an attempted positive-characteristic context exercises separate refusal paths. This acceptance does not require irreducible factorization or root evaluation.

**Example (Shared pendulum columns)** · `ex:nrz:cas-design-jacobian`

Build the complete three-output model g_i=4 pi²(l_i+r)/(t_i²(1+q)²), with variables ordered l1,l2,l3,t1,t2,t3,r,q. Request its 3 by 8 Jacobian, preserving the shared identities of r and q. Before specialization, the nonzero guards on every used t_i and 1+q remain visible. After simultaneous substitution l_i=621/625, t_i=2 and r=q=0, rational facts discharge those guards. Each row's own length cell is pi², its own timing cell is -(621/625)pi², its shared r cell is pi² and its shared q cell is -(1242/625)pi²; every other reading cell is zero. Exactly the final two columns are shared inputs. Independent hand differentiation of the quotient supplies the expected expressions. Byte-identical repeated builds/requests and replay after canonical export are acceptance conditions (`ex:nrz:cas-pendulum-linearization`). No covariance propagation or physical source-independence claim is inferred from those derivatives.

## Public service and client boundary · `sec:nrz:cas-design-api`

**Definition (Checked API surface)** · `def:nrz:cas-design-api-types`

The facade exposes Rational, SymbolKey, SourceKey, Sort, Operator, Predicate, ContextDraft, DraftBatch, typed opaque handles, Cas, Limits, LimitsOverride, BudgetUsage, Request, Operation, GoalPolicy, CostPolicy, Outcome, Witness, VerifiedWitness and Fault. Drafts are untrusted values even when built through convenience methods. `Rational::parse` and arithmetic return `Result` with typed faults. `Cas::new(limits)` validates store ceilings; `admit(batch, limits)` returns committed handles or a construction fault; `walk_original(root, limits)` returns a completed walk and sealed receipt; `substitute(input, substitutions, limits)` constructs exact derived syntax and provenance transactionally. Read-only views expose operator/sort/children and ordered occurrence records, never mutable storage.

`Request` holds an Operation, prepared input handles/receipts, ContextHandle, optional target claim, GoalPolicy, pinned registry and cost-policy snapshots, conditional-result policy and LimitsOverride. Operation variants are Simplify, Equal, Expand, Differentiate, Jacobian, SquareFree, Integrate, Sum, Series, Limit, Solve and Spectral with the typed payloads specified above. `run(request)` returns Outcome and BudgetUsage. GoalPolicy is a closed task-appropriate rank description with an optional explicit target; arbitrary comparison code is not accepted. Wrong-store handles, missing receipts, wrong target sorts or incompatible operation/policy pairs are rejected before graph work. `register_derived(witness, expected_claim, policy, limits)` is the only public way to extend the rule registry.

`export_witness(verified, limits)` returns canonical bytes or a typed size fault. `replay(bytes, expected_claim, limits)` returns a freshly checked VerifiedWitness or ReplayFault, without invoking search; `inspect` exposes the checked claim when no acceptance target is supplied. A caller can request `certify_frozen_cost` separately. Debug and display are bounded summaries using logical IDs; complete text/tree expansion is an explicit metered export, never an implicit recursive Debug traversal. Runtime errors contain structured reasons and optional source paths, with separately budgeted diagnostics; they do not interpolate arbitrarily large expressions into an error string.

|-----|-----------------------------|

|Conditional|A replayed final relation with a nonempty canonical residual set; it is not a discharged answer under the original Gamma alone.|

Fault variants distinguish InvalidLiteral, ZeroDenominator, InvalidSpan, ForeignHandle, InvalidScope, SortMismatch, InvalidContext, InvalidPolicy, InvalidReference, UnsupportedVersion and Exhausted with BudgetKind and operation/path. ReplayFault additionally distinguishes EndpointMismatch, MissingPremise, ConditionMismatch, RuleMismatch and NonCanonicalEncoding. A represented expression with a provably false domain guard, such as division by literal zero, can be retained as original syntax; a request reports that refuted-domain blocker without deriving an equality by vacuity. This differs from trying to construct the impossible Rational with denominator zero, which is Invalid. Exponent/bit/degree limits are Exhausted, not a theorem that the corresponding expression is undefined. External cancellation is Exhausted with Cancelled and a deterministic completed prefix, but byte-determinism promises exclude externally timed cancellation.

Every public input path uses checked access/conversion and an explicit finite work ledger. No unwrap, expect, panic, unreachable assertion, unsafe code, unbounded recursion or placeholder panic implements a refusal. A fallible allocation refusal is reported as Allocation where the underlying API exposes it; environmental allocator aborts have the limit explained in (`rule:nrz:cas-design-transactions`). Atomic admission applies to every failed constructor and proof import. Search can retain fully checked batches admitted before a later exhaustion, and its report identifies that committed prefix; it never publishes the failed candidate or an unverified best result.

**Procedure (Later bindings integration)** · `alg:nrz:cas-design-client-boundary`

In a later migration, bindings maps the old input's ordered operations, byte locations and declaration identities into DraftBatch and retains its immutable physical declaration snapshot. It calls admit, then walk_original, then checks every returned occurrence using its existing physical rules, including operands that algebra could cancel. It keeps a client-owned physical validation receipt keyed by original occurrence root, context/declaration snapshot and CAS traversal receipt. CAS receives only the mathematical context and completed traversal receipt. Physical dimensions, quantity kinds, affine origins, measures, source covariance meaning and companion contributors stay in bindings-owned structures keyed by opaque CAS occurrence/expression handles (`alg:nrz:cas-later-migration`).

After the client has accepted that original input, it may call run with a mathematical request and inspect the exact derived expression and conditions. It first replays the returned witness against the expected mathematical claim and checks whether its own declarations discharge or permit those conditions. To physically check a derived expression it requests a complete generated occurrence materialization, walks that new root and applies its physical checker again, retaining the derivation and original declaration snapshots. A normalized expression is never substituted for the original check record. CAS may supply source/proof dependency links for diagnostics, but cannot mint the client's physical receipt or erase original dependencies when a derivative becomes zero.

The call order is therefore admit original input, walk original, validate physically in bindings, request a derivation, replay/accept its mathematical conditions, materialize derived occurrences, and validate that derived input physically. The first implementation supplied these CAS calls and generic mock-visitor tests without changing consumers. Bindings and docgen now build on nrz-cas, parse against semantic headers and preserve original diagnostics; the descriptor experiment is retired. The unused nrz-algebra package has been removed; nrz-cas is the engine's sole algebra implementation. A generic CAS receipt proves graph coverage only (`rule:vision:check-before-normalization`), (`rule:vision:layer-enforcement`).

**Rule (Exact decision cut boundary)** · `rule:nrz:cas-decision-cut-boundary`

The pure rational cut query `Cas::check_case_cut` checks a supplied closed box against the actual native association and case domain using exact affine extrema. It has no graph publication, hypothesis or witness result; the enclosure origin and qualified introduction required by (`rule:nrz:decision-exact-certificate`) and (`thm:nrz:decision-membership-introduction`) remain open. Its new checks consume only their caller's Work and staged payload; ordinary proof routes retain their existing costs, primitive manifest and wire format.

**Rule (Exact finite decision partition boundary)** · `rule:nrz:cas-decision-partition-boundary`

`Cas::check_case_partition` additionally checks a nonempty finite native partition with globally total rational affine predicates whose nonconstant comparisons each use one Real axis after cancellation. The complete Cartesian cell inventory retains singleton boundaries and checks cover, disjointness and containment in the declared domain. Finite integer families additionally match every integral Real option literal to its unit cell and the domain to its declared range. The returned sealed contract supports identity-checked reuse with a new cut; it creates no proof record, hypothesis or portable cover. The sign, finite integer and seven-chart phase partitions are supported, while parametric families, non-rational and oblique boundaries and certified introduction remain separate obligations of the introduction rule (`thm:nrz:decision-membership-introduction`) and finite-family contract (`rule:nrz:decision-option-ranges`).

These tests are derived here from field, derivative and graph invariants and the accepted examples, without copying another system's test data or code. Small deterministic enumeration replaces a new property-testing dependency. Passing replay alone is necessary but insufficient to test a buggy shared arithmetic primitive. Error and exhaustion tests check both classification and absence of forbidden state publication.

**Step (CAS foundation)** · `step:nrz:cas-foundation`

The foundation supplies exact graph construction, conditional witnesses, bounded identity search, scalar derivatives and square-free layers. The commit procedure below defines its independently tested boundaries.

**Procedure (Four independently reviewable commits)** · `alg:nrz:cas-foundation-commits`

The CAS-foundation step (`step:nrz:cas-foundation`) is bounded to the following four commits, targeted to one 7,200-second implementation round plus correction rounds. Each commit documents the behavior it actually exposes and has passing tests for that behavior; later algorithms return an honest unresolved outcome until their commit lands. Scratch commits are folded into these named units before shipping. The outline is an implementation budget, not permission to relax a checker when the time threshold is reached.

|Commit|Buildable contents and acceptance|
|------|---------------------------------|
|feat(cas): add exact graph construction|Package/policy/list/manifest/census registration; exact rationals; all typed representable operators; graph/contexts/occurrences, budgets and transactional drafts; capture-safe substitution and original walks. Arithmetic, scope, rollback, traversal and unresolved-request tests pass.|
|feat(cas): check conditional identity witnesses|Closed primitive registry, conditions, finite coefficient jets, canonical codec, independent replay and derived-lemma storage. Direct equality/derivative-premise fixtures, exact guards, tampering, imported expected-claim checks and byte determinism pass; no heuristic search claim is made.|
|feat(cas): search identities and derive Jacobians|Two queues, quotas, dominance/expansion policies, versioned costs, frozen-snapshot certification, scalar derivative transforms and Jacobian assembly. Difference-quotient expansion and the pendulum shared-column example pass with replay and resource-boundary tests.|
|feat(cas): derive square-free polynomial layers|Formal derivatives, bounded univariate Euclidean/extended arithmetic, multiplicity-layer generation and its certificates. The degree-five decomposition, constants/zero/field refusals and the full prior suite pass.|

The conditional-witness commit supplies the rule/checker interface and proof records for the later square-free relation but does not register a usable square-free checker until the square-free-layer commit supplies its verified certificate implementation. It never installs a placeholder accepting checker. Likewise derivative schemas may check hand-supplied derivations before the identity-search commit adds automatic derivative production. This lets every commit be a coherent tested capability instead of a temporarily unsound stage. Corrections amend the responsible commit and rerun downstream gates as directed.

The remaining scope excludes arbitrary primitive plugins, full function/complex differentiation, Hermite integration, executed sums/limits/series, numerical roots, irreducible factorization, general matrix reduction and spectral algorithms. It includes representation and honest outcomes for these requests, the three concrete acceptance examples, complete error/limit documentation and portable replay. No concept or consumer change is needed to make this slice coherent. If implementation cannot satisfy a listed invariant within its bounds, it reports that defect and the exact refused scope for review rather than silently weakening the accepted design.
