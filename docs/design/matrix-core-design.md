# The certified matrix core and its descriptor heap · `spec:nrz:matrix-core-design`

Owner NRZ, area nrz. This is the implementation contract for the reordered bite 4 (`step:nrz:bite-certified-matrix-core`), against repository `c12d8473182e04f0fe2f80d17403670bb38d8da2`. It implements the storage and numerical obligations of (`spec:nrz:descriptor-heap-computation`) and (`spec:nrz:matrix-shapes`); it does not report them as already implemented. The unit of computation is a value region and its independently shaped companion regions. A scalar is a 1×1 value region. No heap coordinate, bound, covariance coefficient, residual or count center enters CAS arithmetic. The CAS owns mathematical graphs and symbolic evidence; numerical kernels own evaluation and its error.

## Domain and obligation map · `sec:nrz:matrix-core-scope`

**Decision (Supported production domain)** · `dec:nrz:matrix-core-domain`

Implement finite real f32 and f64 dense regions, checked homogeneous and heterogeneous block maps, sum/subtraction, fixed linear and affine coordinate maps, matrix multiplication, selection/reshape/dual transpose, nonempty square solves with multiple right-hand sides, explicit inverses, and elementwise square, reciprocal and square root on their stated domains. Each operation propagates deterministic componentwise bounds, joint covariance when requested and supported, and numerical-error regions. Require complete companion handling before publication; unsupported carried modes refuse the transaction. Exact affine moment propagation and nonlinear linearized covariance are usable capabilities with different assurance. A deterministic normwise solve certificate is also restored into conservative componentwise bounds; a tighter componentwise inverse comparison is an explicit later optimization, not a prerequisite for entrywise coverage.

The initial heap admits count descriptors only as schemas: binding count values to floating arenas refuses. Bite 5 supplies exact discrete arenas and the quantity-facing adapter. General expression evaluation, transcendental elementwise functions, arbitrary rational powers, rank-deficient or rectangular solves, spectra, matrix functions, distribution propagation, expanded confidence regions, uncertain coordinate-reference scales and arbitrary precision are outside this bite. Their missing proof or representation obligations are stated below. Numerical coverage does not imply physical model adequacy. Physics plans, graph scheduling and batch execution remain bite 6; bite 4 exposes operation contracts and optional external record keys suitable for those clients.

## Heap ownership and transactions · `sec:nrz:matrix-core-heap`

**Decision (One numerical owner)** · `dec:nrz:matrix-core-owner`

`nrz-matrix::Heap` owns separate typed arena collections for f32 and f64, descriptor slots, immutable schema pools, source relations, bounded provenance and operation records. A region refers to one contiguous allocation of one scalar format; views supply checked maps into it. The first allocator uses individually owned, contiguous `faer::Mat<P>` slabs, treated as column-major element arenas through safe public accessors. A slab may contain several nonoverlapping regions. Growth adds a slab; it never changes a live allocation's format or address interpretation. No per-element unit or assurance wrapper enters faer. Where a safe slice/view constructor does not accept the requested strides, pack into a fresh faer matrix and copy through checked indices. Storage and kernel feasibility are verified against the repository's pinned faer, not a guessed future API (`ex:exemplars:faer`).

The graph-first representation question is which relations must survive movement: value-to-region, value-to-schema, companion-to-target-version, source-to-dependent-entry and operation-to-evidence. Store those as private IDs and explicit edges; buffer addresses cannot answer any of them. Descriptor indirection takes from (`ex:exemplars:direct3d12-descriptor-heaps`), and metadata/buffer separation from (`ex:exemplars:apache-arrow-columnar-format`). Neither contributes graphics lifetimes, GPU residency, alignment requirements, null semantics or an engine dependency. A growable object graph of scalar quantities is rejected because it duplicates schemas and obscures matrix contractions.

**Rule (Identity and resolution)** · `rule:nrz:matrix-core-resolution`

`Handle<Category,P>` is a copyable opaque locator containing heap identity, descriptor slot and occupation generation, with sealed category and precision markers. Arena slot/generation belongs to the resolved descriptor, not the external handle, so compaction can update physical indirection without invalidating the logical handle. Categories Value, Companion, Factor and Workspace are separate sealed types. The handle grants no permanent borrow and proves no current evidence. Resolving checks the heap, occupied slot, category, precision, arena occupation, region bounds and map revision; a wrong heap is refused before indexing. A process-local checked monotonic identity allocator supplies scopes, ValueIds, SourceIds and execution IDs; it promises no persistence or global uniqueness across processes. Counters never wrap: exhausted slots/arenas retire, and exhausted owner identity allocation fails explicitly. Slot generation changes on reuse; ValueVersion changes on content replacement within a surviving occupation. Equal schemas, equal bytes and copied handles do not create independent sources (`def:nrz:descriptor-reference`).

Schema interning uses exact `Descriptor::Eq`, ordered axis identities, partitions and structure scope; comparison confirms hash collisions. Scoped schema IDs from different pools remain distinct. Convertible measures are not equal measures, and interning never merges origins or normalization maps. Snapshot IDs retain the units context, original occurrences, semantic rule revisions and checked evidence. Changing a schema creates another immutable schema and advances affected descriptor revisions; it cannot retroactively reinterpret old evidence. Every public evidence access resolves its captured dependency versions, including when only a companion or source model changed.

**Rule (Checked layouts and safe views)** · `rule:nrz:matrix-core-layouts`

An affine layout computes `offset + i*row_stride + j*col_stride` in elements. Check extents, products, sums, signed conversions and both extreme addresses with checked integer arithmetic before view creation. For a nonempty layout, the minimum adds each negative stride's extreme contribution and the maximum each positive one; both must lie inside the owning allocated region, not just inside slab capacity. Empty maps have no addressable entry; sums and products with zero contraction have typed zero results, while solve/factor calls require positive order and at least one right-hand side. Explicit gather and structured maps validate every logical index under a work limit. A view of a view composes maps and retains the base value identity. Logical column vectorization remains `i + m*j` (`conv:nrz:shape-entry-order`).

Read-only repeated indices, broadcasts and overlapping inputs are admitted. Output destinations must be injective and mutually disjoint. Dense disjoint contiguous regions use a range proof; other maps enumerate/sort destination indices within the configured limit and reject duplicates, or use fresh contiguous scratch plus a validated scatter. Exhausting that proof limit refuses; bounding-box disjointness is a sufficient fast check, never evidence for overlapping boxes. This bite offers no in-place numerical kernel. All writes use scratch and publication, avoiding undocumented backend alias assumptions. Allocation, layout and indexing failures are ordinary typed errors; safe Rust borrowing and checked access remain mandatory even after metadata validation (`rule:nrz:descriptor-layout-validation`).

`Binding::validate(&mut Heap, ...)` returns an evidence-owning `Bound<'h,P>` holding the exclusive heap borrow, actual dependency snapshots and checked output reservations. It lends immutable `PhysicalView` or `NormalizedView` with lifetimes shorter than that borrow; only normalized views enter numerical adapters. There is no mutable raw-center view of a checked value. Arena growth, mutation, compaction and another execution cannot occur through that heap while a bound view is live. Backend candidate matrices are privately owned scratch, so simultaneous borrowing does not need unsafe splitting or persistent pointers. After explicit normalization preparation, `Bound::normalized_inputs(&self)` lends an operation-ordered `NormalizedInputs` bundle, `Bound::evaluate(&self, NormalizedInputs)` creates an owned candidate, and `Bound::publish(self, Candidate)` consumes the binding after its views are released. Evaluation checks the bundle execution identity and recipe; a valid view from another binding is insufficient. The shared evaluation borrow only reads inputs and allocates independent scratch; visible mutation is confined to consuming publication. An explicit raw export returns an owned copy with no evidence; reimport is a fresh checked import with its source assumptions stated.

**Procedure (Atomic publication)** · `alg:nrz:matrix-core-publish`

Execution first validates original semantics, shapes, all input dependencies and requested companion modes; reserves work and scratch capacity; then computes centers, propagated companions and verification evidence in private storage. A `Candidate<P>` carries a unique execution token, recipe/output contracts and prepared target maps. It is not usable as a Value handle. Before commit, verify finite centers and bound payloads, descriptors and extents, domain and assurance requirements, all companion targets and versions, both covariance axes, restoration maps and budget status. Prepare new descriptor/source edges and operation records and complete all fallible allocations before changing visible state. Under the exclusive borrow, a no-fail commit links all prepared records and publishes the complete output bundle together. Retarget internal companions to the reserved new ValueIds/versions in that same commit; cross-value companions may reference unchanged validated versions. No caller callback or backend operation runs in the commit phase.

A foreign or reused candidate token, incomplete companion set, failed conversion, capacity exhaustion, failed restoration or unmet requested budget publishes no output. Reservations and scratch are discarded; existing values and versions stay unchanged. Failure records retain independently valid partial evidence, including a valid but over-budget bound, without a success handle. Rust allocation failure outside fallible APIs may terminate the process; atomicity promises no partially visible checked result, not process survival under an allocator abort. Explicit recoverable capacity/work limits are checked before backend allocation. Publication here is single-owner transactional visibility, not a concurrent lock-free guarantee (`rule:nrz:descriptor-publication-validation`).

**Rule (Replacement, aliases and invalidation)** · `rule:nrz:matrix-core-invalidation`

Replacing a value is a checked transaction that advances its ValueVersion and atomically installs fresh companions or an explicitly reduced coverage state. All overlapping aliases resolve through the same base version; conservatively invalidate the entire base value when any selected entry changes. Dependent companions, WholeFamily structure, bindings, inverse witnesses and caches are marked stale through reverse dependency edges and also compare versions on access. Old operation records remain historical and cannot authorize current access. Read-only detached snapshots own their old storage and identities; raw copies preserve source dependence explicitly. A source/assurance/declaration/map change invalidates its evidence dependents even with identical center bits. Changing an unrelated allocation does not invalidate an operator factor.

Freeing a base allocation retires all views referencing it; a cached descriptor never revives after region reuse. Compaction is allowed only between evaluations: prepare replacement slabs and validate every affected map, then update indirection atomically and advance layout epochs. Values and mathematical evidence may retain versions if bytes, schemas and source models are identical; physical-view caches must refresh. Precision conversion instead creates a new representation with a new ValueId, its own version and companions; it never changes the scalar type of an arena. This implements (`rule:nrz:descriptor-lifetime-and-mutation`) without conflating address relocation with changed mathematical inputs.

## Shapes and physical coordinates · `sec:nrz:matrix-core-shapes`

**Rule (Shapes are checked matrix contracts)** · `rule:nrz:matrix-core-shape-checks`

Matrix owns `ShapeDraft`, `CheckedShape`, ordered Axis/AxisEntry, partitions, logical entry maps and structure evidence; units supplies the scalar descriptor algebra and layout-free pairing witnesses used to validate them. Check `A: X → Y` entry quotients `D(Y_i) − D(X_j)`, semantic multiplication into each row kind, compatible addition measures, complete nonoverlapping block coverage, typed structural zeros and every original entry recipe before cancellation. Matching lengths or exponent vectors does not identify axes. Repeated block schemas amortize descriptor work but do not skip newly supplied original expressions or numerical scans. Shape limits bound extents, entries, block refinements and symbolic work (`rule:nrz:shape-entry-contract`).

Addition uses common compatible partitions and explicit axis alignments. Product composition checks the ordered contracted axes; selection and reshape record logical permutations. Transpose maps `A: X → Y` to `Aᵀ: Y* → X*`, preserving entry dimensions through reciprocal dual axes, rather than swapping physical axes as though taking an inverse. Formal dual pairing is a matrix relation checked by units, not automatic reciprocal registration for every scalar kind. Inverse and solve reverse the appropriate axes; factor resources retain intermediate axes and permutations. Descriptor-only QR/Cholesky quotient/root admission does not expose those numerical factorizations in this bite (`rule:nrz:shape-transpose-and-duality`), (`rule:nrz:shape-factorizations`).

For structured storage admit typed zeros, diagonal/triangular patterns, selection/permutation and exact duplication maps. An optional bounded dense affine expansion `vec(A) = T z + d` uses the same certified linear-map kernel, with checked coefficient descriptors and retained free-coordinate identities. Only WholeFamily structure restricts uncertain entries; a symmetric center with unconstrained perturbations keeps the full entry covariance. Compute full logical Frobenius norms or apply the proven metric `TᵀT`; symmetric duplication weights an off-diagonal square twice. Reject an unsupported metric instead of using the packed Euclidean norm. Numeric symmetry proves neither physical self-adjointness nor positive definiteness (`rule:nrz:structured-companion-coordinates`).

**Rule (Normalization is an explicit kernel)** · `rule:nrz:matrix-core-normalization`

Physical storage uses coherent SI coordinates; presentation imports first execute checked measure conversion. A heterogeneous operator is a checked block assembly, not one physical matrix with a fictitious common unit. Normalize using positive typed exact source-free difference references: `Â = S_Y⁻¹ A S_X`, `B̂ = S_Y⁻¹ B S_W`, `Ẋ = S_X⁻¹ X S_W`. Points first subtract their declared origins and modify the right-hand side accordingly. Restore each solution entry by `S_X,i/S_W,j`, restoring origins only to point centers. Retain all reference and origin identities, exact maps, lowered coefficients and conversion-error regions. An uncertain physical scale is a value operand requiring its own propagation, not a reference-scale definition (`def:nrz:shape-normalization`).

Normwise certificates name a homogeneous difference norm or the normalized coordinates/metric. A normalized scalar radius R yields entry bounds `abs(S_X,i/S_W,j) R` plus restoration evaluation error; it cannot be displayed as one physical radius shared by volts and amperes. Covariance restores with both paired scale factors; relative forms require their named nonzero difference references. Dimensionless numerical equilibration follows physical normalization and has separate provenance. It does not silently alter the physical budget or supply a physical eigenproblem (`rule:nrz:shape-norms-and-conditioning`).

## Companion regions and assurance · `sec:nrz:matrix-core-companions`

**Definition (Region companions)** · `def:nrz:matrix-core-companion-records`

A companion is a heap descriptor over its own region, not a field on every scalar and not a detached report. For `m × n` values, componentwise absolute bounds have `m × n` entries, full covariance has `mn × mn` entries in logical column order, and a norm radius has one entry plus its coordinate/norm contract. Cross-covariance between N and P selected logical entries has `N × P` entries and two ordered target-version maps. Every region records its own quantity descriptors, source class, coverage, numerical assurance and provenance; absolute bounds and covariance are never interchangeable by shape or equal dimensions (`def:nrz:companion-shape`).

Bounds have nonnegative finite entries with difference dimensions and radius kinds; affine offsets are zero. Covariance pairs carry the sum of the two target dimensions, product difference measures and paired uncertainty kinds; entries may be negative. A sensitivity entry has output-over-input dimension, so contraction with covariance gives the required paired output product. Units derives these descriptors using `uncertainty` and dedicated pairing rules; matrix checks the indices, target identities and contractions. Numerical error in evaluating covariance targets the covariance region itself, with that parameter's product dimension and an evaluation-radius kind. It does not become uncertainty of either original value. Relative bounds retain reference IDs and cannot acquire an origin-dependent implicit denominator.

|AffineMoments|Exact mean/covariance law conditional on the declared joint finite-second-moment model and fixed affine map; floating evaluation still has a separate certified error region.|
|LinearizedMoments|Covariance of the local linear model at a named operating point, with derivative/domain evidence; no claim that the actual nonlinear mean or covariance equals it.|

Assurance is not a single ordered enum permitting promotion from statistics to certification. Matrix privately constructs typed deterministic views only when a retained certificate covers the requested scope. Units checking or a string saying certified supplies no such witness. A result may expose both a nominal deterministic certificate and a physical covariance; it may lack a DeclaredInputs bound. Nonlinear outputs store `f(operating_point)` as a nominal center, not an asserted expectation. When a caller requests a physical nonlinear moment approximation, it must also supply the relevant existence/model assumptions; finite second moments of inputs alone need not imply finite variance of their product.

**Rule (Joint sources and covariance admission)** · `rule:nrz:matrix-core-joint-sources`

`JointModel` defines an ordered source vector with immutable SourceIds/revisions, difference schemas, declared finite moments and a complete joint covariance relation. Statistical imports declare their mathematical mean parameters and center-parameter evaluation enclosures; represent source fluctuations about those means as zero-mean. A center tagged only as an operating point cannot be reported as an expectation. AffineMoments propagates retained means by the same affine map and their parameter errors separately from physical covariance; nonlinear outputs retain only their named nominal operating centers and linearized source relation. A block table distinguishes Known, DeclaredZero and Unknown; zero blocks require a stated zero-covariance assumption, not necessarily independence. Every requested contraction requires all participating blocks, even across two input values or separate executions. No absent block is filled with zero. Repeated value/source selections gather the same random coordinate; copying a center preserves its source map. Source models with the same ID and conflicting definitions refuse globally. Distinct IDs alone establish no independence (`rule:nrz:batch-source-covariance`).

Admit a normalized covariance through either a source factor `U_s = L diag(d) Lᵀ`, with finite represented L and nonnegative represented d, or a checked dense symmetric matrix. The factor defines the mathematical covariance by construction; arbitrary rectangular L admits singular and rank-one cases without positive-definiteness assumptions. A dense import requires exact represented symmetry and a sufficient PSD certificate: nonnegative diagonal dominance, verified with outward absolute row sums, or interval LDL elimination with strictly positive pivot lower bounds. The latter encloses exact real Schur complements in a fixed symmetric ordering, so positive pivots prove positive definiteness. These tests may refuse a valid PSD matrix; a supplied factor is the supported alternative for unresolved singular cases. A failed sufficient test is CannotValidateCovariance, not proof of indefiniteness. Imported parameter enclosures require the sufficient test to cover the entire admitted parameter family or an existing factor/propagation witness. PSD evidence never proves that the source model describes nature.

For propagation retain the source model and sensitivity maps, with dense cross blocks materialized on request within explicit storage/work limits. For affine maps, this relation is an exact model; for nonlinear maps, compose sensitivities at recorded operating points and mark all dependent blocks LinearizedMoments. To form the covariance between a new output y and an already retained output z, use their joint lineage `J_y U_s J_zᵀ`, or the equivalent complete block relation. A declared external z without that relationship refuses. Backend rounding can make a displayed covariance slightly asymmetric or indefinite; symmetrize its center with certified error if desired, but preserve the mathematical PSD lineage and parameter error. Never clip eigenvalues or relabel an arbitrary rounded matrix as exactly PSD. Source-factor storage is an exact representation choice, not a promise of smaller rank or faster evaluation.

**Rule (Coverage and provenance graph)** · `rule:nrz:matrix-core-coverage`

Bound regions distinguish measurement, representation/import, conversion, kernel evaluation, verification and interaction contributions. A deterministic total references its derivation and covered parents. The total and its constituent contributions are alternative views of the same coverage, not additive independent inputs; consumers use the chosen total once. Statistical components never enter that sum. Linear source contributions may be retained separately; mixed products and nonlinear remainders record the union of contributing sources rather than a fictitious independent cause. Triangle inequalities remain valid with unknown correlation but cannot justify deduplication or cancellation of repeated bounds.

The heap owns a bounded immutable provenance DAG; descriptors retain scoped IDs into it. Records retain ordered parents, recipe revision, arithmetic environment, exact descriptor maps, actual value versions and source assumptions. Dependency depth, records, edges, bytes, contraction work and numerical scratch have explicit limits; exhaustion refuses before publication. An evaluation-error companion's outward upper entries are proved bounds on its target, so they do not require an infinite tower of companions on bounds: rounding in constructing those upper entries is already included by outward evaluation. A numerical parameter stored as a center with a nonzero evaluation error still has its own companion. Historical reports borrow this graph, and dropping a source cannot leave an apparently valid dependent descriptor.

## Matrix propagation contracts · `sec:nrz:matrix-core-propagation`

**Rule (One joint differential and three numerical objects)** · `rule:nrz:matrix-core-jacobian-contract`

Write z for the concatenated logical entry vectors of all operands, in recorded order, c for their operating point, r for a deterministic componentwise bound, and U for the complete joint covariance. Each kernel returns a finite center `ŷ`, an enclosure of `f(c)` and a new numerical-error region e bounding `abs(ŷ − f(c))`. For a smooth supported map, a checked symbolic or operation-specific derivative gives J at c. Numerically evaluate it as `Ĵ` with certified entry error `E_J`, giving `abs(J) ≤ abs(Ĵ) + E_J`. If a second-derivative enclosure H holds on the entire convex input box, Taylor's integral remainder gives `R_i ≤ (1/2) sum(j,k) H_i,j,k r_j r_k`. Therefore `r_y = (abs(Ĵ) + E_J) r + R + e`, evaluated outward, is a certified deterministic bound. H bounds absolute second derivatives, not a sampled Hessian. Alternatively use a certified direct enclosure of the whole operation. This argument is the mean-value/Taylor theorem plus triangle inequalities, and includes interaction terms discarded by first-order analysis.

Covariance uses `U_y = J U Jᵀ` and cross-output covariance uses `U_yw = J_y U J_wᵀ`, including all input cross blocks. For a fixed affine map this is an exact identity: subtract expectations, multiply the resulting differences and take expectations; finite second moments suffice. For nonlinear maps it is the covariance of the stated linearization only, with assurance LinearizedMoments. A deterministic remainder bound does not automatically turn that covariance into the true nonlinear covariance or a confidence region. A numerical enclosure of J and U is contracted by validated matrix arithmetic to bound evaluation error in the displayed covariance. Rounding or coefficient conversion is never modeled as an independent random source (`rule:nrz:shape-sensitivity-propagation`). Affine operations on already linearized lineage retain LinearizedMoments; the AffineMoments entries below require exact joint moments of their operands and cannot upgrade inherited estimates.

The initial validated contraction path materializes or tiles the required logical entries and accumulates interval dot products in increasing contraction-index order. Faer computes candidate centers; the independent path encloses the exact contraction and its discrepancy from the candidate. This covers numerical errors in J, U, source factors and both contraction stages, without an assumed backend reduction tree. A product of interval coefficient matrices may overestimate dependency; it still encloses the specified expression. Structural maps and source lineage retain actual dependence for the statistical model. Resource limits may refuse materialization or excessive interval work; partial diagonal output is never reported as full covariance.

For the product bound, expand `(A+δA)(B+δB) − AB = A δB + δA B + δA δB`, apply entrywise triangle inequalities and add the candidate discrepancy. For reciprocal, the exact identity `1/(c+δ) = 1/c − δ/c² + δ²/(c²(c+δ))` gives the linear and quadratic terms using `abs(c+δ) ≥ d`; equivalently the unsplit bound is `r/(abs(c) d)`. The square-root bound follows by rationalizing the difference, with the smallest admissible root in the denominator. All coefficient bounds and denominator tests use outward arithmetic; a computed upper radius must not use a rounded-up lower denominator. These proofs are valid with correlated deterministic perturbations because they never assume independence.

A solve sensitivity is evaluated for the exact nominal solution `X_0 = A_c⁻¹ B_c`, not silently for a rounded candidate. Obtain an enclosure of X_0 from the represented-input solve certificate. For each input direction form `δB − δA X_0` as an enclosed right-hand side and solve with the same verified operator to enclose the true derivative column. Directional/source-factor propagation can avoid forming the full Kronecker Jacobian, but must represent the same entry map and include every source direction. Materialized Jacobians use column vectorization and `J_A = −(X_0ᵀ ⊗ A_c⁻¹)`, `J_B = I_r ⊗ A_c⁻¹`. The Kronecker expressions specify contractions, not a required sparse-matrix library or a CAS matrix-number representation.

**Rule (Mathematical refusal boundaries)** · `rule:nrz:matrix-core-mathematical-refusals`

Unknown covariance blocks prevent the requested joint covariance law; lack of independence is not itself an obstacle when cross blocks are supplied. Unsupported source coverage, an unresolved PSD import, a derivative/domain failure, zero-containing divisor, unresolved solve perturbation margin, insufficient finite-moment assumptions or unbounded numerical enclosure returns a specific failure. Statistical sqrt at zero refuses because its finite derivative does not exist there, even when a deterministic square-root enclosure exists. An arbitrarily user-supplied Jacobian is not admitted merely because its descriptors match. A request to drop a companion must explicitly select a narrower scope and retain the excluded coverage in the new result; default operations refuse rather than silently lose it.

General nonlinear moments need higher moments or a distributional method, so this bite supplies local linearized covariance without claiming exact nonlinear statistics. General elementwise transcendental kernels need validated approximation/domain error in addition to floating rounding; libm finiteness is insufficient. Spectra, matrix powers/functions and rectangular/rank-deficient solves need operation-specific branch, metric, separation and perturbation contracts, so a square solve proof cannot admit them. General interval or affine uncertainty engines, stochastic diagnostics and parallel scheduling remain separate capabilities. These exclusions concern missing guarantees, not an assumption that matrix uncertainty can only propagate through unary affine maps.

**Decision (Graph first, numbers outside)** · `dec:nrz:matrix-core-cas-boundary`

No new wire schema or docgen numerical evaluation is introduced (`spec:nrz:problem-data-schema`).

**Procedure (Symbolic sensitivities become kernels)** · `alg:nrz:matrix-core-sensitivity-lowering`

Units freezes a context after checking all original operands, including unused declarations and operations hidden under zero or cancellation. For each native scalar recipe it uses the current public `Task::Jacobian` or `Task::Differentiate` request with explicit coordinate order/domain, inspects the replayed witness and retains conditional obligations. Formal derivative zeros receive those expected typed descriptors from the derivative relation, not an untyped-zero shortcut for original physical expressions. The output is a private-construction `CheckedSensitivity` owning the graph witnesses, ordered symbol keys, permitted kernel recipe and unresolved numerical domain obligations.

Square and reciprocal use the admitted integer-power/quotient graph. For native square root, the current scalar derivative grammar does not differentiate its named call: derive the partials of the polynomial relation `t² − x = 0` in the graph, then apply the operation-specific positive-root theorem `2t dt = dx`, with `t > 0`, to obtain `dt/dx = 1/(2t)`. The matrix recipe owns that analytic implication and evaluates t and the derivative with certified floating arithmetic; units checks the squared/root and quotient descriptors. Likewise solve sensitivities differentiate `A X − B = 0` entrywise and use the verified invertibility premise to solve the differential equation. These fixed recipe proofs are fully specified here, not user-supplied derivative assertions or a claim that CAS proves an implicit-function theorem. No heap values are substituted into the CAS when discharging positivity, separated denominators or invertibility.

Conditional, unfinished or unsupported CAS evidence cannot be promoted to a derivative witness. ## Element arithmetic and backend checking · `sec:nrz:matrix-core-elements`

**Definition (Scalar element substrate)** · `def:nrz:matrix-core-scalar-elements`

`nrz-scalar` becomes a sealed binary32/binary64 element-arithmetic library, with `Finite<P>`, `Enclosure<P>`, adjacent-value operations, explicit precision changes, fixed-order reductions and a bounded numeric literal decoder. It owns neither a quantity nor a per-value ledger, matrix, descriptor or source model. Replace the provisional residual-threshold exactness shortcuts and interval public surface outright; keep only independently re-established format and enclosure arguments. Canonicalize signed zero on finite admission. Endpoint enclosures denote closed real sets, not affine physical points or probabilistic intervals. Production numerical data stays in plain floating buffers; temporary element enclosures are the kernel verification substrate.

**Rule (Rounding proof and environment)** · `rule:nrz:matrix-core-rounding`

Certification assumes IEEE binary32/binary64, round-to-nearest ties-to-even, gradual underflow, correctly rounded addition/subtraction/multiplication/division/square root, nearest format conversion and explicit fused multiply-add. Admit the gate's `x86_64-unknown-linux-gnu` target only after the boundary corpus passes for each compiler/profile; the historical observation (`assum:nrz:gate-targets`) does not admit a new build automatically. No fast-math reassociation, flush-to-zero, excess intermediate precision or mutable floating environment is supported. Record environment assumptions; probes can detect selected violations but cannot prove external code never changes the environment. No unsafe floating-control inspection or new toolchain exemption is permitted.

If a primitive finite result is `r = RN(z)`, the exact real z is in the rounding cell of r, whose midpoint boundaries lie between `next_down(r)` and `next_up(r)`. Thus that adjacent pair encloses z, including subnormal or zero results under gradual underflow. Refuse when r or a needed outward neighbor is nonfinite. This conservative rule needs no relative-error formula near zero. Exact shortcuts are restricted to checked identities: addition of zero, subtraction of identical finite operands, multiplication by zero or ±1, zero divided by a proved nonzero value, division by ±1, and sqrt of zero or one. Negation and absolute value are exact sign operations. A rounded residual equal to zero proves no additional exactness. Tighter error-free transforms require their own admitted domain proof and oracle corpus (`ex:exemplars:error-free-transformations`).

Endpoint addition/subtraction use monotone endpoints; multiplication/division use the hull of four endpoint combinations, with any zero-containing divisor refused. Square handles crossing zero and intersects the lower bound with zero; sqrt requires a nonnegative lower endpoint and uses monotonicity. Explicit FMA encloses the eight endpoint triples of the multi-affine expression using one `mul_add` each; multiply-then-add remains two separate rounded operations. Sums and dots use a documented increasing-index left fold, with zero for an empty reduction and mismatch refusal for unequal dot lengths. Induction on these inclusion-preserving operations proves containment. A finite final exact answer does not excuse an overflowing intermediate; this order may refuse.

A norm upper bound uses a finite positive power-of-two scale chosen from the largest magnitude, encloses division by that scale, squares, sums, takes sqrt and encloses multiplication back. Zero input returns zero. Enclose scaling even when it is a power of two, because subnormal information can be lost. Clamp an enclosure's lower norm/square endpoint to zero only using the mathematical nonnegativity proof. Refuse an unbounded result. For a kernel candidate c and an independently obtained enclosure `[l,u]` of its exact target t, compute e as an outward upper bound on `max(abs(c−l),abs(c−u))`; then `abs(c−t) ≤ e`. This is the kernel's numerical-error companion, including verification-rounding conservatism. It does not describe measurement error, truncation omitted by a recipe, or statistical approximation.

**Decision (faer candidates and a small accuracy crate)** · `dec:nrz:matrix-core-backend-accuracy`

Only matrix depends on faer. Its safe storage and selected kernels produce candidates, factor resources and scratch; no public faer result is a checked region until descriptor, companion, numerical and publication checks succeed. Independent interval dot products enclose matrix products, residuals, inverse defects and covariance contractions without using faer's reduction order as a premise. For solves, the certificate below converts residual error to solution error. Kernel precision and verification precision are separately reported; f64 verification of f32 centers is permitted because widening is exact. Candidate speed never changes the admitted proof.

Retain `nrz-accuracy` as a small separate crate for dimension-neutral nonnegative bound arithmetic, named norm/budget policies and mathematical budget decisions over scalar enclosures. Matrix and later physics both need that policy vocabulary, and scalar should not depend on it. Do not put `ScalarValue`, a heap, covariance ownership, unit descriptors or a separate provenance store there. It owns no per-number ledger and cannot issue a heap certificate. Matrix alone combines region-level evidence into private deterministic access tokens; accuracy's public mathematical bound results require matrix target/version validation. This narrower responsibility merits a crate without making uncertainty scalar-first. The architecture package descriptions need the owner follow-up recorded below.

**Procedure (Descriptor constants cross once)** · `alg:nrz:matrix-core-constant-lowering`

Each digit is exactly representable, so induction proves inclusion of the specified mathematical constant. **Rule (Affine conversion error is propagated over regions)** · `rule:nrz:matrix-core-affine-conversion`

For an exact checked coefficient a enclosed by `[a]`, exact shift b enclosed by `[b]`, center c and deterministic component bound r, enclose `[a] c + [b]` to bound the new center discrepancy e. Then `r′ = sup(abs([a])) r + e` is sound, since `a(c+δ)+b−c′ = aδ + (ac+b−c′)`. This includes coefficient representation error both at c and over δ. For a general fixed matrix map the same argument gives `abs([C]) r + e`. Use differences and zero offsets for radii and reference scales. An uncertainty in a calibration coefficient is a separate uncertain operand, never hidden inside an exact measure definition. Irrational/symbolic scales retain the current explicit unsupported boundary.

For covariance `U′ = C U Dᵀ`, use intervals enclosing C, D and the mathematical U to enclose the exact parameter result. Choose its floating center and derive a separate evaluation bound; do not add conversion e to physical covariance as though rounding were a new random experiment. The two target maps, including identity maps for unchanged sides, are mandatory. Convert a connected requested bundle transactionally: allocate all new value representations and transformed companion targets before publication. Original bundles remain valid for their old versions. Unknown cross blocks or a missing external target map refuse the requested bundle. Standard uncertainties are numerical square roots of variance parameters with their own evaluation bounds; they never become deterministic physical radii.

For narrowing, widen a rounded f32 endpoint exactly to f64 for comparison with its source endpoint; step a lower endpoint down only if it exceeds the source, and an upper endpoint up only if it is smaller. Reject out-of-range finite sources and nonfinite outward endpoints. Evaluate the center displacement outward and add it once, while outward-converting the previous deterministic bound. Statistical parameter rounding belongs to that parameter's region. Widening retains every old error; measure conversion and precision conversion remain separate operation records even if requested together. Round trips are tested by containment under both conversion errors, not equal center bits (`rule:vision:precision-conversions`).

## The certified real square solve · `sec:nrz:matrix-core-solve`

**Procedure (Solve over a frozen binding)** · `alg:nrz:matrix-core-solve-pipeline`

Admit `A: X → Y` of positive square order n and `B: W → Y` with positive column count r. Validate original semantics, ordered axes, source/companion coverage, precision, layouts and budgets before faer entry. Form one normalized coordinate problem with the retained X/Y/W references. Sum compatible deterministic input contributions exactly once into componentwise bounds E_A and E_B; derive outward Frobenius bounds r_A and r_B. A normwise-only input companion may instead supply its declared normalized radius, or conservatively expand to entrywise bounds. Never use standard uncertainty or covariance as either deterministic radius. Explicit RepresentedInputs mode records the physical-input exclusions and still includes import/conversion errors covered by its named nominal target.

Candidate generation uses private partial-pivoted LU resources and optional invertible dimensionless row/column power-of-two equilibration. If `A_s = D_r Â D_c` and `B_s = D_r B̂`, solve `A_s Y = B_s` and set `Ẋ = D_c Y`. Construct an approximate inverse candidate in the same normalization, undoing equilibration as `Z = D_c Z_s D_r`. All scaling and restoration rounding is enclosed. Verify against the saved unequilibrated normalized center Â and B̂, so the certificate never assumes scaling was exact or improved conditioning. Check finite candidates and permitted backend preconditions; a failed pivot or nonfinite result is a candidate failure, not a published value. Separate the physical right-hand sides from the identity columns used for Z.

**Rule (Inverse witness and total solve bound)** · `rule:nrz:matrix-core-solve-theorem`

In these normalized coordinates let c_X be the candidate, `ρ ≥ norm_F(B − A c_X)`, `z ≥ norm_F(c_X)`, `q ≥ norm_F(I − Z A)` and `h ≥ norm_F(Z)`. Validate each residual/defect entry through independent interval dot products and compute norms with the scalar scaled-norm procedure. If `q < 1`, the Neumann series gives `norm_2(A⁻¹) ≤ h/(1−q) = g`: `Z A = I−E` is invertible, and `A⁻¹ = (I−E)⁻¹ Z`. Frobenius bounds dominate the needed spectral norms. This is the explicit approximate-inverse argument taken from (`ex:exemplars:intlab`), consistent with (`dec:vision:inverse-norm-certificate`). A tighter q may be admitted only with its own valid norm proof.

Require an upper bound on `g r_A` strictly below one and a positive lower bound `d ≤ 1−g r_A`. For every common operator perturbation with `norm_F(ΔA) ≤ r_A` and joint right-hand-side perturbation with `norm_F(ΔB) ≤ r_B`, the solution exists and satisfies `norm_F(X−c_X) ≤ g (ρ + r_B + r_A z)/d`. Indeed `A(X−c_X) = (B−A c_X) + ΔB − ΔA c_X − ΔA(X−c_X)`; submultiplicativity moves the last term to the left. The same ΔA acts on every right-hand side. The numerator includes both input/solution interaction and candidate residual; it is not a linearized error formula (`rule:nrz:shape-certified-solve`).

Compute g, all products, the denominator lower bound and the final upper radius outward. A separate numerical-only companion `g ρ` bounds the discrepancy from the represented center solution; the total certificate above already includes that contribution and its perturbation amplification. These overlapping views name their coverage and are not added together. For inspection the total derivation retains input/computational parents and the interaction amplification without claiming unique attribution. Convert its normalized norm radius to conservative entry bounds of the same magnitude, then scale per X/W entry and include restoration error. For homogeneous physical coordinates, residual and r_B carry B's dimension, r_A carries A's, g the inverse dimension, and the output radius B/A; every norm and quotient also carries compatible kinds/difference measures.

An explicit inverse solves against the typed identity on Y and publishes `A⁻¹: Y → X` with a separately checked matrix envelope. The approximate Z used only to certify a solve is a private witness and cannot escape as a certified inverse. A factor resource records relational reconstruction evidence when exposed as such, but never a forward bound on each LU entry. Factor-to-value export is unsupported until each factor's own descriptor, axes and numerical companion are established (`rule:vision:decomposition-objects`).

**Rule (Budgets, recovery and cache keys)** · `rule:nrz:matrix-core-solve-policy`

An optional local budget names the output norm/coordinates or every requested component, nonnegative absolute difference tolerance a, nonnegative relative ratio t and strictly positive characteristic difference scale s. Units checks those descriptors; accuracy compares the certified upper error against a lower enclosure endpoint of `a + t s`. Acceptance requires the upper error to be no larger. A proved violation of this certificate threshold returns BudgetExceeded, which says the available bound fails the budget rather than proving the actual error is too large; an unresolved comparison returns BudgetUnresolved; absence returns NotRequested and never Met. Point budgets use difference scales, not a shifted point center. Equivalent display measures use the same physical tolerance and references. Changing normalization changes a norm-based budget unless its physical weighted metric is preserved explicitly.

Refinement computes an independently enclosed residual, selects a finite residual-center correction right-hand side, solves with the eligible factors, updates the candidate in the declared precision and recomputes the full certificate. Record each attempt. Stop on budget success, iteration/work limit, nonfinite arithmetic, or no decrease in the certified radius over the configured stagnation window; residual reduction alone cannot accept an output. A policy may authorize a fresh f64 execution after f32 failure, with explicit conversion/error companions and distinct precision in the returned tagged outcome. The promoted execution retains input measurement and import errors; it does not recover lost f32 input information. Mixed f32 factorization/f64 residual work is a candidate strategy, always accepted by the same final theorem. Zero refinement iterations and no promotion are valid bounded policies.

A factor key includes operator identity/version, shape and descriptor revision, precision, maps, structure scope, algorithm and relevant policy. Its inverse witness also includes arithmetic environment, defect proof and norm interpretation. Right-hand-side identity/version, all companion/source revisions, output targets, budgets and recovery choices belong to the solve-result key. Changing B can reuse a factor but never its previous point's residual or certificate. Changing a covariance source can invalidate the statistical result without invalidating a source-free operator factor. Original schema or source revisions remain exact key components; hashes only accelerate comparisons (`rule:nrz:computation-cache-validity`).

Failures distinguish InvalidBinding, UnsupportedOperation/Mode, MissingCoverage/CrossBlock, DomainNotEstablished, NonFinite, ArithmeticOverflow, CandidateFailure, CannotCertifyInverse, PerturbationMargin, BudgetExceeded, BudgetUnresolved, Stagnation and ResourceLimit. Preserve typed units/CAS causes, original paths and block/entry/target locations. An unsuccessful bound proves neither singularity nor an inaccurate actual solution. An operation record contains success or its explicit failure and available evidence; downstream execution requires an admitted published handle. Physics later adds blocked/inactive graph records over these outcomes. Numerical evidence already valid under another scope remains inspectable in the failure record.

## Worked independent oracles · `sec:nrz:matrix-core-oracles`

The examples below are mathematical expectations recomputed with independent exact rational arithmetic for this design. They are not observed results of a production heap. Implementation tests decode returned floating values/endpoints to exact rationals and compare containment; an outward implementation may return wider bounds than the exact formulas. Unless explicitly stated otherwise, these examples omit new floating evaluation error in their displayed exact numbers; the implemented result must include it.

**Example (Two entries and their independent regions)** · `ex:nrz:matrix-core-heap-example`

Let x be two voltage differences `(2,3) V`, with deterministic radius entries `(1/10,1/5) V` under an explicitly bounded-input scenario, and in a separate finite-moment scenario joint covariance `U_x = [[1/100,1/200],[1/200,1/25]] V²`. These statistical and deterministic declarations are separate scenarios, so no compatibility between their support assumptions is inferred. The normalized statistical matrix is positive definite: its leading entry is positive and determinant is `3/8000`. One slab may hold center offsets 0–1, radius offsets 2–3 and covariance offsets 4–7; its own two-entry numerical-error region occupies another disjoint range. The covariance vectorization is `(1/100,1/200,1/200,1/25)` in column order. x, its radius, covariance and numerical-error descriptors all name different regions; each companion targets x's exact ValueId/version, and covariance names both ordered entry selections.

For the fixed dimensionless map `L = [[1,2],[-1,1]]`, the exact center is `y = (8,1) V`, deterministic radii are `(1/2,3/10) V`, and `U_y = [[19/100,13/200],[13/200,1/25]] V²`. The cross block `U_yx = [[1/50,17/200],[-1/200,7/200]] V²` must remain available. For z = x + x, the center is `(4,6) V`, deterministic radii double and covariance is `4 U_x`, not `2 U_x`: two input handles select the same source. Selecting only y's second entry selects the matching covariance row/column and cross row; it does not redefine the source.

An alias selecting x's first entry names the same base version. Replacing that entry increments x's base version and makes the previously captured covariance, y lineage and bindings stale; identical schemas do not rescue them. Retiring and reusing x's descriptor slot makes the old generation fail resolution. Converting x to a new precision allocates a new value descriptor and transformed companion targets, retaining source identity and any narrowing error. Old x and y remain valid only as explicit immutable snapshots of their old versions, not as current aliases. These are required lifecycle outcomes, not a runtime transcript.

**Example (Product and nonlinear interaction)** · `ex:nrz:matrix-core-interaction-example`

Take `A = [[2,0],[1,3]]`, `B = (1,2)ᵀ`, componentwise bounds `R_A = [[1/10,0],[0,1/5]]`, `R_B = (1/10,1/4)ᵀ`, all in compatible ratio coordinates. The center product is `(2,7)ᵀ`. The three deterministic terms are `abs(A) R_B = (1/5,17/20)ᵀ`, `R_A abs(B) = (1/10,2/5)ᵀ` and `R_A R_B = (1/100,1/20)ᵀ`, totaling `(31/100,13/10)ᵀ`. The all-positive endpoint perturbation gives `(231/100,83/10)ᵀ`, attaining both differences, so dropping the interaction demonstrably fails.

For the preceding voltage vector x under elementwise square, derive squared-voltage output kinds explicitly. The Jacobian is `diag(4,6)` in voltage units, the deterministic radii are `(41/100,31/25) V²`, and the linearized covariance is `[[4/25,3/25],[3/25,36/25]] V⁴`. The deterministic result includes r²; the statistical matrix is only LinearizedMoments. For a sharp counterexample to promoting it, a ratio-valued random scalar taking −1, 0 and 1 with equal probabilities has mean zero and variance 2/3; its square has mean 2/3 and variance 2/9, while `f(center) = 0` and the derivative-based variance is zero. Thus neither a nominal nonlinear center nor its local covariance is generally the true moment, even with finite exact input moments.

**Example (Solve bound and common columns)** · `ex:nrz:matrix-core-solve-example`

In normalized coordinates choose `A = diag(2,4)`, `B = (2,8)ᵀ`, candidate `(1,2)ᵀ` and inverse witness `Z = diag(1/2,1/4)`. Exact residual and defect are zero. Since `norm_F(Z)² = 5/16 ≤ 9/16`, g = 3/4 is a valid conservative inverse-norm bound; `norm_F(c_X)² = 5 ≤ 25/4` permits z = 5/2. For r_A = 1/10 and r_B = 1/5, the margin is 37/40 and the exact displayed bound is 27/74. A permissible perturbation `ΔA = diag(−1/10,0)`, `ΔB = (1/5,0)ᵀ` yields solution `(22/19,2)ᵀ`, whose error 3/19 lies below 27/74. With absolute budget 2/5 and zero relative part the displayed bound meets budget; with 1/3 it does not. Floating production must establish its own possibly wider q, g, residual and final threshold comparison.

For two right-hand sides, use a single ratio scalar operator `A = 2 + δa` and exact `B = (2,4)`. At δa = 0 the solution is `(1,2)` and sensitivity to the common operator perturbation is `(−1/2,−1)ᵀ`. If the operator's variance is 1/100, its linearized solution covariance is `[[1/400,1/200],[1/200,1/100]]`, with a nonzero cross-column block despite exact right-hand sides. This is a 1×2 output value and a 2×2 companion, not two independent solves. The mathematical derivative follows from differentiating `(2+δa) X = B`; a deterministic certificate still needs a separate bounded perturbation family.

The mixed voltage/current ladder (`ex:nrz:resistor-shape-covariance`) and common-source gains (`ex:nrz:resistor-source-batch`) are larger acceptance oracles. Recompute the fixed operator, `w = (1,5/13,2/13,1/13,−8/13)ᵀ`, `M w = (0,0,0,0,1)ᵀ` and the full covariance outer product independently. With source variance 1/10000 and gains 1, 2, 3, the cross block between v1 at gain 1 and current at gain 3 is `−3/42250 V A`; the mean's covariance is `4 U_0`, whereas discarding cross blocks gives the wrong `14/9 U_0`. Matrix integration invokes operations separately and retains those relations; implementing the batch planner itself remains physics work.

**Rule (Adversarial coverage and refusal quality)** · `rule:nrz:matrix-core-refusal-tests`

Require genuine successful enclosures for small admitted systems and maps, so refusing everything cannot pass. Validate every successful result against the exact rational problem, including import uncertainty; failure remains explicit and carries no false success. The historical scalar Rump test and matrix fixture distance check use production interval arithmetic in their expected-value paths; replace those oracle paths rather than treating their previous success as independent truth.

Test resource limits immediately below, at and above the required work/capacity without equating exhaustion with mathematical impossibility. **Rule (Measurements and completion gate)** · `rule:nrz:matrix-core-measurements`

Benchmark artifacts use committed inputs and recorded measurements; documentation generation never runs a live benchmark. No performance threshold is invented in this design.
