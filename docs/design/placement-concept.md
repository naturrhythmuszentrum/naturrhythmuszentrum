# Heap placement, padding and collection · `spec:nrz:placement-concept`

**Principle (One placement account)** · `prin:nrz:placement-scope`

Placement is graph structure describing how a checked question occupies numerical storage and how its results reach decision nodes. This concept inventories the existing arrangements and supplies requirements for their subsequent design; it specifies no replacement API, implementation or compatibility obligation. Existing decided contracts remain authoritative where the inventory exposes conflicts. The continuation is (`step:nrz:backlog-placement-design`), outside LC closing. Affected designs are those that own an inventoried arrangement and receive a citation back; architectural and CAS foundations supply inherited principles without acquiring arrangement ownership.

**Principle (Inherited boundaries)** · `prin:nrz:placement-foundations`

Numerical data stays on the heap; CAS holds exact graph structure and checked judgments, never matrix payload (`prin:nrz:descriptor-binding-float-heap`), (`dec:nrz:matrix-core-cas-boundary`). A native float stands for a cell; demanded finer resolution generalizes it to a multileg heap matrix of native floats, never a wider float (`dec:nrz:matrix-core-multileg-cells`). Every float entry has binding coverage, possibly through several checked overlapping readings such as a complex value and its real part (`prin:nrz:descriptor-binding-total`), (`rule:nrz:descriptor-binding-checked-overlap`). Lowering checks meaning; kernels are meaning-free float edges with laws and enclosure theorems (`def:nrz:descriptor-binding-lowering`), (`def:nrz:descriptor-binding-kernel`), (`thm:nrz:descriptor-binding-kernel-enclosure`). Grid questions prepare exact authority for a tile box and evaluate varying cells in a heap pass (`rule:nrz:lc-grid-tile-certificate`), (`rule:nrz:lc-grid-heap-pass`). Representation questions concern shared graph nodes and evidence edges, not comparisons of disconnected lists (`def:nrz:cas-graph-model`), (`def:nrz:descriptor-binding-computational-graph`), (`rule:nrz:tiles-streams-identities`). Exact descriptors coexist with machine-dependent heap results reproducible within tracked error (`prin:nrz:descriptor-binding-reproducibility`). A heap result changes descriptor meaning only through the existing decision node (`def:nrz:decision-node`), (`rule:nrz:descriptor-binding-certified-feedback`).

## The arrangements in use · `sec:nrz:placement-inventory`

**Convention (Inventory costs and evidence)** · `conv:nrz:placement-inventory-costs`

Source paths in this inventory are relative to `crates/matrix/src/`. Payload formulas exclude headers unless stated; actual reserved capacities, owner records, maps, staging and simultaneous lifetimes must also be charged. Byte residence, traffic, native Work and exact Work are different quantities. The native tariffs are (`rule:nrz:matrix-loans-owner-tariffs`), (`rule:nrz:matrix-loans-kernel-tariffs`); legacy layout-work limits are not interchangeable with that caller ledger. Bounds below describe demand, not measured time or a new tariff. Exact byte derivations and their assumptions are (`assum:nrz:placement-cost-symbols`), (`calc:nrz:placement-slab-bytes`), (`calc:nrz:placement-mask-bytes`).

**Observation (Slabs and allocator capacity)** · `obs:nrz:placement-slabs`

Its implied graph has slab/region nodes, allocation-occupation nodes and component-to-region placement edges; capacity and reservation edges distinguish addressable entries from allocator padding. Legacy sharing puts several region edges into one slab, whereas a loan gives each lendable region a separate owner node.

`heap/extent.rs`, `heap/resources.rs`, `heap/slots.rs` and `loan/lifecycle/admission/plan.rs` arrange checked scalar lengths into precision-specific owners. Matrix decides allocation, indirection and lifetime; the pinned allocator decides rounded physical capacity. A slab's declared length includes checked layout gaps, while backend spare capacity is not addressable tile storage. The payload reservation is wR bytes, the safe initialization visits L entries, and headers and slot scans add their actual costs (`rule:nrz:matrix-loans-slab-capacity`), (`rule:nrz:matrix-core-resolution`). Legacy slabs may contain separate regions, but detachable loans require separate owners; those are different sharing decisions, not interchangeable lifetime contracts (`dec:nrz:matrix-core-owner`), (`dec:nrz:matrix-loans-allocation-owners`).

**Observation (Affine component arrangements and gaps)** · `obs:nrz:placement-components`

Its implied graph links cell/component nodes through signed address-map edges to slab-region nodes, with gap nodes excluded from those component edges. Dense and affine routes prove the same placement edge by different bounded proofs; the output route may instead enumerate addresses.

`layout/affine.rs`, `layout/outputs.rs`, `heap/views.rs` and `loan/lifecycle/admission.rs` implement contiguous, interleaved, reversed and signed affine component maps. Matrix checks the chosen engine layout; the host writes through its sealed declaration. A map decides where each logical component resides, including prefix, suffix and internal gaps. Full physical length L costs wR reserved bytes and L zero-fill steps per channel; logical initialization still concerns Ck components. The host affine injectivity proof uses bounded machine-word arithmetic; general output disjointness may enumerate and sort addresses with temporary address storage and a layout-work bound. These are distinct proofs of related nonaliasing facts (`rule:nrz:matrix-loans-dense-host-layout`), (`rule:nrz:matrix-loans-affine-host-layout`), (`rule:nrz:matrix-core-layouts`). Explicit gathers remain refused by this host route even when a gather could describe the same addresses.

**Observation (Padded native cell maps)** · `obs:nrz:placement-native-padding`

Its implied graph has destination cell positions, original cell nodes and partial correspondence edges: unused positions have padding-owner edges but no original-cell edge. A dense consumer expects total correspondence; a selected consumer traverses only present edges, which explains the different admission outcomes.

`shape/maps.rs` and `loan/application/movement.rs` retain original, gathered or product cell incidence without an entry-sized descriptor map. Matrix chooses destination capacity and checks its relation to source cells. A compacted selection can have fewer mapped cells than destination capacity; unmapped cells have no source and stay unrequested. Dense enumeration and composition refuse such maps, dense kernel scratch refuses them in `kernels/resources.rs`, and `statistics/plan.rs` unconditionally withholds statistics capability from `ProjectedElementwise`, the recipe carrying native padding, as well as withholding Transform capability when `has_padding()` holds. Capacity still costs full destination slabs, logical tracking and mask words; selected readers charge only actual checked loads, with map/projection work additional. Native selection padding therefore differs from harmless physical gaps inside an injective host map (`rule:nrz:matrix-loans-projected-square`), (`[MATRIX-test:unit:loan-native-padding-dense-refusal]`), (`[MATRIX-test:unit:loan-native-padding-map-refusal]`).

**Observation (Packed masks)** · `obs:nrz:placement-masks`

Its implied graph has mask nodes with coverage edges to cell nodes and a layout-version edge authenticating bit interpretation; word-tail padding has an exclusion edge to its owner. Coverage edges do not target float-component positions, even when those positions are permuted.

`mask/layout.rs`, `mask/storage.rs` and `mask/algebra.rs` place one bit per cell into zero-initialized unsigned 64-bit words, retain layout versions and clear word tails. Matrix decides storage and checks correspondence; the bindings and decision contracts decide a mask role's meaning. Each independent mask costs 8 ceil(C/64) payload bytes plus capacity/header costs; scans and algebra pay for words visited and selected cells emitted, while publication and normalization have their own charges. Equal bit patterns or equal populations cannot substitute for equal original cell associations. A component permutation changes float positions without changing the logical cell bits (`def:nrz:tiles-streams-mask-storage`), (`rule:nrz:tiles-streams-mask-algebra`), (`rule:nrz:tiles-streams-mask-versions`).

**Observation (Tiles and bundles)** · `obs:nrz:placement-tiles`

Its implied graph has tile and bundle nodes with membership, ownership, required-companion and atomic-publication edges to their region/mask nodes. Bundle closure follows those dependency edges; a decision demand is a separate edge selection that can cross bundle membership.

`loan/declaration.rs`, `loan/lifecycle/admission/plan.rs` and `loan/lifecycle/publication.rs` group value owners, companion owners, tracking words and masks into checked tile declarations and publication bundles. The question supplies axes and dependencies; matrix selects feasible capacity/layout under the host preference rule and owns the complete reservation. Bytes are the sum of distinct simultaneously live owners, including scratch and retained inputs; Work includes validation, zero-fill, coverage closure, records and retention edges. Exact tile authority is prepared once for its box rather than once per varying cell. A storage bundle is atomic ownership/publication scope, while a decision's demand can span several bundles or part of one (`def:nrz:matrix-loans-declaration`), (`def:nrz:matrix-loans-identities`), (`rule:nrz:tiles-streams-tile-choice`), (`def:nrz:lc-grid-barrier`).

**Observation (Companion channels)** · `obs:nrz:placement-companions`

Its implied graph has channel nodes, target-version edges to value nodes and independent component-placement and coverage edges. Cross-companions have both target edges; forcing them into the host triple's shared placement would erase relations present in the general graph.

`loan/payload.rs`, `loan/lifecycle/admission.rs` and `loan/application/evaluation.rs` place center, deterministic total and numerical-error channels in separate owners. Bindings decides their exact target relations and independently shaped readings; matrix authenticates actual extents, maps, versions and coverage. A dense binary64 center/total/error triple costs 24Ck logical payload bytes before allocator rounding, masks and tracking; independently shaped covariance or cross-companions require their own extents and both target maps. Every visited component and incidence is charged; equal byte shape grants no companion authority (`def:nrz:matrix-loans-host-total`), (`def:nrz:matrix-loans-host-error`), (`def:nrz:matrix-core-companion-records`), (`rule:nrz:descriptor-binding-companion-reading`). The host triple's shared component map is a special case, not a rule that all companions have the value's shape.

**Observation (Scatter and selected writes)** · `obs:nrz:placement-scatter`

Its implied graph fans a selected write node out to injective destination component nodes, then joins affected reading/evidence edges into a replacement transaction. The stores and whole-base component copies spread; replacement closure and publication are fan-in without a mandatory decision node.

`heap/scatter.rs`, `layout/outputs.rs` and `binding/live/write.rs` check injective writes, prepare whole-base replacement scratch and publish the complete invalidation closure. The caller selects a checked reading; matrix decides and validates physical destinations and affected versions. Scatter distributes contributions without reducing them, but its implementation can also copy a whole base and publish a replacement. For B base entries and q affected planes, raw whole-base scratch costs wqB bytes in addition to fresh slabs, selected-index/invalidation records and the still-live old owners. For a non-dense alias layout with E entries, injectivity scratch additionally reserves max(E × size_of((Key, usize)), size_of((Key, usize, usize))) bytes for its address vector or preceding one-range probe; those two temporaries do not coexist. Copies, output checks and dependency visits contribute their actual work; some legacy routes use compatibility resource scopes rather than the loan ledger. Read-only repeated aliases are admitted where writes would overlap and refuse (`rule:nrz:matrix-core-layouts`), (`rule:nrz:descriptor-binding-invalidation`), (`rule:nrz:matrix-loans-compatibility-scopes`). The surrounding publication is collection, distinct from the scatter stores themselves.

**Observation (Relocation)** · `obs:nrz:placement-relocation`

Its implied graph retains original cell/value nodes while replacing physical placement edges to new slab nodes and advancing their epoch. The whole-owner transaction joins many region edges without a mandatory decision node; mathematical identity edges can survive the physical change.

`heap/relocation.rs`, `heap/views.rs` and `heap/slots.rs` move legacy storage by preparing replacement slabs and refreshing physical indirection under an exclusive heap borrow. Matrix decides when movement is safe. The physical epoch changes while unchanged mathematical values and companion targets may keep their versions. Preparation pays for all copied entries across formats and checked explicit gather entries; bytes include old and new slabs, tables and raw copy scratch at their simultaneous peak. Managed lent or pinned owners cannot be moved through this route (`rule:nrz:matrix-core-invalidation`), (`rule:nrz:matrix-core-resolution`), (`rule:nrz:matrix-loans-lease-coexistence`). This physical heap compaction is different from selecting fewer logical cells, although both collect and publish storage.

**Observation (Mask compaction and materialized movement)** · `obs:nrz:placement-compaction`

Its implied graph joins selected mask/cell nodes into a new prefix layout and retains new-position-to-original-cell edges. Numerical movement adds center and companion edges separately, so the mask-only graph is not the complete moved bundle graph.

`mask/compaction.rs` counts and gathers selected original indices into a dense prefix with unused capacity clear; it publishes masks and maps, not numerical components. `loan/application/movement.rs` separately copies complete center/total/error bundles to disjoint dense owners. The engine's continuation cost comparison decides whether to materialize a branch; bindings preserves its checked reading relation. For S selected cells, an original-index map has S native indices plus metadata; destination capacity pays full masks/slabs, and old parents remain live until their readers release. Population and prefix scans pay per visited word, map construction per selected index and movement per transferred component, with checked invocation and closure costs (`rule:nrz:tiles-streams-mask-compaction`), (`rule:nrz:tiles-streams-branch-choice`), (`rule:nrz:matrix-loans-mapped-movement-work`). Treating mask compaction alone as complete numerical compaction would lose companions and source lineage.

**Observation (Gather and identity transport)** · `obs:nrz:placement-gather`

Its implied graph fans an existing view out through independent component-copy edges into packed storage, then joins the completed components for publication/export. Mask transport joins source and target mask nodes through their common original-cell nodes. A position-to-position zip would replace those identity edges with a different, unjustified relation; the publication and mask join lack a required decision node.

`layout/packing.rs` packs a raw view into logical column order when a borrowed backend view is unavailable; `mask/gather_transport.rs` transports mask coverage by joining retained original identities, not equal physical positions. Matrix owns both mechanisms. Packing requires a fresh slab and raw export scratch proportional to all copied components and bounded layout work, but supplies no published value evidence. Mask transport reserves destination words, charges each target association and every comparison in its bounded ordered-map search, and moves no numerical values. For T destination associations and S sorted source associations the search demand is O(T log(S+1)), besides word initialization and publication; a dense source lookup is constant per association. Native original-index gathers and arbitrary component gathers have different admission boundaries (`rule:nrz:matrix-core-layouts`), (`rule:nrz:matrix-loans-gathered-law`), (`rule:nrz:tiles-streams-mask-algebra`). The packing copy spreads, just as scatter stores do; publication/export of the completed packed view and mask transport collect under (`prin:nrz:placement-spread-collect`).

**Observation (Broadcast and binary applications)** · `obs:nrz:placement-broadcast`

Its implied graph fans one retained scalar/channel node out to many consumer-cell nodes, preserving one shared source node. Equal-extent binary application edges differ from factor-projection or singleton fan-out edges; one must not be substituted for another merely because their buffers fit.

`heap/aliases.rs` permits checked read-only repeated addresses; `loan/masked_reader.rs` and `loan/owned_selection.rs` can project repeated cells without copying their floats. Lowering decides whether a tile-invariant scalar can be shared; matrix checks lifetime, incidence and companion coverage. Such a scalar costs one retained bundle plus use edges rather than a replicated plane, while each actual projected load and coverage check remains charged; materializing repeated cells instead pays destination bytes and copies. `loan/application/binary/validation.rs` and `loan/application/binary/correspondence.rs` admit Product and Quotient on equal extents, with a per-tile scalar on either ordered side (`rule:nrz:matrix-loans-binary-tile-scalar`), or on explicitly checked Cartesian factors (`rule:nrz:matrix-loans-cartesian-binary`). Tile-scalar demand belongs to the output-sized operand, and Cartesian demand belongs to the captured product layout; each route retains its original source pins, axes and companion coverage. Other unequal extents and implicit factor incidence remain refused. A function's product name alone does not establish Cartesian factor semantics. General broadcast must preserve the same source dependence and carry an admitted numerical law (`rule:nrz:descriptor-binding-hoisted-constants`), (`rule:nrz:matrix-loans-binary-correspondence`), (`rule:nrz:matrix-loans-binary-demand`), (`def:nrz:matrix-loans-owned-product-reader`).

**Observation (Cartesian factor binding)** · `obs:nrz:placement-cartesian`

Its implied graph has product-axis nodes with ordered factor edges, cell-to-tuple edges and projection edges back to shared original factor cells. Component-order edges and tuple-order edges connect different node kinds; explicit gathered products additionally retain the original-product correspondence edge.

`mask/product.rs`, `shape/maps.rs`, `loan/masked_reader.rs` and `loan/owned_selection.rs` retain ordered product axes and factor projections. Bindings determines the question's factor meaning; matrix checks original axis identities, product extent and selected factor. Product capacity is the checked product of factor capacities; metadata for the native factor relation is constant-size, while a materialized product mask costs words proportional to product capacity. Product construction charges three native units; an owned factor load adds one projection unit to ordinary selected-load work, giving four units before a successful load. Gathering first resolves the original product index and then projects the factor. The product's row-major tuple enumeration and a component matrix's logical column order describe different index spaces; neither supplies statistical independence (`def:nrz:matrix-loans-owned-product-reader`), (`conv:nrz:shape-entry-order`), (`rule:nrz:matrix-loans-mapped-movement`).

**Observation (Waiting state in the arrangement graph)** · `obs:nrz:placement-inventory-waiting`

Affine reads, broadcast, factor projection, packing copies and scatter stores traverse already published, authenticated nodes and need no arrival choice of their own. Tile evaluation starts with its admitted present inputs; no waiting state is created by its fan-out edges. Under the graph criterion of (`prin:nrz:placement-spread-collect`), packing publication/export, mask compaction/transport, relocation commit, whole-base replacement closure, filled-closure handback and publication collect contributions into a shared result or completion scope. Their low-level entry points in (`obs:nrz:placement-gather`), (`obs:nrz:placement-compaction`), (`obs:nrz:placement-relocation`), (`obs:nrz:placement-scatter`), (`obs:nrz:placement-tiles`) do not themselves declare a decision-node arrival set and choice policy. That missing ownership is a conflict even when all contributions are present synchronously. A masked application partitions admitted cells into the completed set C, `CellRefused`, `CellUndecided` and `Pending`; finalizing a suspended application's completed subset chooses over incomplete arrivals without a decision node (`rule:nrz:matrix-loans-masked-law`), (`rule:nrz:matrix-loans-application-outcomes`). Retirement and reclaim wait for independent reader, pin and delivery releases, retaining `RetirementWaiting(PinnedUses)` and preventing full flush completion until obligations discharge (`alg:nrz:matrix-loans-retirement`), (`rule:nrz:tiles-streams-release`), (`rule:nrz:tiles-streams-flush-completion`). Both are additional collection conflicts. Graph-walk readiness and deterministic per-node flush behavior are distinguished from collection choice in (`prin:nrz:placement-waiting-decision`).

## Vocabulary · `sec:nrz:placement-vocabulary`

**Convention (Established cell, tile and bundle meanings)** · `conv:nrz:placement-established-terms`

Cell retains the demanded numerical selection meaning of (`def:nrz:lc-compute-cell`), generalized to the native-float refinement position of (`dec:nrz:matrix-core-multileg-cells`); it is neither an allocation slot nor a floating operation. Tile retains the finite indexed heap subset of (`def:nrz:lc-grid-tile`), with matching coverage under (`rule:nrz:tiles-streams-mask-coverage`). Bundle retains the complete versioned value, companion, map and mask association of (`def:nrz:matrix-loans-identities`). Cell, tile and bundle are nodes joined by membership and dependency edges. These definitions distinguish question membership, finite execution extent and atomic ownership; sharing one extent does not identify the three.

**Definition (Component)** · `def:nrz:placement-component`

A component node denotes one ordered native-float coordinate of a cell's admitted numerical representation. Its logical ordinal is interpreted by the checked reading map, not by its address or scalar width. A multileg cell has several such native coordinates; additional legs do not widen any coordinate's float format. Component order follows the representation and the logical-entry convention (`def:nrz:descriptor-binding-symbol-binding`), (`conv:nrz:shape-entry-order`).

**Definition (Channel)** · `def:nrz:placement-channel`

A channel node denotes one declared numerical reading carried over a cell domain with its own component shape and coverage, such as center, total radius or numerical error. Its allocation may be separate from other channels and its companion target map may relate different domains; the channel itself grants no meaning or assurance beyond the binding. Existing host channels are instances (`def:nrz:matrix-loans-host-center`), (`def:nrz:matrix-loans-host-total`), (`def:nrz:matrix-loans-host-error`), (`def:nrz:descriptor-binding-companion-symbols`).

**Convention (Slab)** · `conv:nrz:placement-slab`

A slab node denotes the contiguous typed scalar allocation already used by (`dec:nrz:matrix-core-owner`); its addressable length and rounded allocation capacity remain distinct under (`rule:nrz:matrix-loans-slab-capacity`). A region is a checked range inside an arena under (`def:nrz:scalar-arena`). Neither term denotes an independent physical source or a complete readable tile.

**Definition (Logical layout and physical layout)** · `def:nrz:placement-layout`

A logical layout is an ordered graph relation from the question's cell and component identities to the entries selected by a reading, including permutations, repetitions and Cartesian factor incidence. A physical layout connects those admitted entry nodes by authenticated placement edges to checked positions within particular numerical owners, with extents, strides and bounds. Their composition answers a concrete read; its logical part follows (`conv:nrz:shape-entry-order`), while its physical safety follows (`rule:nrz:descriptor-layout-validation`). An index permutation in one space must not silently permute the other.

**Definition (Placement)** · `def:nrz:placement`

A placement node roots the complete graph realization of logical cells, components and channels in physical owners: placement, membership, capacity, precision, companion, mask-coverage and original-association edges. Slab regions, tiles, bundles, masks and padding regions are nodes in that graph, not separate lists reconciled by shape or ordinal coincidence. It includes which storage is inaccessible padding, not only the address formula for present entries. Equal numerical bytes or equal shapes do not identify placements or authenticate their bindings (`def:nrz:matrix-loans-identities`).

**Definition (Stride, alignment and gap)** · `def:nrz:placement-geometry`

A stride is the signed element displacement associated with a logical coordinate increment in an affine physical map. Alignment is a proved divisibility constraint on an address for a stated access type, not a physical unit or a semantic property of a cell. A gap is addressable storage inside an owner's declared length that its selected component map does not reach. Gaps can be prefix, suffix or internal; another checked region may occupy an otherwise unused range, so a gap relative to one view is not automatically padding of the whole owner (`rule:nrz:matrix-core-layouts`), (`rule:nrz:matrix-loans-affine-host-layout`).

**Definition (Padding)** · `def:nrz:placement-padding`

A padding-region node denotes reserved representation capacity with no logical cell/component contribution in the relevant placement. It includes owner gaps reserved for layout, unmatched native destination cells, mask word tails and any admitted SIMD lane tails; allocator spare capacity is additionally inaccessible. Its belongs-to edge names the slab, mask or admitted vector owner, and its exclusion evidence states that it carries no logical meaning. Padding is neither an exact zero of the question nor a missing demanded observation. A hole instead names an actual logical cell whose required coverage is absent (`rule:nrz:matrix-loans-selected-loads`), (`rule:nrz:tiles-streams-partial-tile`).

**Definition (Original identity and physical position)** · `def:nrz:placement-identity`

An original cell node is identified by its scoped ordered-axis association, including original product coordinates and any retained source relation. A physical-position node denotes a checked address or mask bit in one current layout occupation; a versioned holds-component or covers-cell edge connects it to original identity. Copy, compaction and relocation can change positions without creating new original identities; repeated positions or copied cells cannot create independent sources. Gather transport resolves original associations, while versions and pins authenticate the positions presently read (`rule:nrz:tiles-streams-mask-compaction`), (`rule:nrz:matrix-loans-mapped-movement`), (`rule:nrz:batch-subset-identities`).

## Placement · `sec:nrz:placement-contract`

**Rule (Authenticated placement edges)** · `rule:nrz:placement-edges`

Placement joins the same graphs as the many-to-many symbol-to-float binding edges of (`prin:nrz:descriptor-binding-two-graphs`), (`def:nrz:descriptor-binding-symbol-binding`). A holds-component edge relates a physical position to an original cell's ordered component; a covers-cell edge relates a mask to its qualified cells; a belongs-to edge assigns padding to an owner with explicit no-meaning evidence. Membership, companion-target, source, retention and application edges keep their distinct authorities. Every placement edge carries its revision and authentication dependencies, including both endpoint identities and the proof or live check that licenses traversal. Shared exact authority does not replace current occupation checks (`rule:nrz:tiles-streams-identities`). These are graph relations, not a requirement to allocate a record per float: a checked affine or product edge can represent a whole indexed family with its quantified evidence.

**Rule (Shared placement and preparation nodes)** · `rule:nrz:placement-sharing`

Two readers of the same authenticated placement share its nodes and retain separate use edges rather than duplicate placement authority. Repeated preparation of that same placement is one prepared node plus a charged lookup and current authentication, following the shared constant/authority pattern of (`def:nrz:tiles-streams-constant-key`), (`rule:nrz:tiles-streams-cache-tiers`). Its key includes the complete logical relation, physical occupation and required revisions; equal bytes, printed maps or shapes do not identify it. A reusable formal layout proof can be shared across different concrete placement nodes, while each application authenticates its own endpoint versions. A changed edge creates a new revision and invalidates its actual dependents; reuse never retains an unbounded history or makes a retired numerical owner live again. The precise interning and lifetime mechanism remains (`open:nrz:placement-types`).

**Rule (Question and engine responsibilities)** · `rule:nrz:placement-authority`

The question fixes original axes, selection, component reading, source dependence, companion requirements and demanded outputs. The engine chooses owners, physical ordering, feasible tile capacity, strides, materialization and spare capacity within that contract. Bindings checks every meaning relation, including overlapping readings; matrix checks actual placement and numerical lifetime. A native Cartesian product, common address, equality of values or host hint cannot supply a missing semantic edge. This preserves (`rule:vision:layer-enforcement`), (`rule:nrz:descriptor-binding-validation`), (`rule:nrz:tiles-streams-tile-choice`).

**Rule (Facts exposed to bindings and kernels)** · `rule:nrz:placement-visible-facts`

A binding may traverse authenticated selection, coverage and companion edges and rely on ordered selections, extent, precision, representation revisions, original correspondence and required companion targets. Its storage-neutral contract does not resolve pointers. A kernel may traverse only its admitted numerical placement and demand edges and rely on numerical shapes, safe access map, initialized demand, supported alignment and numerical law; it must never infer units, kinds, independent sources or exact membership from contiguity, addresses or padding. A low-level locator grants no meaning and a symbolic witness grants no storage lifetime (`rule:nrz:descriptor-binding-kernel-boundary`), (`rule:nrz:descriptor-binding-checked-overlap`).

**Rule (Placement authentication and revision)** · `rule:nrz:placement-versioning`

Authenticate the placement node and each traversed edge against owner scope, slot occupation/generation, physical epoch, value/companion versions and targets, layout/mask versions, selected original identities, declaration/read-map revisions and error/source scope together before capture. Keep the required owners pinned across use and publication; refuse stale or foreign substitutions before numerical loads. Physical relocation may preserve value identity while invalidating cached physical views; changed selection or reading requires new dependent attachments even when bytes agree. `loan/application/chain.rs` checks captured numerical-error scope against the member and origin, and `binding/live/write.rs` prepares the complete affected-reading invalidation closure. These are instances of (`rule:nrz:descriptor-binding-invalidation`), (`rule:nrz:matrix-loans-authentication`), (`rule:nrz:matrix-loans-error-scope`), (`[MATRIX-test:unit:loan-mapped-movement-capture-repair]`), not authority to identify versions by byte equality.

**Rule (Tiles and multileg cells)** · `rule:nrz:placement-cell-resolution`

Tile size controls residence and amortization without changing the question or a decision node's input demand. A cell's admitted legs and required companions remain a complete reading across physical owners; splitting them across storage cannot publish a partial cell. Adding resolution requires the real-demand and separate-design conditions of (`dec:nrz:matrix-core-multileg-cells`), with the additional components, masks, mappings and enclosure costs included. This concept admits no multileg implementation or alternative float format (`rule:nrz:matrix-loans-setters`), (`rule:nrz:lc-grid-size`).

**Rule (Vector access is a physical contract)** · `rule:nrz:placement-vectors`

A `std::simd` kernel's vector width is an execution property, not a new logical axis or permission to enlarge a question. Safe loads must be justified for their actual access type; neither the slab allocator's internal rounding nor a mask word's alignment proves a public vector alignment promise. A selected component map may need safe unaligned access, masked access or a separately admitted pack. Every conversion retains original identity and counts its bytes and Work. Which owner chooses alignment and vector-width padding remains (`open:nrz:placement-vector-owner`); this rule asserts no supported SIMD implementation or new target requirement (`rule:nrz:matrix-loans-slab-capacity`), (`rule:nrz:matrix-core-layouts`).

## Padding · `sec:nrz:placement-padding`

**Rule (Padding has an accountable owner)** · `rule:nrz:placement-padding-owner`

The allocation owner reserves all padding until release. Addressable mapped slabs are safely zero-filled over their full L entries; logical write flags are separate and zero-filled storage never supplies observation evidence. Backend capacity beyond L is reserved but never read or treated as initialized. Unmapped native cells remain unrequested, and unused mask bits remain clear. A filled mask and its complete companion closure govern readability, not the value of spare bytes (`rule:nrz:matrix-loans-slab-capacity`), (`rule:nrz:matrix-loans-setters`), (`rule:nrz:matrix-loans-clearing`), (`def:nrz:tiles-streams-mask-storage`).

**Rule (Padded lanes cannot contribute)** · `rule:nrz:placement-padding-exclusion`

Computing on padded lanes requires a separately admitted kernel contract proving safe initialized accesses and independence from every real output. Such a contract must exclude those results from values, masks, populations, extrema, statistics, reductions, numerical-error accumulation, content keys, digests, portable witnesses and raw exports, and from any domain guard that could affect real lanes. A zero spare value is insufficient for reciprocal, root or any other restricted law. No such permission follows from vector width: absent that proof, padded lanes are never evaluated or loaded. Dense scratch, enumeration, map composition and padded statistics refusals in (`obs:nrz:placement-native-padding`) are the existing boundary; a future SIMD tail contract cannot bypass it.

**Rule (No meaning in padding)** · `rule:nrz:placement-padding-evidence`

Padding cannot carry a source, a measured zero, a semantic count, an enclosure premise or branch membership. A mask tail bit must be zero even after complement or other word algebra; otherwise popcount and selection manufacture cells. A SIMD tail lane must likewise have no path to a result or evidence reduction. Padding must not reach content keys, digests, portable witnesses or raw exports; physical spare bytes cannot become portable value identity or evidence. Logical structural zeros remain real entries with original checks and are not padding. Total binding coverage of real float entries is retained under (`prin:nrz:descriptor-binding-total`); the precise representation of reserved nonentries in that coverage inventory remains (`open:nrz:placement-padding-coverage`), not permission to allocate unbound scratch.

**Assumption (Byte and traversal symbols)** · `assum:nrz:placement-cost-symbols`

Let C be logical destination cell capacity, k the components per cell in one channel, w the native scalar width in bytes, L the full addressable scalar length including gaps, and R the allocator's scalar capacity. Let q count equally shaped independently allocated channels only for the illustrative equal-channel formulas. Let S count selected original cells, which can be less than C. All products, ceilings, signed extents and sums use checked arithmetic; overflow refuses. Headers, capacity excess, maps, companions of other shapes and scratch are added by their actual owner inventories (`rule:nrz:matrix-loans-private-bytes`), (`rule:nrz:matrix-loans-byte-scope`).

**Calculation (Slab residence and initialization)** · `calc:nrz:placement-slab-bytes`

Under (`assum:nrz:placement-cost-symbols`) and the pinned constructor of (`rule:nrz:matrix-loans-slab-capacity`), set a = 64/w, then R = a ceil(L/a). The addressable payload is wL bytes; the additional reserved allocator tail is w(R − L); adding them gives wR. For q independent equal channels the payload reservation is qwR, not wCk and not q × w × S × k. A gap-free channel has L = Ck; adding g addressable gaps gives L = Ck + g before rounding. Addressable zero-fill costs qL scalar initialization steps, while the unread allocator tail contributes bytes without fictitious initialization Work. Empty L gives R = 0. For binary64 with C = 65, k = 1 and no gaps, L = 65, a = 8, R = 72: one channel reserves 576 payload bytes, of which 520 are addressable and 56 are inaccessible capacity. Three independent equal channels reserve 1728 payload bytes and initialize 195 scalars, before tracking, headers or scratch.

**Calculation (Masks, tracking and map storage)** · `calc:nrz:placement-mask-bytes`

Under (`assum:nrz:placement-cost-symbols`), divide C by 64 and round up to get W = ceil(C/64) words. Multiplying by the eight-byte word width gives 8W bytes per mask; the unused tail has 64W − C bits and must be clear. At C = 65 this is two words, sixteen bytes and 63 tail bits. A channel's component initialization needs ceil(Ck/64) words and its derived complete-cell map needs ceil(C/64) words; for q equal channels this is 8q(ceil(Ck/64) + ceil(C/64)) payload bytes before additional role masks. These initialization and complete-cell tracking words exist only during the loan lifetime and are destroyed at publication commit under (`rule:nrz:matrix-loans-publication`); they are not added to published residence. An S-entry explicit original-index map adds S times the native index width plus its owner/capacity costs; native product projection can avoid that entry-sized map. These follow (`rule:nrz:matrix-loans-dense-host-layout`), (`def:nrz:tiles-streams-mask-storage`), (`def:nrz:matrix-loans-owned-product-reader`).

**Rule (Padding in costs)** · `rule:nrz:placement-padding-costs`

Reserve padding bytes whether used, cleared or inaccessible, and include simultaneous old-plus-new owners during movement. Charge actual initialized scalars, visited words, map checks and admitted padded-lane arithmetic; do not charge inaccessible allocator bytes as arithmetic or discount scanned tail words as empty. Report logical useful selections, padded capacity, residence and traffic separately. Full-word mask traffic tends to a bit per cell but small tiles pay the ceiling in (`calc:nrz:placement-mask-bytes`); a claimed SIMD saving must include tails, packing and exclusion work. These terms belong to the existing mask, output and validation components, without double counting shared owners or inventing measured throughput (`def:nrz:lc-overhead-mask`), (`def:nrz:lc-overhead-output`), (`def:nrz:lc-overhead-validation`), (`rule:nrz:lc-overhead-composition`).

## Spread and collect at decision nodes · `sec:nrz:placement-collection`

**Principle (Spread without collection)** · `prin:nrz:placement-spread-collect`

Spreading is fan-out in the computational graph. It reads buffers that already exist with authenticated present inputs and writes independent outputs. Broadcast, independent cell evaluation, tile evaluation, component fan-out, packing copies and scatter stores distribute work and preserve original identities. Nothing remains to be awaited or chosen by that fan-out edge, so it creates no waiting state and needs no decision node. An unavailable required input prevents ordinary execution of that edge. The graph criterion for collection is convergence of contribution or completion edges into a shared result, coverage, aggregate or release scope whose completion or admitted partial outcome accounts for those contributions together. Merely reading several existing operands for an independent cell output, as in a binary elementwise application, does not meet that criterion. Combining cells into a reduction, joining coverage for publication or awaiting releases for reclamation does. Collection must account for independently returning contributions and can wait for them; a synchronous join is the same graph scope with all contributions already arrived. This waiting and accounting makes the collecting node a decision node under the proposed principle. Gathering, reduction, error and Work accumulation, compaction and publication therefore converge only at decision nodes. A fan-in that collects anywhere else is a conflict, even if no buffer is copied. The barrier is the existing (`def:nrz:decision-node`), with graph-level demand under (`def:nrz:lc-grid-barrier`); there is no second kind of barrier. Existing operations that collect without such a node are conflicts for the placement design, not implicit new barriers or already implemented instances of this principle.

**Principle (Waiting makes collection a decision)** · `prin:nrz:placement-waiting-decision`

Collection under (`prin:nrz:placement-spread-collect`) accounts for independently returning tiles, cells, refinements, stream samples or completion obligations. Its converging edges distinguish returned, pending and terminally absent contributions and carry their versions, coverage, companions and evidence. The decision node owns this arrival set and the policy for choosing a partial collection on flush; extending the current certified semantic definition to every such scope remains (`open:nrz:placement-collection-model`). Graph-walk readiness under (`def:nrz:tiles-streams-readiness`) is all-or-terminal gating on required producer edges, not this collection arrival set or a choice over it. Every node still has the ordinary/flushed interface of (`def:nrz:tiles-streams-node-flush`). For a spreading node, the cells in D∖A whose input is missing deterministically become `MissingInput` (`rule:nrz:matrix-loans-masked-law`); this mapping makes no choice, and only valid corresponding cells are produced under (`rule:nrz:tiles-streams-flush-native`). The `Pending` cells of a suspended application, and the choice to finalize them, are the masked-application conflict in (`arg:nrz:placement-collection-conflicts`). Publication of its partial output mask collects and remains the ordinary-publication conflict; a contraction run under flush remains the kernel-contraction conflict in (`arg:nrz:placement-collection-conflicts`). These interfaces do not introduce a second barrier kind or remove existing flush obligations.

**Rule (Dependencies define the collection)** · `rule:nrz:placement-collection-demand`

The decision node owns the waiting state, authenticated arrival set and flush policy for its collecting fan-in edges. Its accounting distinguishes returned inputs from pending producers and terminal absence, and its policy determines the choice when flush arrives before all inputs return. The collecting edges must name the node's ordered input-demand edges, exact question/partition, source and companion scope, required producer completions, missing-input policy, cumulative allowances and permitted outputs. It may depend on part of a tile or several tiles. Finishing a storage pass, acquiring a buffer or closing a window does not satisfy absent dependencies. The actual frozen versions, coverage and reading maps authenticate what is collected under (`def:nrz:tiles-streams-barrier-interface`), (`rule:nrz:tiles-streams-barrier-evaluation`), (`def:nrz:decision-evidence`). Pure storage availability and guard checks do not become certified semantic selections by being called decisions (`rule:nrz:decision-crossing-authority`).

**Requirement (End of a tile pass)** · `req:nrz:placement-pass-collection`

Per-cell outputs and their required numerical companions spread through an admitted heap pass (`rule:nrz:lc-grid-heap-pass`). An end-of-pass gather, population, norm, error total, Work total or publication collects. It reaches a decision node only when it is part of that node's declared input preparation and collection scope; tile completion alone supplies no decision. The application evaluator's per-cell error formation and ordinary result publication are not evidence that every pass already has such a node. Their integration is the error/publication conflict in (`open:nrz:placement-collection-model`), (`open:nrz:placement-error-work`).

**Observation (The decision node itself)** · `obs:nrz:placement-decision-collection`

A decision node already collects authenticated enclosure inputs, their exact reading and source context, and enclosure/cut evidence to publish a decided or undecided outcome and authorize later strata. It may collect a sub-tile mask or a multi-tile quantified question, paying for every required input and distinct proof premise. Cache reuse does not erase current membership checks. This is the existing semantic instance of the principle (`def:nrz:decision-node`), (`def:nrz:lc-grid-barrier`), (`rule:nrz:tiles-streams-barrier-cache`), (`rule:nrz:lattice-boundary-selection`). It does not yet specify arbitrary storage collection or reduction-only outcomes.

**Requirement (Refinement)** · `req:nrz:placement-refinement-collection`

The selecting decision collects unresolved outcomes and their remaining obligations, then spreads work into its permitted refinement subgraph. The next collection belongs to a decision node over that subgraph's actual dependencies, not automatically to every child allocation or split. The same target/source family, inclusion/cover evidence and cumulative allowances survive; a later result cannot justify its own input lowering (`rule:nrz:lc-grid-split`), (`rule:nrz:lc-grid-stop`), (`rule:nrz:decision-refinement`), (`rule:nrz:decision-stratification`). Ordinary numerical tightening that has no such collection remains an input computation; its internal accumulations retain the conflict in (`open:nrz:placement-error-work`).

**Observation (Publication)** · `obs:nrz:placement-publication-collection`

Publication collects complete versions, companions, masks, evidence and ownership into an observable group. Decision publication is already tied to the node and its selected continuation under (`rule:nrz:tiles-streams-barrier-publication`). General loan handback and ordinary numerical result publication use their own atomic transactions under (`rule:nrz:matrix-loans-publication`), (`alg:nrz:matrix-core-publish`); their code does not require a semantic decision node. Their readiness and no-fail commit rules remain binding, while their placement under the collection principle is an explicit conflict. Calling an atomic commit a new barrier would not resolve it (`open:nrz:placement-collection-model`).

**Requirement (Host interface)** · `req:nrz:placement-host-collection`

Host setters spread writes into tracked cells. Handback's coverage closure and publication, and host export of a gathered result, collect. A returned input may feed a subsequent declared decision once its full publication and demand are ready, but that later consumer does not retrospectively turn the handback transaction into a decision node. Result delivery after a decision carries its existing scoped evidence; raw export alone grants none. The host-interface conflict is how such collection belongs to a node while preserving repairable loans, absence and delivery obligations (`rule:nrz:tiles-streams-host-loan`), (`alg:nrz:matrix-loans-filled-closure`), (`rule:nrz:lc-stream-retirement`), (`open:nrz:placement-collection-model`).

**Requirement (Stream windows)** · `req:nrz:placement-window-collection`

A window is a versioned subdomain, not a storage frontier or new source. Selecting its incidence alone need not reduce values; a window aggregate or decision collects at the node whose demand names those inputs and missing-input semantics. Crossing a tile boundary does not close it. Flush changes expectation and node-specific readiness without manufacturing upstream results; historical inference requires retained evidence or a proved sufficient summary. Any summary formed outside a decision node is a collection conflict, not a distinct window barrier (`def:nrz:lc-stream-window`), (`rule:nrz:lc-stream-decision-scope`), (`def:nrz:tiles-streams-node-flush`), (`rule:nrz:lc-stream-flush`).

**Rule (Flush forces a choice over the arrival set)** · `rule:nrz:placement-flush-choice`

A host flush may reach a collecting decision node before every input is ready. The flushed demand predicate requires waiting, with no engine deadline, while an admitted mandatory producer or outstanding loan is pending, until it publishes or supplies an admissible terminal outcome (`rule:nrz:tiles-streams-flush-partial`); for an outstanding loan or detached application only successful handback or publication, cancellation, or abandonment reconciliation supplies it (`rule:nrz:tiles-streams-flush-native`), (`rule:nrz:matrix-loans-abandonment`). Once that precondition is satisfied, its declared policy chooses among an admitted partial result with authenticated arrived coverage, permitted finite refinement and refusal of the requested result. Partial publication remains a real choice: the policy may end permitted refinement while allowance remains, without exhausting it first; publication still follows the end of permitted refinement, including every activated refinement continuation, and the original reader pins release only after all continuations finish (`rule:nrz:tiles-streams-flush-local`). Split the remainder into terminal-absent cells carrying the declared missing-input outcome and arrived-but-unresolved cells carrying `Undecided`. Record the host request and its motivation, scope/generation, policy revision, arrival set in declared demand order rather than completion order, outstanding/absent edges, retained input versions, selected action and remaining allowances (`rule:nrz:placement-reduction-order`), (`conv:nrz:batch-order-and-replay`). A partial result never treats missing cells as present or zero, and an undecided remainder asserts no complement membership. A published selection is `Decided` only with its required proof; arrived but unavailable proof uses only an applicable closed `Undecided` reason, while malformed references, unsupported contracts and invalid evidence retain typed refusal under (`def:nrz:decision-outcomes`). The missing-input outcome is not a new undecided reason; both that contract gap and a policy stop with refinement allowance remaining are recorded in (`open:nrz:placement-flush-policy`). Flush closes expectation edges for future contributions under (`def:nrz:tiles-streams-flush-scope`). A wait after flush covers only mandatory producers already admitted, including outstanding loans, not new expected inputs. Permitted finite refinement continuations inherit that flush generation while draining. Waiting and refinement are continuing graph state, not false final `Decided` results. A result-producing collection runs only when its ordinary or flushed demand predicate permits it; notification cannot bypass an admitted mandatory producer. The choice obeys (`def:nrz:tiles-streams-node-flush`), (`rule:nrz:tiles-streams-flush-local`) and the finite depth, attempt, byte and cumulative Work bounds of (`rule:nrz:lc-grid-stop`).

**Requirement (Deadline-motivated host flush)** · `req:nrz:placement-flush-deadline`

A deadline may motivate an external host flush request on a declared graph scope; it does not introduce an engine deadline scheduler. The node records the request and actual arrival set, then, after already admitted mandatory producers settle under (`rule:nrz:placement-flush-choice`), may publish an allowed partial result with terminal absence separated from arrived-but-unresolved outcomes, refuse, or drain permitted finite refinement. Until then, required producers and exclusive loans still pending remain outstanding; flush does not close them. Deadline expiry proves neither absence nor a mathematical outcome (`def:nrz:tiles-streams-flush-scope`), (`rule:nrz:tiles-streams-flush-native`). A request to keep expectation edges open for future contributions is not a flush under the current contract; alternative trigger authority belongs only in (`open:nrz:placement-flush-policy`).

**Requirement (Host-requested full or partial flush)** · `req:nrz:placement-flush-host`

A host request names the evaluation or owned subgraph closure. Partial publication with separate terminal-absent and arrived-but-unresolved coverage, refusal, or permitted finite refinement uses that node's output contract and actual returned inputs under (`rule:nrz:placement-flush-choice`). Evidence records the flush generation, owned expectation edges, external pending producers, outstanding loans and delivery obligations, and which shared regions remain pinned. A partial flush cannot close another consumer's expectation edges or claim an empty heap. Full completion additionally requires all scoped work, required delivery and release; requesting it alone is not completion (`rule:nrz:tiles-streams-flush-partial`), (`rule:nrz:tiles-streams-flush-completion`). The existing host flow remains (`rule:nrz:lc-stream-host-flow`).

**Requirement (Window-motivated host flush)** · `req:nrz:placement-flush-window`

Window state may motivate the host to request flush on the decision subgraph for a declared domain version; the window itself is not a second barrier or an automatic frontier. Evidence records the boundary/inclusion rule, uncertain membership, source/clock versions and arrived versus missing coverage. An observed-domain result may publish its actual subdomain; a fixed-domain universal result needs complete coverage or a valid counterexample for its negative, and an existential result needs a valid witness or complete exclusion for its negative. The flushed demand predicate first requires the producer and loan wait under (`rule:nrz:placement-flush-choice`). After that precondition, carry terminal-absent cells as the declared missing-input outcome and arrived-but-unresolved cells as scoped `Undecided`, or choose permitted finite refinement or refusal under (`rule:nrz:placement-flush-choice`), without changing quantifiers. A partial observed result is a separate declared output, not a whole-window theorem (`def:nrz:lc-stream-window`), (`rule:nrz:tiles-streams-flush-quantified`).

**Requirement (Budget-motivated host flush)** · `req:nrz:placement-flush-budget`

Budget state may motivate the host to request flush before all inputs or refinements return; the engine does not trigger it under the current host-owned flow (`rule:nrz:lc-stream-host-flow`), (`rule:nrz:tiles-streams-walk-capacity`). The node records spent Work, retained byte reservations, remaining depth/attempt/precision allowances, unfinished dependency edges and the reason further collection cannot proceed. It may publish the last valid arrived results, terminal absence with the declared missing-input outcome, and arrived-but-unresolved cells with `Undecided`, or refuse unavailable outputs. Waiting covers only already admitted mandatory producers; finite refinement may drain only within the remaining allowances and publication/cleanup requirements under (`rule:nrz:placement-flush-choice`). Exhausted cumulative Work never authorizes an extra uncharged pass or a refill, and no notification seizes a loan or reads unpublished bytes. `DecisionBudgetExhausted` and `RefinementExhausted` retain their distinct evidence under (`def:nrz:decision-outcomes`), (`rule:nrz:lc-grid-stop`), (`rule:nrz:matrix-loans-cleanup-tariffs`). The placement design must explain how the forced choice itself is reserved and accounted (`open:nrz:placement-error-work`), (`open:nrz:placement-flush-policy`).

**Rule (Collection cost and carried evidence)** · `rule:nrz:placement-collection-cost`

Crossing a decision node pays actual dependency authentication, selected reads, map joins, reduction operations, temporary storage, mask scans, proof construction or reuse, attachment and publication costs. Keep original identities, ordered membership, source correlations, value/companion versions, reading and arithmetic revisions, completed/refused coverage and spent-attempt receipts. A move preserves existing error scope; it cannot replace inherited error by zero or fabricate independence. Cache hits still pay lookup and attachment. No constant-time or constant-Work claim follows from grouping many inputs at one node (`rule:nrz:matrix-loans-error-scope`), (`rule:nrz:tiles-streams-cache-charge`), (`rule:nrz:plan-cumulative-allowances`), (`rule:nrz:lc-overhead-scopes`).

**Principle (Error and Work collect at decisions)** · `prin:nrz:placement-error-work`

Tracked error and Work accumulate at decision nodes under (`prin:nrz:placement-spread-collect`). Their collection retains each contribution's identity and scope once, including failed attempts, without counting a numerical-error term again when the total radius already covers it. This is a placement objective, not permission to delay safety checks or discard existing local enclosure evidence. Existing kernel error composition and immediate/prepaid budget debits remain required by (`rule:nrz:descriptor-binding-error-composition`), (`thm:nrz:descriptor-binding-kernel-enclosure`), (`rule:nrz:matrix-loans-ledger`). Their internal accumulations are real conflicts for (`open:nrz:placement-error-work`); relabelling them as noncollection would conceal the design work.

**Rule (Stable reduction order and reproducibility)** · `rule:nrz:placement-reduction-order`

A reduction at a decision node uses the declared stable input order and validated arithmetic, keyed by original identities rather than physical position, allocation order or completion timing. The exact law, error coverage and arithmetic environment still determine its assurance; stable order does not promise identical floating bits across machines. Moving or compacting data must preserve that order or retain an explicitly admitted ordered map. These are the requirements of (`conv:nrz:batch-order-and-replay`), (`dec:vision:reductions-and-residuals`), (`prin:nrz:descriptor-binding-reproducibility`). Internal matrix contractions already reduce inside kernels; moving their collection responsibility to decision nodes remains part of (`open:nrz:placement-collection-model`), not a silent change to their laws.

**Argument (Bounded collection overhead)** · `arg:nrz:placement-collection-overhead`

One collection per declared decision-node execution avoids repeatedly gathering and publishing after each cell. With N inputs feeding D such executions, a fixed collection setup cost b contributes Db rather than Nb when each input feeds exactly one execution, D < N and no additional per-cell node is required. This comparison assumes the same question and declared dependency scopes; overlapping demands, such as a per-reading question and a window aggregate over the same cells in (`def:nrz:lc-stream-standing-question`), require counting each execution's actual incidence rather than claiming this saving; input visits, arithmetic, distinct proof premises, retries and child nodes still cost their actual work. Error contributions can travel with spread outputs until their declared collection without inventing one exact descriptor per lane. Deferral retains spread outputs, error contributions and arrival-set state until collection, and can raise peak residence relative to accumulating as results arrive. At each time t, add the retained-output, retained-contribution and arrival-state bytes not already counted to the other live owners, then take the maximum over t under (`rule:nrz:tiles-streams-residence`); shared owners are counted once. Setup savings do not remove that residence term. Tile capacity amortizes setup but cannot enlarge or shrink decision demand. No throughput ratio follows without the schedule and resource model of (`rule:nrz:lc-overhead-composition`); a genuinely per-cell decision graph has no asserted D-saving (`rule:nrz:lc-grid-fast-path`).

## What the existing arrangements become · `sec:nrz:placement-disposition`

**Convention (Disposition vocabulary)** · `conv:nrz:placement-disposition`

An instance already follows the placement or padding principle stated here; a special case needs a general account without changing its decided contract; a conflict needs an explicit later decision. A mechanism can have sound placement while its surrounding collection conflicts with (`prin:nrz:placement-spread-collect`). The inventory does not claim the proposed model is implemented.

**Argument (Storage and coverage dispositions)** · `arg:nrz:placement-storage-disposition`

Slabs and checked gaps are instances of owned, charged physical capacity, with separate legacy and loan ownership as special cases (`obs:nrz:placement-slabs`). Affine/interleaved/reversed components are special cases of the logical-to-physical relation, with differing injectivity proofs to generalize (`obs:nrz:placement-components`). Padded native maps and packed masks are instances of excluded nonentries, whose common coverage representation remains open (`obs:nrz:placement-native-padding`), (`obs:nrz:placement-masks`). Tiles/bundles and independently shaped companions are special cases of complete placement and target incidence, not permission to force every channel into one shared map (`obs:nrz:placement-tiles`), (`obs:nrz:placement-companions`). Their publication and error aggregation retain the collection conflicts below.

**Argument (Movement and sharing dispositions)** · `arg:nrz:placement-movement-disposition`

Scatter stores and whole-base component copies are spread instances, but replacement closure and publication are collection conflicts (`obs:nrz:placement-scatter`). Relocation preserves original identity and physical revision as a placement instance; its compaction/publication needs a decision-node account (`obs:nrz:placement-relocation`). Mask compaction and gather transport are identity-preserving special cases whose existing collection entry points lack a required decision node; packing copies spread while their publication/export collects (`obs:nrz:placement-compaction`), (`obs:nrz:placement-gather`). Broadcast and Cartesian factor projection are spread instances with retained dependence; general binary broadcast, factor incidence and differing tuple/component orders remain special cases to reconcile, without treating a native map as a numerical law (`obs:nrz:placement-broadcast`), (`obs:nrz:placement-cartesian`). Existing no-gather host admission remains unchanged while the design reconciles these representation boundaries.

**Argument (Collection conflicts remain explicit)** · `arg:nrz:placement-collection-conflicts`

Collecting fan-in under (`prin:nrz:placement-spread-collect`) occurs in standalone mask population/compaction and transport, packing publication/export, physical heap compaction commit, whole-base selected replacement closure, handback closure, ordinary publication, kernel contractions, local error propagation and immediate cumulative Work debit without a mandatory decision-node owner. Packing and scatter component copies themselves spread. Finalizing a suspended masked application's completed subset chooses among C, `CellRefused`, `CellUndecided` and `Pending` without a decision node (`rule:nrz:matrix-loans-masked-law`), (`rule:nrz:matrix-loans-application-outcomes`). Retirement/reclaim joins independent reader, pin and delivery releases with `RetirementWaiting(PinnedUses)`; full flush completion waits for these obligations (`alg:nrz:matrix-loans-retirement`), (`rule:nrz:tiles-streams-release`). Publishing a pointwise kernel's partial output mask and running a contraction under flush are the ordinary-publication and kernel-contraction conflicts, respectively (`rule:nrz:tiles-streams-flush-native`). These entry points lack mandatory decision-node ownership of their collection arrival set and choice policy, even where they already expose readiness, waiting or deterministic flush interfaces. Their current contracts are not refuted by this concept, and an eventual downstream decision does not itself account for those earlier collections. The current decision definition requires certified inputs and a declared semantic contract, so extending its collection role to ordinary storage operations is substantial design work, including the circularity of requiring input publication before a decision can read it (`def:nrz:decision-node`), (`def:nrz:tiles-streams-barrier-interface`). Resolve it explicitly through (`open:nrz:placement-collection-model`), (`open:nrz:placement-error-work`) rather than adding unnamed barriers or changing existing positions here.

## Open questions for the placement design · `sec:nrz:placement-open`

**Open Question (One placement type or related layer types)** · `open:nrz:placement-types`

Should one placement-node type cross the layers through authenticated edge adapters, or should bindings, matrix and kernel contracts use distinct related node types? Which edges may each kernel traverse, and how are placement-node identity, edge revisions and shared preparation authenticated and retained? Specify the checked graph edges and revisions that prevent drift between logical order, physical layout, original identity and companion incidence, without reversing matrix → bindings → CAS or exposing heap data to CAS (`rule:nrz:placement-authority`), (`rule:nrz:placement-versioning`).

**Open Question (Alignment and vector-width ownership)** · `open:nrz:placement-vector-owner`

Does a placement node own alignment and vector-tail padding edges for an admitted kernel family, or does a kernel request those edges through an authenticated physical contract? Specify safe access, restricted-domain tails, error exclusion, actual byte/Work accounting and layout conversion costs while preserving the absence of a public alignment promise in (`rule:nrz:matrix-loans-slab-capacity`) and the refusals in (`rule:nrz:placement-padding-exclusion`).

**Open Question (Host preference and placement choice)** · `open:nrz:placement-host-hint`

Which preference edges can a host attach to a placement request for layout or locality as well as capacity, and which engine-owned choice/evidence edges record the actual realization? Preserve the existing feasible-capacity, nearest-hint, smaller-tie and preferred-layout rules in (`rule:nrz:tiles-streams-tile-choice`) until a separately decided replacement exists. State which physical alternatives can satisfy a hint without changing original demand, error scope or the simultaneous resource peak (`rule:nrz:placement-authority`).

**Open Question (Collection on the decision node)** · `open:nrz:placement-collection-model`

How is collecting fan-in expressed on a decision node in the computational graph, what may that node collect, and what original identities, ordered dependencies, arrival states, error/Work contributions and authentication must each collecting edge carry? Reconcile the region-version/kernel-edge graph of (`def:nrz:descriptor-binding-computational-graph`) with the certified semantic node of (`def:nrz:decision-node`). Specify gathering, reductions, storage-only compaction, publication and host handback without a second barrier kind, forged semantic outcomes or a cycle requiring publication before the node that authorizes it. The design faces an explicit fork: widen (`def:nrz:decision-node`) to accept collection contracts with nonsemantic outcomes, risking a second barrier kind under the same name because the current node requires a partition contract and certified enclosures for each required coordinate; or require every collection to belong to an existing semantic node's declared input-preparation scope, confronting the complete-handback/publication-before-reads rule of (`def:nrz:tiles-streams-barrier-interface`) and its circularity. Neither option is decided here.
