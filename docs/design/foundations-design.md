## Scalar arithmetic · `sec:nrz:foundations-scalar`

**Definition (Finite scalar substrate)** · `def:nrz:foundations-scalar-contract`

`Scalar` is sealed to primitive `f32` and `f64`, with f64 the default parameter. `Precision` distinguishes Binary32 and Binary64. `Finite<P>` admits finite bit patterns and canonicalizes either signed zero to positive zero; the mathematical domain is real numbers, so zero sign is not evidence. `Enclosure<P>` owns ordered finite endpoints and means a closed set of represented real coordinates. `singleton` means represented exactness and has no affine-point meaning. Endpoints, negative radii, NaNs and infinities are checked before arithmetic. Exact discrete counts are not scalar implementations.

**Rule (Rounding environment and primitive proof)** · `rule:nrz:foundations-rounding`

The certified path requires the binary formats, round-to-nearest ties-to-even, gradual underflow, correctly rounded primitive addition/subtraction/multiplication/division/square root, nearest format conversion and explicitly requested fused multiply-add. It neither changes the floating environment nor permits fast-math reassociation, excess intermediate precision or flush-to-zero behavior. The initial supported target is the gate's `x86_64-unknown-linux-gnu`; its historical compiler/CPU observation is (`assum:nrz:gate-targets`), not evidence for an untested new build. Each production compiler/profile combination must pass the independent boundary corpus before admission. Debug and release are separate required checks. An environment declaration records target, arithmetic revision and these assumptions; a runtime probe can refuse an observed violation but cannot prove the process will never change its rounding environment. No unsafe floating-control inspection is introduced.

For a finite correctly rounded result `r = RN(z)`, the exact real result z lies between the adjacent finite values below and above r: the rounding cell is bounded by their midpoints, which lie inside those adjacent values. This argument also covers subnormal rounding and a result rounded to zero under gradual underflow. Therefore use `[next_down(r), next_up(r)]` unless an exact identity below applies. If r or a required outward neighbor is infinite, return `Overflow`; refusal at a finite extreme is permitted even when a tighter specialized proof could succeed. There is no fixed relative-error formula near underflow. NaN cannot enter through a successful constructor.

The initial exact shortcuts are only mathematical identities checked on finite operands: adding zero, subtracting equal represented operands, multiplying by zero or ±1, dividing by ±1 or dividing zero by a proved nonzero operand, and square root of zero or one. Negation and absolute value are exact sign operations. All other results use outward neighbors, even when a residual happens to round to zero. This removes the prototype's underflow-sensitive residual inference. A future error-free transformation needs its own proved domain and exact oracle tests before narrowing an enclosure (`ex:exemplars:error-free-transformations`). No performance or tightness improvement is claimed for this conservative replacement.

**Rule (Enclosure operations and evaluation order)** · `rule:nrz:foundations-enclosure-operations`

Addition and subtraction use their monotone endpoint formulas. Multiplication and division take the hull of all four endpoint combinations, with division refusing any denominator interval containing zero. Square treats a zero crossing explicitly and intersects its lower bound with zero. Square root requires a nonnegative lower endpoint, uses monotonicity and intersects its lower result with zero. Explicit fused multiply-add encloses each of the eight endpoint triples using one `mul_add`; a separately written multiply followed by add performs two rounded operations. The corner extrema follow because the fused real formula is affine in each operand with the others fixed. Do not silently fuse or unfuse either path.

`sum` and `dot` traverse increasing slice indices in a documented left fold; an empty reduction is exactly zero, unequal dot lengths refuse. Each intermediate is enclosed by the preceding rule, so induction gives inclusion of the exact represented-input reduction. A large intermediate can cause refusal even if another expression order would have a finite result. The Euclidean/Frobenius primitive finds the largest absolute entry, selects a finite positive power-of-two scale, encloses each division by that exact scale, squares, sums, takes square root and encloses multiplication back by the scale. The divisions are still enclosed: power-of-two scaling can lose subnormal information. This proves an upper norm bound without requiring direct squares to be finite. Zero input returns zero; a non-finite bound refuses. Scalar knows neither a matrix shape nor a physical norm.

**Rule (Precision conversion)** · `rule:nrz:foundations-precision-conversion`

Widening f32 to f64 is exact for every finite represented value because its significand and exponent range fit; widen both endpoints exactly and retain all existing components. Narrowing a finite f64 endpoint first rejects magnitude beyond f32's largest finite value, rounds once, then compares its exact f64 widening with the original: step the lower endpoint down only if it is greater, and the upper endpoint up only if it is smaller. This contains the source endpoint, including underflow to zero. Choose the new center by nearest conversion and compute its displacement bound outward; accuracy adds that displacement once to the computational ledger. Every component's upper bound narrows outward, not by a plain cast. A statistical parameter's numerical enclosure narrows independently of the value center. Overflow and an unmet requested budget refuse without altering the original value. Precision conversion changes representation identity, not dimension, kind, measure, source or role; it is a different operation from measure conversion (`rule:vision:precision-conversions`).

## Envelopes, assurance and provenance · `sec:nrz:foundations-accuracy`

**Definition (Assurance is scoped access)** · `def:nrz:foundations-assurance`

`ScalarValue<P>` owns a finite center, immutable companion ledger, coverage and provenance. Constructors are distinct: `represented` declares the modeled input to be exactly its binary coordinate; `declared_enclosure` records a caller-supplied deterministic input assumption and validates its numerical bounds; `probabilistic` records that a physical input has no deterministic enclosure; and the units exact-import constructor retains an exact rational target and a conversion bound. A declaration is an assumption about input coverage, not a measurement theorem. A checked units descriptor or a source string containing the word certified grants none of these constructors' computed guarantees.

`deterministic(DeclaredInputs)` returns a private-construction `DeterministicRef` only if all required input sources have deterministic coverage and every carried contribution has been composed by a supported operation. The default operation policy requests this scope. `deterministic(RepresentedInputs)` requires explicit selection and names the narrower nominal problem; it includes import, conversion and rounding error but excludes unbounded physical input variation. `statistical()` and `estimated()` have distinct accessors and return no deterministic token. Neither an assurance enum discriminant supplied by a caller nor deserialization can construct a computed enclosure witness. Read-only centers are available as diagnostics; extracting a raw center carries no guarantee and there is no mutable center borrow retaining its old companion. `DeterministicRef` promises its stated scalar enclosure, not a matrix solve theorem or physical model validity (`rule:vision:assurance-and-correlation`).

**Definition (Component ledger and coverage)** · `def:nrz:foundations-ledger`

A ledger entry records a stable component key, class, expression mode, numerical bound or parameter, target, source dependencies, assurance, coverage and provenance parent. Classes distinguish measurement, representation, conversion, arithmetic, verification and interaction; the latter five are computational contributions, while modelling/discretization claims are retained as separately covered or excluded assertions. Units supplies each entry's physical descriptor. Entries contributing to a deterministic total are nonnegative absolute difference bounds; relative bounds first use their checked reference. Statistical entries do not participate. Reports borrow this intrinsic ledger; they cannot append a missing propagation after publishing a value.

An aggregate radius is computed by an outward sum of contributing entries. Bounds remain conservative with shared sources because triangle inequalities do not assume independence. Equal source keys do not authorize cancellation or deduplication of two contributions. The provenance DAG may share parent records, while the arithmetic ledger retains each term's multiplicity. A numerical error in a covariance parameter is a bound on that parameter's evaluation, not a physical radius on either covariance target. Unknown or unsupported input coverage makes the requested total unavailable, even if a separately scoped computational bound exists.

**Rule (Deterministic scalar closure)** · `rule:nrz:foundations-deterministic-closure`

Write represented centers a and b, component radii r_ai and r_bj, and outward totals R_a and R_b. First obtain a finite candidate c by the specified primitive operation. Let rho bound the distance from c to an enclosure of the exact operation on represented centers; compute rho with outward subtraction and magnitude, never an unchecked subtraction. Addition/subtraction propagates each input radius unchanged and adds rho. Multiplication propagates `abs(b) r_ai` and `abs(a) r_bj`, adds each `r_ai r_bj` as an interaction contribution, and adds rho. Expanding `(a + δa)(b + δb) − ab` proves the bound, including measurement/computational and cross-source interactions. Component compression may replace the cross-pair list by one upper bound with the union of all contributing keys; it cannot omit that union or claim an independent attribution.

For division write B = abs(b), D = B − R_b in exact real arithmetic and require a computed lower bound d ≤ D with d > 0; this is a numerical test independent of a declared nonzero symbol. The exact perturbation identity gives `abs((a+δa)/(b+δb) − a/b) ≤ R_a/D + abs(a) R_b/(B D)`. The identity `1/D = 1/B + R_b/(B D)` splits this into linear and interaction terms. Preserve source contributions using the linear terms `r_ai/B` and `abs(a) r_bj/B²`; bound the remaining interactions by `R_a R_b/(B d) + abs(a) R_b²/(B² d)`, and add rho. Replacing D by its positive lower bound d only increases these interaction bounds. Every coefficient and denominator bound is evaluated with enclosures in the safe direction; a denominator that cannot be proved positive refuses.

For square root require the entire admitted interval nonnegative. With a > 0 and a valid lower bound l on `a − R_a`, use `K ≥ 1/(sqrt(a) + sqrt(max(0,l)))`; then `abs(sqrt(a+δ) − sqrt(a)) ≤ K abs(δ)` by rationalizing the difference. Propagate each radius as `K r_ai` and add the center's root-rounding rho. Obtain a positive lower bound on the denominator before dividing; inability to do so is a refusal. For a = 0 the admitted symmetric ball must have R_a = 0, and sqrt is exactly zero. Integer powers use a documented repeated-multiplication order under an operation limit, with negative powers requiring a separated-zero reciprocal. Exponent zero returns one only when the input enclosure excludes zero; the indeterminate zero-to-zero case refuses with UnsupportedPower. Other rational powers remain descriptor-checkable but numerically unsupported. Square uses the bound 2 abs(a) R_a + R_a² plus rho. For fused a b + t, use abs(b) R_a + abs(a) R_b + R_a R_b + R_t plus the fused center rho, preserving each component and product as above. Fusion does not remove perturbation terms.

These formulas describe one safe implementation, not a first-order uncertainty approximation. The default accepts conservative overcounting; a future tighter bound must retain the same coverage and independent oracle obligations. All inputs remain immutable on refusal. Producing a valid bound and meeting a budget are separate outcomes.

**Rule (Budgets and compact provenance)** · `rule:nrz:foundations-budgets-provenance`

`AccuracyBudget<P>` contains a nonnegative absolute tolerance, nonnegative relative ratio and positive explicit reference scale; units verifies their difference descriptors. Accept only when the upper radius is at most a lower enclosure endpoint of `absolute + relative × reference`, or when an exact comparison establishes the inequality. Never round the allowed tolerance upward for acceptance. An enclosure crossing the budget boundary is `BudgetUnresolved`, not success; a proved violation is `BudgetExceeded`. With no budget return `NotRequested`, never `Met`. A point uses a difference reference; a count uses an explicit count-error/reference contract. The policy records covered scope and unsupported uncertainty handling; there is no silent fallback from deterministic to estimated assurance (`dec:vision:accuracy-policy`), (`rule:vision:local-and-observable-budgets`).

`ProvenanceStore` owns immutable records for imports, exact definitions, operations, conversions, source assertions and coverage. Values keep scoped `ProvenanceId` references, not copied expression histories. Each record contains operation revision, ordered parent IDs, input/output representation identities and any exact map identity. Sharing does not merge value or source identity. Limits cover records, parent edges and retained descriptive bytes; exhaustion returns `ProvenanceLimit` before publishing a result. IDs and versions refuse exhaustion rather than wrap. Dropping a store cannot leave a usable dangling ID: values retain shared ownership or borrow it. Stable export, global content-addressed IDs and replay serialization are outside this bite; Debug strings and process addresses are never persistence keys. The actual arithmetic/profile contract is referenced by provenance, with no live clocks in generated documentation.

## Quantities and exact conversion · `sec:nrz:foundations-quantities`

**Definition (Descriptor-backed numerical quantity)** · `def:nrz:foundations-quantity`

`Quantity<P, R>` owns a coherent `Descriptor`, finite numerical center, complete intrinsic companion set, immutable value identity and provenance. R is DynamicRole, Point or Difference; fixed-role lifts inspect the descriptor and fail if it disagrees. Types carry precision and fixed roles, not seven physical exponents. A dynamic operation first checks descriptor meaning; a fixed-role method additionally restricts its Rust inputs/outputs. Quantity constructors reject count descriptors and unbound uncertainty kinds. `Count` is a separate exact representation. `PresentedQuantity<P, R>` is an immutable converted view with the requested display measure and its own conversion envelope; only coherent `Quantity` enters ordinary numerical arithmetic. Converting a presentation back is an explicit checked import, never a relabelled center.

Native elementary methods use the existing Registry rules before numerical evaluation, including ordered kind rules and count-literal special cases where applicable. A composite expression arrives as CAS original occurrences and takes the full data-time path below. No quantity operation executes an unchecked normal form, automatically inserts a missing kind rule, or treats zero as a wildcard descriptor. Source measures/origins remain provenance even though the stored descriptor is coherent (`rule:vision:canonical-quantities-and-affine-coordinates`).

**Procedure (Exact rational to binary import)** · `alg:nrz:foundations-exact-import`

Use `nrz-cas::Rational` for exact literals, scales, shifts, dimension exponents and count centers. For a finite binary number decode its sign, integer significand and binary exponent from bits, then build the exact rational significand times a power of two through the existing budgeted constructors and arithmetic. For a nonnegative rational target q, compare it exactly with the largest finite value, then binary-search the monotonically ordered nonnegative finite bit patterns for adjacent representable brackets L ≤ q ≤ U. Equality gives a singleton; otherwise compare q with the exact rational midpoint to choose the nearest center, breaking a tie by the low significand bit. Negative targets reflect the positive bracket and zero canonicalizes. At most 64 bracket iterations suffice for either format; the endpoint, equality and tie comparisons also consume the same explicit ledger. No conversion passes through f64 when the requested result is f32.

The conversion proof is the exact bracket comparison, not the parser's floating result or a decimal round trip. Convert the exact distance between q and the chosen center to an upper binary bound with the same bracket routine. If that bound, either endpoint or the center cannot be finite, refuse. The exact dyadic decoding covers exponents down to −1074 and significands of at most 53 bits for f64; these follow from its format fields. The CAS default component/intermediate limits of 4096/8192 bits can represent such individual dyadics, but do not promise that an arbitrary later conversion fits. Work, intermediate and component exhaustion remain normal refusals, with no float fallback. Existing `Rational::from_ratio`, `pow`, `compare`, `add`, `sub`, `mul`, `div` and `parse` suffice; no CAS representation change or numerator getter is required.

Each public import/conversion owns one numerical-operation budget passed through all exact work and component conversions; do not reset a default ledger at each comparison. Existing descriptor admission/checking retains its separate current per-check budgets. The new units adapter uses budgeted Rational operations directly instead of assuming the convenience `Conversion::apply` supplies a cumulative numerical-import budget. The first implementation uses documented defaults and boundary tests, records actual work, and permits explicit caller limits; a larger supported workload requires an explicit limit rather than an unmetered path.

**Rule (Measure conversion and error accounting)** · `rule:nrz:foundations-measure-conversion`

For compatible descriptors, retain the exact existing recipe `q′ = a q + b`, with `a = s_U/s_V > 0` and point shift `b = (o_U−o_V)/s_V`; b is zero for differences. Exact rational imports apply this map before the single final binary import. For an existing binary center c, decode c exactly, form `a c + b` in CAS rational arithmetic, then enclose that exact target around a newly rounded center c′. The discrepancy is one new computational conversion component. Each deterministic component radius transforms by a times its old radius, rounded upward through exact rational import. Thus `abs(q′−c′) ≤ a abs(q−c) + abs(a c+b−c′)` proves the total. Bound-rounding excess is already contained in the rounded-up component and is not added a second time as physical input variation.

A general numerical arithmetic operation uses floating enclosures; descriptor definitions and these cold conversion boundaries use CAS exact arithmetic. No exact rational is reconstructed from a float's printed decimal string. Supported measure constants are exact rationals only, following the current `UnsupportedMeasureScale` boundary; an irrational/symbolic or uncertain calibration scale is not silently approximated into a measure. Quantity multiplication by an uncertain gain is a different operation with its own input and interaction components. Precision and measure conversions have separate records and errors even if requested together.

**Rule (Points, differences and origins)** · `rule:nrz:foundations-affine-roles`

Support point minus point to difference; point plus/minus difference to point; difference plus point to point; and compatible difference arithmetic. Refuse point plus point, difference minus point, ordinary point negation, products, quotients, powers and norms. Removing an origin requires an explicit compatible point identity and produces a difference; restoration uses that same checked origin. A canonical zero-offset point remains a point. A midpoint is expressed as `a + (b−a)/2` and checked in that form; there is no new arbitrary weighted-point-sum constructor. An absolute-zero physical reference must be explicitly declared when a law needs multiplicative absolute temperature. Offsets enter center coordinates only, never uncertainty radii, standard uncertainties, variances, covariance or relative reference scales.

**Rule (Exact discrete count storage and operations)** · `rule:nrz:foundations-counts`

`Count<P = f64>` stores a denominator-one CAS Rational, its checked count descriptor/domain and its own companion set. P specifies only the numerical precision of the continuous companions; the center remains exact regardless of P. Its center never stores a float, including for integers smaller than a floating significand limit. Construction checks integral value and domain. Add/subtract/negate and exact integer scaling use Registry closure rules, budgeted exact arithmetic and a final domain check. Signed and nonnegative domain behavior remains the current rule; bounded domains continue to refuse unproved whole-domain closure even if one proposed result happens to fit. A new concrete-value closure capability would require separate original-expression evidence and is not introduced here.

`Count<P>::count_ratio` is explicit, checks compatible counted kind/domain and a denominator separated from zero over admitted deterministic inputs, then returns a continuous ratio quantity with rational-center conversion error and propagated uncertainty. Ordinary count division, a fractional count result, floating count import, count-to-angle/mole conversion and metadata-to-count coercion refuse. A count's admissible deterministic set is the intersection of its declared integer domain with its enclosure; a non-integer radius need not be rounded into an integer. Its standard uncertainty may be 1/2, while a mean or expectation needs a separately declared continuous kind. Exact-center arithmetic produces no representation error; uncertainty does not make that center a fractional count. Statistical propagation through count operations is limited to the exact unary transforms listed below. Count add/subtract sums deterministic radii outward; integer scaling multiplies them by the exact absolute coefficient before upper import. Count-ratio closure applies the division proof to exact rational centers and dyadic component bounds, evaluates its coefficients and interactions with budgeted Rational arithmetic, then imports each upper bound and the exact quotient center. It never approximates a large count center merely to calculate its derivative coefficient; an unrepresentable result or exhausted budget refuses.

## Intrinsic uncertainty companions · `sec:nrz:foundations-companions`

**Definition (Independent component meaning)** · `def:nrz:foundations-component-descriptors`

`CompanionSet<P>` is intrinsic to its immutable value. Each `Component<P>` has a checked component descriptor, measurement/computational class, mode, actual target identity/version and logical selection, optional second target, optional reference, source declaration/version, assurance and provenance. Use the existing `uncertainty` constructor for Radius, Standard, RelativeRadius, RelativeStandard, Variance and Covariance. Absolute radius and standard uncertainty use the value's difference dimension/scale but distinct kinds; variance doubles its dimension and squares its scale; covariance adds both dimensions and multiplies both difference scales. Relative modes have zero dimension, coherent ratio measure and their distinct uncertainty kind. These constructors retain the current relative-identity and nonzero-reference checks; sharing a Descriptor never shares a target.

A `ParameterEnclosure<P>` encloses the declared mathematical magnitude of a statistical component, not all outcomes of the random value. Its computational evaluation radius has the parameter's own dimension and difference measure and the distinct `EvaluationRadiusOf` kind targeting that component key. Implement this as a private-construction `EvaluationErrorDescriptor` wrapping the checked parameter descriptor, rather than manufacturing a generally usable nested relative `Kind`. Its only operations are parameter conversion and enclosure reporting; it cannot enter ordinary quantity algebra or the scalar original-expression checker. This keeps the current ban on nested relative kinds while representing numerical error in a relative parameter honestly. Exact rational parameter storage is also admitted; its floating presentation uses this same checked enclosure boundary.

All constructors check target arity, nonnegative radii/standard uncertainties/variances, finite parameter enclosures and descriptor compatibility. Covariance coordinates may be negative. Source assertions about a distribution, covariance or independence remain assertions; passing these checks proves neither statistical validity nor positive semidefiniteness. A negative lower endpoint in a declared nonnegative parameter enclosure refuses unless an independent exact definition establishes the nonnegative domain and permits a checked intersection. Counts' components are continuous uncertainty quantities with no CountDomain; points' components have Difference role and zero offset (`def:vision:intrinsic-uncertainty-companions`).

For the statistical unary case, a and b are exact rational mathematical quantities with source-free exact-definition evidence, not merely floating values whose error happened to round to zero. Their numerical representation error is computational. The explicit affine_statistical operation requests this statistical contract and still cannot produce DeclaredInputs deterministic access unless separate deterministic coverage exists. `Var(aX+b) = a² Var(X)` and `Cov(aX+b,cY+d) = ac Cov(X,Y)` follow by subtracting the transformed expectations; finite second moments suffice. A negative a reverses covariance sign while standard uncertainty scales by abs(a). Compatible addition of a known exact offset, multiplication/division by a known exact coefficient and negation are admitted through this explicit unary path. An operation carrying any unsupported component refuses atomically, even if another component could be propagated. The caller may explicitly select the nominal represented-input problem, but the result must retain excluded physical/statistical coverage and cannot masquerade as the original fully covered value.

A continuous standard uncertainty on a Count may pass through exact integer scaling or a declared exact count translation only when the existing count-domain operation admits it. Combining two random counts and count-ratio statistics are unsupported. This never changes the discrete center or invents a continuous expectation. For points, the unary map must be an admitted coordinate/origin map or point-with-exact-difference translation; ordinary point multiplication remains forbidden despite the statistical affine formula.

**Rule (Covariance conversion transaction)** · `rule:nrz:foundations-covariance-conversion`

`CovarianceDescriptor` names ordered left/right target entries and versions, independent extents N and P, component descriptors, source declarations and coordinate maps. Construct every entry with the paired product rule, never the operator quotient rule. For diagonal conversions `x′_i = a_i x_i + b_i` and `y′_j = c_j y_j + d_j`, compute `U′_ij = a_i c_j U_ij`; evaluate the parameter interval conservatively and derive its own evaluation-error descriptor. If a source covariance is stored exactly, the transformed exact rational can remain exact until presentation. Neither offsets nor center conversion error are random covariance terms; numerical error has its separate ledger.

A conversion with cross-value companions receives an explicit map for every transformed target and a retained identity map for every unchanged target. Prepare new values, maps and all affected companions, then return one immutable converted bundle only after every check succeeds. It may refer to an unchanged external value by its validated identity/version; it does not mutate that value. Missing coverage or an inconsistent map refuses the whole bundle. Old bundles remain valid under their old identities. A single-value convenience method is available only when all its companions can be transformed without an unresolved external target. This contract prevents a converted center from retaining a covariance tied to its previous representation.

**Example (Conversion and interaction oracles)** · `ex:nrz:foundations-conversions`

The following are exact mathematical expectations, recomputed with independent rational arithmetic during this design round. They are not observations of an implemented quantity API. Every implementation test decodes returned binary endpoints into rational numbers before comparing them with these targets; toleranced decimal comparison is insufficient.

|--------------|------------------------|--------------------------------------|
|125 cm, deterministic radius 2 cm|5/4 m, radius 1/50 m|The center is exactly binary; the non-dyadic radius rounds upward.|

For the Celsius example, applying the inverse exact map to the stored kelvin center gives `879609302220799/43980465111040 °C`, before its next rounding. It differs from 20 °C by the carried kelvin representation error. The round trip is therefore checked by enclosure of 20, not by asserting equal center bits. In general, forward error e and backward rounding error f give a round-trip radius at least `e/a + f`; existing measurement bounds also return with their original physical scale. Exact dyadic cases may be identical, but the contract promises containment.

For multiplication, centers 2 and 3 with radii 1/10 and 1/5 give `3/10 + 2/5 + 1/50 = 18/25` before arithmetic rounding. These rational cases test both source attribution and the total enclosure independently.

## Matrix-facing descriptors · `sec:nrz:foundations-shapes`

**Definition (Checked operator schemas)** · `def:nrz:foundations-operator-schema`

Units owns layout-free `Axis`, `AxisEntry`, `BlockPartition`, `OperatorSchema` drafts and private-construction `CheckedOperatorSchema`. Matrix owns their assembly use and later their storage association. An axis entry contains an ordered coordinate key, Descriptor and difference role; points first supply a separate origin map. Shape equality includes ordered coordinate meanings, exact descriptor equality, partitions, logical entry map and declared structure scope. It excludes numerical precision, buffer addresses, value/source identities and batch ordinals. Measure aliases with different names remain unequal schemas even when an explicit conversion relates them (`def:nrz:quantity-schema-key`).

`check_operator` checks extents and products with overflow-aware metadata arithmetic, complete nonoverlapping partition coverage, axis order and every entry/block descriptor. For each position it checks the exact dimension quotient and the registered multiplication of the entry kind with its domain kind into the codomain kind. Row terms must have compatible difference meaning after explicit conversion. Homogeneous leaves declare one descriptor and provide original-expression evidence for each distinct entry expression; zero and structurally absent entries still have typed quotient contracts. A repeated checked schema may be shared, but newly supplied expressions must each be checked before zero elimination. Empty shapes are valid structural objects with no entry access; their normalized norm is zero, and they supply no nonempty solve admission (`rule:nrz:shape-entry-contract`).

`check_composition` and `check_addition` are descriptor-only operations: check ordered contracted axes, an explicit alignment/conversion if needed, compatible partitions and scalar kind rules, then derive output schemas. They execute no multiplication kernel. Scalar quotient/root tests also derive the homogeneous solve/inverse descriptor, QR's ratio Q/input-dimension R and an admitted half-dimension Cholesky factor. Their names denote dimension contracts only, not rank, invertibility, orthogonality or factor certificates (`rule:nrz:shape-composition`), (`rule:nrz:shape-solves-and-inverses`), (`rule:nrz:shape-factorizations`). General dual-space operation/factor execution belongs to bite 5 or 7; covariance pair axes are never represented by pretending an ordinary scalar kind has acquired an automatic reciprocal kind.

**Rule (Coordinate maps and structured entries)** · `rule:nrz:foundations-coordinate-maps`

`NormalizationContract` requires a positive exact typed difference reference for each domain/codomain coordinate, plus a compatible explicit origin for every point field. The first implementation admits exact rational reference coordinates; uncertain reference scales refuse. Check `Ahat_ij = A_ij S_X,j/S_Y,i`, `xhat_j = (x_j−origin_j)/S_X,j` and the corresponding right-hand-side map through units operations. A normalized descriptor retains the complete original kinds, roles, axes, reference and origin identities; zero exponents alone cannot construct it. Numerical reference conversions use the exact-import boundary and retain their enclosures. Restoration scales each entry's deterministic bound by its own inverse map and restores origins only to centers (`def:nrz:shape-normalization`), (`rule:nrz:shape-norms-and-conditioning`).

Logical entry order is `i + m*j`, regardless of eventual storage. `EntryMap` admits checked identity, selection and permutation maps, and a bounded exact linear/affine structural expansion from free coordinates. Every coefficient has the required quotient descriptor, every offset has the output difference meaning, and indices/extents are checked before use. Composition retains original free-entry identities and typed zeros. Exact symmetric duplication is a special expansion: mirrored positions select the same free coordinate, not independent copies. Structure records CenterOnly versus WholeFamily; only WholeFamily can restrict companion coordinates (`rule:nrz:structured-companion-coordinates`).

For a declared expansion T, retain the formal paired conversion `U_full = T U_free Tᵀ` as checked contraction/coordinate evidence; do not evaluate statistical propagation. Retain the exact norm metric `TᵀT` or refuse a requested packed-norm equivalence when that metric is outside the bounded descriptor fragment. Symmetric duplication yields diagonal weights one on diagonal entries and two on off-diagonal free entries, since each off-diagonal square occurs twice. No unweighted packed norm is certified. Affine offsets of the expansion do not enter covariance or difference bounds. Shape/resource limits bound entries, coefficients, contraction checks and exact arithmetic; dense materialization is not required just to share a repeated schema.

**Definition (Checked companion shapes)** · `def:nrz:foundations-companion-shapes`

`CheckedCompanionSchema` distinguishes entrywise radius/standard arrays, a marginal variance array, full paired covariance, cross-covariance and one scalar norm radius. Each declares its own extent and target selections. For an m by n center, full covariance has mn by mn logical entries; a norm radius has one entry with a named norm and coherent homogeneous or normalized coordinate interpretation. Target selections contain value identity, value version and logical-entry indices, not just schema IDs. The same checks support scalar quantities as one-entry values (`def:nrz:companion-shape`), (`def:nrz:covariance-shape`), (`def:nrz:numerical-error-shapes`).

`PairedDescriptor` uses existing covariance Descriptor construction for product dimensions/measures. Descriptor-only Correlation and RelativeCovariance use separate `PairedKind` variants retaining both target kinds and their standard/reference keys, zero Dimension and coherent ratio measure; they are not ordinary scalar `Kind::Ratio` values. All fields are private and derived by the checked constructor. They cannot be passed to scalar Registry operations or silently installed as schema-v2 scalar companions. Correlation declares `Defined`, `UnavailableZeroVariance` or `Unknown`; Defined requires explicit positive-standard obligations that numerical binding must discharge, while zero variance cannot produce filled zero/one entries. Relative covariance requires two exact nonzero difference reference contracts. Normalized covariance under arbitrary scales retains covariance interpretation and is not renamed correlation (`rule:nrz:correlation-and-relative-shapes`).

**Rule (Shape evidence delivered here)** · `rule:nrz:foundations-shape-evidence`

Bite 4 delivers all descriptor checks for typed entry quotients, homogeneous/block coverage, ordered identities, relative references, paired covariance and structured expansion/contraction maps. Test wrong dimensions/kinds/roles, reordered same-dimension axes, untyped zeros, invalid partitions/extents, stale selections, missing paired maps, zero/uncertain references, undefined correlation and CenterOnly structure used for family covariance. Use the truss force/displacement quotient and the four resistor blocks, including its zero resistance block, from (`prob:exemplars:spring-mass-truss`) and (`ex:nrz:resistor-shape-covariance`). Recreate the smaller exact resistor coordinate/covariance descriptor example from (`ex:nrz:descriptor-resistor-prototype`) without recreating its toy solve kernel.

This is the foundations share of (`req:nrz:shape-implementation-evidence`). Storage, strides, aliasing, heap generations, numerical transpose/solve/factor execution and certificates remain bite 5; general eigen/power/function domains remain bite 7. Tests of formal `T U Tᵀ` or sensitivity contractions establish descriptor and dependency consistency only. They establish neither an actual Jacobian, covariance PSD, source independence, an approximation's adequacy nor a deterministic rounding bound. Those limits are preserved in every checked result (`rule:nrz:shape-data-time-evidence`).

## Immutable declaration and binding evidence · `sec:nrz:foundations-evidence`

**Definition (Checked declaration snapshot)** · `def:nrz:foundations-declaration-evidence`

`Context::freeze` consumes the mutable declaration builder, performs `check_all`, and returns `CheckedDeclarations` owning the original expressions, used and unused declaration results, semantic header, complete Registry/function snapshot, exact conversion maps, dependency closure, companion evidence and its CAS owner. Retaining the owner keeps OriginalForm/Handle references inspectable. Its declaration payload is immutable even if the CAS internally admits later derived coordinates. Existing `CheckedExpression` remains a check result; only the evidence-owning frozen set authorizes reusable binding. A freely assembled vector of checked results cannot forge that set.

Assign a private scoped SnapshotId and monotonically increasing builder revision. Every successful declaration/function change advances the revision; failed admission changes neither payload nor revision. A rebuilt context has a new scope even when its text is equal. Registry/exponent-policy changes require a new snapshot. Evidence compares exact stored identities/revisions and maps; hashes may accelerate comparison but cannot authorize reuse by collision. No persistent encoding or global identity claim is introduced. All retained original occurrences, including canceled and zero-multiplied children, remain reachable. A transformed or substituted expression is checked as new original occurrences before receiving new evidence (`rule:nrz:plan-validation`).

**Definition (Values and sources remain separate)** · `def:nrz:foundations-value-source-evidence`

`ValueKey` and `ValueVersion` name an owner's immutable mathematical value instance and content revision; `RepresentationKey` additionally identifies precision and conversion. `EntryTarget` selects ordered logical entries from that version. `SourceKey` names a separately declared common source and source revision. A `SourceDeclaration` contains its descriptor, uncertainty mode and parameter declarations, coverage/assumption claims and any explicit transformations from another source. A checked `SourceSet` rejects duplicate keys with conflicting payloads, conflicting revisions asserted as one current source, unknown transformations and cycles. Distinct sources with no joint declaration retain Unknown correlation. Copying a value creates a new value/representation while retaining its source dependence.

Scope tokens use a checked process-local identity allocator that refuses exhaustion; counters never wrap. External owner/version facts are assertions supplied to this layer, not heap-resolution proofs. Units can check their consistency and compare snapshots, while matrix must later establish that facts describe actual live storage. Textual `Evidence.source` from current problem data is retained as provenance, never promoted by string equality into a versioned SourceKey. No units type resolves a matrix handle or depends on an arena (`dec:nrz:heap-ownership-and-sharing`).

**Rule (Version-sensitive binding revalidation)** · `rule:nrz:foundations-binding-revalidation`

`BindingFacts<P>` supplies explicit declaration-key associations, actual value/representation versions and schemas, companion targets, source set, shape/entry maps, exact conversions, references/origins and assurance policy. Checking it against `CheckedDeclarations` returns immutable `CheckedBindingEvidence<P>` with those precise dependencies. The check compares declared and actual dimensions, kinds and roles, discharges concrete shape/metadata obligations, verifies every paired target and reference, checks common-source consistency and rejects unsupported modes. Numerical admission separately checks finite centers, count-domain membership, nonzero denominator/reference intervals and applicable budgets. Declarative nonzero and positive claims never substitute for those scans.

`revalidate` accepts fresh owner facts and requires every captured dependency to match. A changed center/version, companion parameter, source assertion, descriptor/measure/origin, normalization scale, precision, function/rule environment or policy returns `StaleEvidence` with the differing key; construct a new checked binding rather than updating an old witness. Exact equal schemas with different value/source keys are not interchangeable. Unrelated new values need not invalidate a witness whose retained dependencies are unchanged. A pure immutable schema transformation can be cached by snapshot/map identity; it does not cache value-dependent domain or budget success. Shared sources are checked jointly across supplied binding facts, without implementing batch execution (`rule:nrz:binding-validation`), (`rule:nrz:descriptor-lifetime-and-mutation`), (`rule:nrz:computation-cache-validity`).

Matrix's bite-4 `Assembly<Draft>` and `SchemaBinding<P, Draft>` consume these units contracts. Only their checked states lend `PhysicalSchemaView` or `NormalizedSchemaView`; these are schema/coordinate witnesses with no raw numerical buffer access. A `SchemaCandidate` is tied to the checked binding identity and becomes a `PublishedSchema` only after output descriptor/companion/map validation. This is schema publication, not value publication or certification. The binding holds an immutable borrow of the facts owner, so changing facts through that owner while the view remains live fails to compile. Future matrix heaps and physics plans must recreate the same invariants at actual storage/execution boundaries (`def:nrz:checked-descriptor-boundary`), (`rule:nrz:descriptor-publication-validation`).

## Data-time and docgen boundary · `sec:nrz:foundations-data-time`

**Procedure (Original declarations meet numerical values)** · `alg:nrz:foundations-data-integration`

Start with the existing semantic header, Registry and explicit declarations. Parse with Context::parse against the CAS header; run check_all, check_against/check_equation and, for operators, the additional shape checks before converting or substituting any numerical coordinate. Freeze the resulting evidence. Bind numerical Quantity/Count values through explicit declaration keys, with metadata in a separate tagged field that cannot be supplied as a quantity operand. Check actual source, companion and reference relationships, then execute only a separately supported native scalar operation and derive its output descriptor/companion. A valid original formula does not automatically select an evaluator: unsupported numerical functions, rational powers or uncertainty modes return `UnsupportedOperation` with the original location.

The representation question is graph-first: original occurrences and mathematical operations stay in the CAS graph, and units evidence refers to those handles and occurrence paths. There is no duplicate algebra AST, string-rewriting evaluator, numerical interpretation of a normal-form string, or request to turn the scalar CAS into matrix algebra. Matrix axis and contraction records are client declarations validated by units. Native elementary quantity methods use the same descriptor authority; arbitrary client recipes still need original-expression evidence and an operation-to-recipe contract at their later planner boundary. A CAS equality, including one with residual domain conditions, is neither a numerical rewrite license nor an enclosure theorem (`rule:vision:check-before-normalization`), (`rule:vision:algebra-domain-boundary`).

`CompanionEvidence::Established` and `Propagated` continue to mean checked relationships and allowed contributor dependencies. They do not validate the chosen uncertainty formula, its derivative or its statistical assumptions. Bind their named targets/contributors to actual value and source keys before numerical use, retaining contributors even under zero/cancellation. Numerical transformations issue new target/conversion evidence and retain the original declarations; copying a propagated status onto a changed target is refused.

**Rule (Schema ownership and generated evidence)** · `rule:nrz:foundations-docgen-boundary`

Docgen continues to decode and revalidate schema v2 with the same units/CAS checks at data, render and check boundaries. It never trusts a serialized checked flag or turns the current `uncertainty = none` alternative into physical exactness. All seven problems and three adversarial source inputs retain their existing supported/unsupported classifications, source values, identities and documentary closed forms. A units API change needed for snapshot ownership is integrated atomically with its docgen caller adaptation; no foundation test relabels an unsupported formula as executable. Numerical quantity construction is tested at the units public boundary using explicit runtime import/coverage choices, not by making docgen execute the engine.

The problem-data schema lane owns wire fields, version admission, parser/checker limits, generator diagnostics, input migration and regenerated datasets/catalogues (`spec:nrz:problem-data-schema`). Versioned sources, shape axes, paired entry maps and batch-axis roles require that lane's explicitly admitted future schema version; this document defines the reusable runtime contracts only. Current free-text source/assurance claims cannot supply those missing fields by inference. Schema tests remain in docgen's gate, including missing/unknown symbols, cycles, wrong scales/offsets, count/ratio/metadata confusion, stale generated evidence and legacy-v1 refusal. Existing table shape validation is never reported as formula or numerical validation (`req:nrz:problem-data-evidence`).

## Verification inventory · `sec:nrz:foundations-tests`

**Rule (Independent rational oracles)** · `rule:nrz:foundations-independent-oracles`

Expected mathematics uses a test-only rational path independent of all production scalar, accuracy, units conversion and CAS routines under test. For binary boundary cases, decode sign/exponent/significand directly to integer powers of two in `num-bigint`/`num-rational` development-only helpers; compute exact add/sub/mul/div/FMA and compare the production endpoints as rational numbers. For square roots require nonnegative endpoints with `lo² ≤ input ≤ hi²`; for an upper norm require its rational square to dominate the exact sum of squares. No oracle uses the production sqrt, norm, nextafter enclosure, exact-import search, units Conversion::apply or CAS equality checker to obtain its expected bound. Larger precision, randomized sampling and round-trip agreement alone are not truth.

For rational conversion tests derive the scale/shift independently from explicit fixture fractions and compare with decoded output bounds. For count/domain and dimension tests use independently enumerated integers and seven rational component expectations, not production dimension arithmetic to manufacture the expected result. The Rump oracle evaluates its original rational polynomial with exact test arithmetic and checks the returned interval directly against `−54767/66192`; it never constructs the target interval with the scalar code under test. Fixed adversarial cases require a meaningful successful enclosure on admitted small inputs as well as permitted wide enclosures/refusals on stress inputs, so an implementation refusing everything cannot pass.

**Decision (Four test layers for each crate)** · `dec:nrz:foundations-test-layout`

Use the repository's four-layer layout: inline private tests only for inaccessible invariants, crate-interaction tests in `src/tests/`, public conformance modules in `tests/conformance/`, and complete public lifecycles in `tests/integration/`, wired through `tests/public.rs` (`dec:nrz:cas-solving-design-test-layout`). Shared fixtures live in `src/testing/` with the public/private harness separation; conformance and integration imports exercise the actual public facade. Migrate affected scalar/units/matrix tests without dropping their semantic assertions, except the expressly retired solver capability. Docgen adapts relevant tests without an unrelated whole-suite rearrangement. Rustdoc compile twins are public conformance evidence, not a fifth logical layer. Each assertion belongs at the outermost layer that can express it.

**Rule (Semantic and data-time refusal inventory)** · `rule:nrz:foundations-semantic-tests`

Retain current original-expression tests and extend their numerical binding: reduced rational exponents, integral-policy refusal, equal-exponent wrong kinds, count/ratio/angle/mole separation, exact count imports and invalid fractional results, structural metadata isolation, affine role table, typed physical zeros and invalid original operands under zero/cancellation/zero powers. Exercise admitted roots/powers, scalar solve quotients, homogeneous QR/Cholesky descriptor relations and registered frequency kinds, while separately refusing unsupported numerical powers/functions. Preserve original spans, declaration chains and both covariance sides in diagnostics. No optional static adapter is introduced; any later adapter must agree with descriptor authority over its declared subset.

Data-time positives include observable/uncertainty expressions, forward references and independent companion descriptors. Negatives include missing/unknown symbols/functions, unused cycles, absent scales, wrong offsets, nonzero claims contradicted by bound values, metadata in a quantity slot, wrong target/reference, unsupported legacy formulas, exhausted original/coordinate budgets and forged generated status. A declared but dishonestly defined reporting name is not detectable by spelling; exact scale definitions remain reviewed input assumptions. Cross-layer tests verify that check success alone supplies no scalar enclosure, covariance PSD, numerical Jacobian or source independence.

**Rule (Arithmetic and assurance refusal inventory)** · `rule:nrz:foundations-arithmetic-tests`

Check both precisions against independent rationals at normal/subnormal boundaries, signed zero, minimum subnormal, maximum finite, exact and inexact cancellation, halfway conversion ties, underflowed products, explicit FMA cancellation, overflow, zero-containing divisors and negative-root intervals. Include products with separate input/computational radii and mixed interactions, the division bound above, root intervals touching zero, repeated integer powers, and scaled norms whose direct squares overflow. Require deterministic order within each admitted environment; cross-environment bit identity is not promised. Unsupported environment admission refuses.

Conversions test multiplicative/affine maps, exact dyadics and non-dyadics, round trips within carried bounds, no offset in radii/standard/variance/covariance, independently rounded statistical parameter errors, paired covariance scale products, source-preserving precision changes and failed conversion atomicity. A dimensioned value's relative uncertainty remains a ratio with its bound reference; count standard uncertainty may be non-integral; mixed-dimension covariance remains a product. A wrong count measure, symbolic scale, uncertain normalization reference, incompatible point, missing source cross relation or unsupported statistical binary operation refuses explicitly. Test every exact/provenance/shape budget immediately below, at and above an independently measured boundary, without inferring that resource exhaustion disproves the mathematics.

Assurance tests distinguish represented-only exactness from physical-input enclosure, exact-decimal import error from measurement radius, and parameter evaluation bounds from statistical coverage. Widening cannot erase prior error; narrowing adds displacement exactly once. A missing deterministic source refuses DeclaredInputs even when nominal computational bounds are available. Budgets test exact equality, proven failure, unresolved threshold and NotRequested, with equivalent measures using the same physical reference. Dependency checks cover every edge category in (`tab:nrz:foundations-dependencies`). The host gate remains authoritative for lint, rustdoc, public compile twins, workspace tests and documentation fixed point; this design round runs none of those toolchain checks.

## Implementation lanes and handoff · `sec:nrz:foundations-lanes`

**Decision (CAS requests and representation boundary)** · `dec:nrz:foundations-cas-requests`

No new CAS API or representation is required. The graph-first question is whether an original occurrence, its immutable semantic header and existing exact Rational operations can carry each foundation obligation. They can: quantities retain original handles and client evidence, scalar coordinate conversions use Rational, and shapes/target identities remain units declarations. Existing `Context::cas` and CAS syntax inspection suffice for retained-original diagnostics. Do not request a second algebra, float nodes, unit-bearing CAS objects, heap handles or a noncommutative matrix extension. If implementation discovers an actual public-facade obstruction, send the CAS owner a graph/handle operation request with its minimal missing operation and reason; do not patch `crates/cas/`, emulate an unbounded second rational engine, or bypass the original checker. Such a discovery is a blocked capability, not authorization for a hidden CAS change.

**Rule (Findings for other document owners)** · `rule:nrz:foundations-owner-findings`

The implementing commits must update the scalar/matrix/units README notices and their templates to describe only their then-current supported surfaces.
