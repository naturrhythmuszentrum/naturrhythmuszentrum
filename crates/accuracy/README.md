# nrz-accuracy · `guide:accuracy:overview`

`nrz-accuracy` supplies dimension-neutral nonnegative bounds and numerical policies over `nrz-scalar`'s sealed binary32/binary64 formats. It owns no heap, value ledger, physical assurance token, source model or provenance store. A magnitude acquires physical meaning only when its caller validates the target, coordinates, coverage and versions. See the matrix-core design for the matrix owner's responsibilities.

`Nonnegative<P>::new` admits finite nonnegative magnitudes and canonicalizes signed zero. Its private state proves that numerical invariant, not that a caller-supplied magnitude bounds a physical error. `add` returns an outward upper sum and `scale` an outward upper product, including underflow. Each delegates to scalar enclosures under an explicit `ArithmeticContext`; an unavailable finite endpoint returns the scalar error through `AccuracyFailure`. No fallible arithmetic is hidden behind operator traits.

`BoundVectorRef` validates and borrows a plain immutable slice without allocating or changing its bytes. `sum` and `dot` use increasing-index left folds starting at zero; each dot product encloses multiplication before addition. Unequal lengths refuse. Overflowing intermediates refuse even if another evaluation order might succeed. Empty reductions are exactly zero.

`norm` returns a `NormSummary` retaining `NormKind`, logical entry count and a nonnegative upper bound. `One` is the sum of entries and `Infinity` their maximum; these are entry norms, not induced matrix norms. `Euclidean` and `Frobenius` use scalar's enclosed power-of-two scaling, squared sum, square root and outward restoration. All empty norms are zero. The caller supplies every logical entry and structural multiplicity, including both copies of a symmetric off-diagonal entry, in the intended coordinates. This crate checks neither matrix shape nor a physical metric.

```rust
use nrz_accuracy::{BoundVectorRef, NormKind};
use nrz_scalar::ArithmeticContext;

let context = ArithmeticContext::new()?;
let entries = [3.0_f64, 4.0];
let summary = BoundVectorRef::new(&entries)?.norm(NormKind::Euclidean, &context)?;
assert!(summary.upper().get() >= 5.0);
# Ok::<(), nrz_accuracy::AccuracyFailure>(())
```

Public conformance tests independently decode binary values into exact rationals for addition, scaling, contractions and all named norms. Root-norm tests compare squared returned bounds with exact sums of squares. Both formats cover small successes, halfway contributions, subnormals, underflow, huge/tiny mixtures, zero identities and explicit overflow. Public lifecycles compose contributions and preserve logical multiplicity; compile twins reject forged nonnegative and borrowed-vector state. Production depends only on `nrz-scalar`; the rational libraries are development-only oracles.

`Budget::new` takes nonnegative absolute and relative tolerances and a strictly positive characteristic difference scale, all interpreted as exactly represented numbers. `Budget::from_enclosures` admits lowered coefficient enclosures only when both tolerance lower endpoints are nonnegative and the scale lower endpoint is positive. The scale remains mandatory for a purely absolute budget. A shifted point center is never an implicit relative reference; the caller checks physical descriptors and the named norm/coordinates.

`assess_budget` encloses `absolute + relative * reference_scale` with scalar arithmetic and retains the threshold in a `BudgetAssessment`. It returns `Met` only when the supplied error upper bound is at most the threshold's lower endpoint, `Exceeded` only when it is strictly greater than the upper endpoint, and `Unresolved` for the remaining overlap. `Exceeded` says the available bound fails the threshold; it does not prove the actual error is too large. No request produces `NotRequested`, never `Met`. Proved nonnegativity permits clamping a negative underflow endpoint to zero. Tolerance overflow returns the scalar cause rather than a successful comparison. `Budget::widen` exactly widens coefficient endpoints and preserves all prior widths.

`Limits` sets finite cumulative attempt and work allowances; zero means no allowance, with no unlimited sentinel. Its `WorkBudget` reserves an attempt and its known work atomically before execution and charges additional work before an operation. Failed reservations change neither counter; successful reservations are never refunded after failure. Checked integer addition prevents wraparound. The caller defines a reproducible work unit and includes numerical verification in its charges.

`RecoveryPolicy` sets a maximum number of refinements after the initial execution at each precision, a positive stagnation window and `Promotion::Never` or `Promotion::F32ToF64`. Zero refinements is valid. Starting a `Recovery` fixes its budget and cumulative limits. `begin_attempt` reserves resources before a kernel; `charge` covers further work; `complete` accepts a caller-certified radius and recomputes the full budget comparison. `fail` records an arithmetic refusal. Invalid phase transitions return errors without advancing counters. Recovery owns only numerical policy state: it executes no solver, retains no numerical buffers and grants no physical assurance.

Budget success stops immediately; absence of a request stops after the first available bound as `NotRequested`. Otherwise, consecutive attempts without a strictly smaller best certified radius trigger stagnation, followed by the per-precision refinement limit. A decrease back to an old best does not reset that window. Resource exhaustion and arithmetic failure stop explicitly. `RecoveryEvidence` records precision, total attempts/work, refinements, stagnation count, best/last available radii, the last available comparison and the stopping reason. A failed threshold evaluation retains its newly supplied bound with no comparison. A failed attempt without a new bound retains earlier independently valid evidence. The heap owner retains snapshots per attempt with target/version and algorithm records; a reduced residual alone is never a success condition.

A stopped binary32 run may consume itself through `retry_f64` only when promotion was authorized and its stop was a refinement limit, stagnation, nonfinite arithmetic or overflow. This returns a fresh binary64 policy run together with the earlier evidence. It transfers cumulative limits and charged work, widens the fixed budget exactly, and resets per-precision progress without carrying forward a result bound. The caller explicitly converts inputs with their existing error contributions and computes fresh certificates. Binary64 runs expose no further promotion. Successful, unrequested, resource-stopped and unsupported-environment outcomes cannot authorize retry.

Budget tests include exact absolute/relative equality, both sides of the threshold, interval overlap, absent requests, invalid reference scales, overflow and independent rational examples where a rounded-up tolerance would falsely accept. Recovery tests cover state transitions, exact resource limits, integer overflow, zero refinement, strict progress and stagnation, nonfinite attempts, retained failure evidence and explicit precision retry. Public vector-to-policy lifecycles compare every norm to an exact rational oracle before a decision; retry tests preserve coefficient widths and cumulative charges. An inline private test covers the otherwise inaccessible exhausted attempt counter; all externally expressible assertions live in the public test target.
