# nrz-matrix · `guide:matrix:overview`

`nrz-matrix` owns a homogeneous descriptor heap with separate binary32 and binary64 faer arenas. A scalar is a 1×1 region. Values and declared absolute bounds have separate storage regions and units descriptors; every bound names the exact identity and version of its entire target region. Heap coordinates never enter CAS arithmetic. See the matrix-core design for the complete operation contract.

`Heap::import_represented` admits finite coherent coordinates with explicitly represented-only coverage. `Heap::import_declared_bounds` atomically admits finite centers and nonnegative finite componentwise radius entries, deriving the radius descriptor through units. These supplied bounds remain caller assumptions. Imports use logical column order, canonicalize signed zero, and retain point/difference roles. Floating count storage and noncoherent coordinate imports refuse. Unsupported nested relative-radius derivation preserves the units error.

Opaque `Handle<Category, P>` locators carry a heap scope and descriptor occupation generation. Value and companion access checks ownership, occupation, category, precision, region bounds and target versions before lending a read-only `RegionView`. Equal schemas are interned using exact descriptor equality without merging value identities. Each arena slab owns a one-column faer matrix; logical rectangles select its entries through checked layouts. `RegionView::export` returns an owned raw copy without evidence or a declaration of source independence. Live borrows prevent heap mutation.

`HeapLimits` bounds descriptor slots, elements per precision (including companions), and immutable schemas. Preparation scans and validates the complete bundle, reserves metadata capacity and builds every slab before an allocation-free publication step. Replacement scratch is bounded by the same element limit as the new live bundle; old and prepared storage may coexist, so peak heap-owned addressable elements can reach twice that limit, in addition to backend padding and metadata. A refusal publishes no partial value or companion. Rust allocator aborts remain outside the recoverable-capacity contract. Process-local identities never wrap and make no persistence promise.

```rust
use nrz_matrix::{Extent, Heap, HeapLimits};
use nrz_units::Descriptor;

let mut heap = Heap::new(HeapLimits::default())?;
let imported = heap.import_declared_bounds(
    Extent::new(2, 1)?,
    &Descriptor::ratio(),
    &[2.0_f64, 3.0],
    &[0.125, 0.25],
)?;
let value = heap.value(imported.value())?;
let copy = value.region().export()?;
assert_eq!(copy.len(), 2);
# Ok::<(), nrz_matrix::HeapError>(())
```

`Heap::replace_represented` and `Heap::replace_declared_bounds` require the caller's captured `ValueVersion`. They preserve the value handle and base `ValueId`, advance the whole base version exactly once, and atomically replace the entire supported companion set. Extents, quantity schemas and precision remain fixed. Even identical center bits with changed bounds advance the version. Represented replacement explicitly removes declared-input coverage. Captured old bound handles become stale; unrelated values and companions remain valid. A stale expected version, invalid payload, capacity refusal or exhausted version leaves the old bundle unchanged.

`Heap::retire` retires the whole value/bound bundle and releases its storage. Vacant descriptor and arena slots are reused with incremented generations; exhausted generations are never reused. Old handles and cached internal arena keys cannot revive. A fresh import has a fresh `ValueId` and starts at version one even when its schema and bytes match retired data. Schema capacity counts immutable lifetime entries, including those no longer used by a live value. Retiring a base also retires every alias of that occupation. Retiring only an alias releases its descriptor; nested aliases already point directly to the base.

`Layout::strided` checks signed affine extents, products, sums and both extreme addresses against the owning region. `Layout::gather` validates each explicit index under its supplied work limit. Repeated indices and zero strides are valid read selections. Empty maps have no addressable entry. All maps use logical order `i + m*j`; a selection of a view addresses that view's logical entries, and `Layout::compose` checks and flattens the map into base-region offsets. General composition refuses if enumeration exceeds the work limit.

`Heap::alias` creates a descriptor pointing directly to the base value. It retains the base identity and resolves its current version and coverage on every read, including after whole-base replacement. The selected extent and entry map are available from `RegionView`; its schema identity names the owning homogeneous schema before selection. `ValueView::bound` names the whole-base companion, while `Heap::selected_bound` applies the identical entry map to the bound and exposes the base target and current version. Checked replacement through an alias first proves its output injectivity, copies the base into fresh scratch, scatters selected entries through checked indices and publishes the complete base bundle once. All aliases, including disjoint selections of that base, observe the new version. Old companion handles become stale. Represented replacement drops the entire base's declared coverage explicitly; bounded replacement keeps untouched bounds. A partial selection cannot introduce declared coverage on a represented-only base because the other entries have no bounds. A bijective whole-base selection can supply that complete coverage.

`HeapLimits::with_layout_work` bounds gather validation, general composition and raw/packed copies (default 1,048,576 entries). Copy size is also bounded by the per-precision element capacity. `RegionView::pack` copies any admitted map through checked indices into a fresh contiguous faer slab in logical column order. `PackedRegion` is an owned raw snapshot with read-only access, independent of subsequent heap changes; it carries no publication or numerical evidence. The temporary raw copy and packed slab may coexist during packing. No backend mutable view escapes.

`Heap::validate_outputs` checks injectivity within each destination and mutual disjointness across the whole destination list. Dense affine maps, including reversed and transposed contiguous maps, use exact sorted address ranges. Other maps enumerate and sort all destination addresses under one combined layout work limit. Duplicate addresses refuse; exhausting the limit refuses even when the destinations might be disjoint. An overlapping bounding box is never accepted as a proof. The number of output descriptors is separately bounded by descriptor capacity. Inputs remain read-only and may overlap; all numerical mutation stays in independent scratch.

`Heap::compact` requires an exclusive heap borrow, so live views and future exclusively borrowed evaluations prevent compaction. It prepares fresh precision-separated slabs and dense arena slot tables, validates every affected value, companion and alias map, then installs all indirection and the successor physical epoch together. It retains one slab per owned region and stable descriptor slot indices. Value versions, schemas, bound handles and target identities remain unchanged when only storage moves. `RegionView::layout_epoch` exposes the refreshed physical revision; cached internal regions with an older epoch refuse even if an arena slot/generation coincides. Epoch exhaustion and all preparation failures leave the current heap unchanged. Compaction work counts copied entries across both precisions plus explicit gather entries. Old and new slabs may coexist during preparation, with one additional raw region copy; compaction introduces no numerical or source-independence claim.

The prototype solve capability has been removed: `DenseSystem`, bare `certified_solve`, mutable-field `Outcome`/`Report`, the old backend adapter and solver-only tests are retired. This heap is not a replacement solve implementation or verification of one. Historical feasibility records and adversarial fixture data remain intact. Production solving returns at the later checked operation boundary.

The homogeneous heap binds the ordered shape contracts described below through checked copy operations. Heterogeneous storage, general numerical kernels, conversions and covariance/source models remain unavailable. `Factor` and `Workspace` are category markers only. The only scalar dependencies used here are the sealed primitive-format contract, finite admission, zero and comparison; no prototype scalar interval or certificate is used.

`ShapeDraft::check` admits ordered physical operators over a retained `Rc<CheckedDeclarations>`. `AxisEntry` creates a fresh coordinate identity; cloning preserves it, while equal names, dimensions and measures do not. `Axis` carries a complete `Partition`. Every `BlockDraft` must respect those boundaries, and the complete assembly must cover each logical entry exactly once. Empty shapes use an empty block table. `ShapeLimits` bounds axes, entries, blocks, common refinements and contraction work; units applies its own bounded exact descriptor algebra.

Each `EntryDraft` declares a scalar schema, a typed structural zero, a named frozen original, or a separately checked original from that same snapshot. The checker uses units' output-over-input `PairingWitness` and scalar multiplication rules for every entry, including zeros. It retains the original checks and exact conversion into axis-quotient coordinates. Points cannot enter a linear operator. Newly supplied checked originals must match the retained snapshot even when their dimensions agree. Directly declared schemas claim no expression evidence.

`CheckedShape::sum` requires explicit domain and codomain `AxisAlignment` bijections and retains their exact conversion maps and common partition refinements. `product` checks ordered contracted coordinates and concrete scalar multiplication and addition before considering zeros; an empty contraction yields typed zero entries. Convertible contracted measures require an explicit prior alignment or selection. `EntryMap` records column-order selection, repetition, composition and reshape independently of storage addresses; `CheckedShape::select` rechecks the new physical axes.

`dual_transpose` records the logical entry permutation and reciprocal formal dual axes. It preserves coefficient dimensions and is involutive; it does not swap the physical axes as an inverse would. Formal duals retain units pairing witnesses without registering scalar reciprocal kinds. Direct scalar assembly or selection over formal duals refuses. `solve` and `inverse` check nonempty square envelopes and derive the reversed quotient axes, with positive RHS width required for solves. Those formal result entries need no invented scalar quotient kind. `identity` derives ratio diagonals and typed off-diagonal quotient zeros, including on heterogeneous axes. Shape checks establish no invertibility, factorization, orthogonality or numerical accuracy.

`QrShapeContract` checks homogeneous dimensionless-Q/input-typed-R envelopes and the ordered intermediate axis through the same composition checker. `CholeskyRootContract` asks the frozen units registry for the admitted half-power descriptor, preserving exponent-policy and missing-kind-rule refusals. Neither contract proves factor reconstruction, orthogonality, triangularity, positive definiteness or existence of a matrix root; numerical factor resources and their metric obligations remain separate.

`StructureScope::CenterOnly` and `WholeFamily` distinguish center structure from constraints on every admissible perturbation. Derived shapes retain operand contracts and the original declaration owner. A copied shape or repeated logical entry creates neither a numerical value nor a new independent source. Public shape fields remain private; consumers obtain checked contracts only through validation and the supported descriptor operations.

`ReferenceScale` defines one positive exact source-free unit of a typed difference measure. Symbolic, zero and negative scales are already refused by units' `Measure`; points, counts and relative kinds cannot become normalization references. References have distinct definition identities even when their labels and exact scales agree. `PointOrigin` defines the zero point of an exact point measure and likewise retains its identity. These constructors define exact schema constants; they accept no heap value, uncertainty assertion or numerical calibration operand.

`CoordinateMap` checks one reference per ordered axis entry and one compatible origin exactly for point coordinates. It maps coherent physical centers to normalized coordinates and retains exact restoration maps. `NormalizationSchema` checks one shared X/Y/W system for a square solve and records `A_hat = S_Y^-1 A S_X`, `B_hat = S_Y^-1 B S_W` and `X_hat = S_X^-1 X S_W`. Every matrix entry retains its typed row/column reference quotient. Center maps subtract origins first. For an affine vector equation, the right-hand-side recipe then adds the separately recorded `S_Y^-1 (O_Y - A O_X) S_W` correction, so the solved physical equation retains its variable-origin contribution. Solution restoration adds its declared origin only to centers. Separate zero-shift maps restore differences, deterministic radii and numerical evaluation errors; paired covariance restoration must use both sides.

Point origins are shared by each row across all ratio RHS columns, with each column retaining its own reference scale. Non-ratio column origins explicitly refuse until an entry-origin schema exists. Arbitrary distinct origins per matrix entry are not inferred from axis origins. Formal dual normalization also refuses because units supplies no scalar dual kind. Exact maps are retained as units conversions; numerical coefficient lowering, normalization/restoration evaluation and their error companions are later kernel work. No numerical normalization is claimed by a successful schema check.

`StructuredExpansion::check` admits bounded exact source-free affine maps `vec(A) = T z + d` with retained free-coordinate identities, typed coefficients, typed omitted zeros and exact offsets. Expansion outputs and offsets use coherent physical coordinates; free inputs use their declared difference measures. Explicit duplicate coefficient positions refuse, and an expansion cannot contradict a logical structural zero. Logical entries need concrete scalar descriptors; formal solve/inverse quotients require a separate scalar admission first. `ExactCoefficient` defines an exact scalar constant from a zero-shift units map factor in a declared difference measure, including signed coefficients and exact zeros. Its exact algebra is confined to descriptor constants.

Only `WholeFamily` expansion authorizes the same map on perturbations and both covariance axes. `CenterOnly` refuses companion compression. `metric(LogicalFrobenius)` derives the exact Gram matrix `T^T T` for homogeneous logical differences and coherent free coordinates. Symmetric duplication therefore weights an off-diagonal square twice. `PackedEuclidean` additionally requires the exact Gram identity and refuses ordinary symmetric packing. A heterogeneous physical norm or unsupported reference metric refuses; normalization does not silently supply an isometry. These metrics apply to differences, where `d` cancels; computing a center norm must also evaluate the retained affine offset. No symmetry declaration proves positive definiteness or physical self-adjointness.

`OperationDraft::copy` checks a native recipe with one fresh output per input. Each `CopyContract` retains its checked ordered shape, frozen declarations and concrete homogeneous difference descriptor. It explicitly defines one coherent unit reference for every domain and codomain coordinate through `CoordinateMap`; normalization and restoration therefore copy the represented entries exactly. This admits physical homogeneous differences as well as ratios. Points, heterogeneous entry schemas and formal entries without a concrete scalar descriptor refuse. General scales, affine origins and arithmetic kernels remain later capabilities. Empty rectangles use ratio schemas and have no addressable entries.

`Binding::new` requires a `CheckedOperation`. `validate` takes the exclusive heap borrow and captures every actual value identity/version, schema, logical selection and declared-bound occupation, schema and target version. It checks every concrete slot and structural zero, including zero radii for `WholeFamily` zeros. Inputs can overlap or repeat. `ExecutionLimits` bounds the slot count and the total selected centers plus carried companions per scan or private payload set. Heap limits also apply to the complete output reservation.

`Bound` owns the checked evidence and real private destination slabs and descriptor reservations. It uses the existing output proof to establish injectivity and mutual disjointness for all destination regions, including companions. `output_reservations` exposes future identities and schemas, never output handles. Dropping a binding releases the reservations without publishing a value. Binding preparation can coexist with one temporary zero payload set and its reserved backend slabs; both sets are bounded by the scratch entry limit. No caller callback runs in publication preparation.

`physical_input` lends an immutable `PhysicalView`. `normalized_inputs` lends the complete operation-ordered `NormalizedInputs` bundle with the binding's unique execution identity and its explicit coherent unit-reference interpretation. Companion entries follow exactly the same selected logical map. Neither view grants raw mutation. The exclusive binding and its shorter borrows prevent mutation, growth, compaction and another execution through the same heap until they end. Execution and reserved value identities use the checked nonwrapping process-local allocator. A published ordered shape retains its coordinate identities: a later binding must use those same ordered axes. A projected alias of a derived value needs a matching supported shape contract; matching dimensions or newly repeated coordinate names cannot reinterpret an output.

`Bound::evaluate` accepts only its own `NormalizedInputs` bundle and issues one unique candidate token after a successful exact copy. A `Candidate` owns unpublished centers and complete companions; it is neither cloneable nor a value handle. Repeated evaluation and foreign view bundles refuse. `Bound::publish` consumes the binding and candidate, independently rechecks every copied bit, finite bound, recipe revision, output extent, reserved identity/version and both directions of every companion target. The final `Outcome<Vec<PublishedBundle<P>>>` exposes all outputs together. No prefix becomes visible when a later output fails.

Publication fills the already reserved private slabs and prepares all immutable graph records, source edges and append capacities before changing visible state. The commit only installs prepared storage, schemas, descriptors and graph objects through the existing no-fail primitives. It runs no allocation, caller callback or numerical kernel. Internal bounds target the reserved fresh output identities and versions in that same commit. Existing inputs and their versions remain unchanged on every refusal. Scratch consists of the reserved slab set and candidate payload set, each bounded by `ExecutionLimits`; temporary preparation copies and ordinary allocator aborts remain subject to the heap's documented allocation contract.

`Failure` carries a typed cause and an unpublished `FailureRecord`. A later candidate or provenance refusal preserves each independently validated earlier `CopyEvidence`, including its exact input coverage, without a success handle or an exposed candidate payload. `FailureRecord::evidence` rechecks the particular claim's actual source and companion dependencies; `historical_evidence` supplies only the recorded attempt facts. The copy recipe asserts represented bit identity and retention of declared assumptions, not a new floating certificate, statistical model, numerical budget success or source independence.

The heap owns an immutable provenance DAG with separate monotone staleness flags. Each output node links its exact source selection, target version, operation record and optional earlier output parent. Two outputs copied from the same source retain that relation. Sibling outputs have separate dependency keys. Reverse source edges are traversed in topological order on evidence access, comparing value occupations/versions, schemas, layouts, precision and companion occupations/targets, and propagating stale parent state. A companion-only input change or any alias-wide base replacement invalidates its downstream claims even with identical selected center bits. Unrelated siblings remain readable. Compaction retains mathematical lineage while refreshing physical indirection.

`Heap::operation_record` checks the complete current operation; `Heap::provenance` checks an individual output node. `Heap::historical_record` retains immutable facts after sources change or retire and cannot authorize current access. The existing `Heap::value` and `Heap::companion` accessors also reject stale derived evidence. Record and node IDs are scoped to the heap. Reused descriptor slots cannot revive old source relations, and previously consumed candidate tokens cannot be replayed.

`ProvenanceLimits` bounds lineage depth, retained operation records plus output nodes, explicit source/target/operation/parent edges, accounted graph metadata bytes, and traversal/parent-search work. Limits refuse before graph publication. `provenance_usage` exposes retained accounting; `set_provenance_limits` refuses policies smaller than current usage. Byte accounting includes fixed record objects and conservatively charges full logical-map offsets, while immutable checked shape/declaration owners remain governed by their separate shape and units limits. It is metadata accounting, not a measurement of allocator overhead or peak process memory. Retained historical records count toward lifetime capacities. Failed publication leaves these accounts unchanged.

```rust
use nrz_matrix::{Binding, CheckedShape, ExecutionLimits, Handle, Heap, OperationDraft, Value};

fn copy_value(heap: &mut Heap, shape: CheckedShape, input: Handle<Value, f64>)
    -> Result<Handle<Value, f64>, Box<dyn std::error::Error>>
{
    let limits = ExecutionLimits::default();
    let operation = OperationDraft::copy(vec![shape]).check(limits)?;
    let bound = Binding::new(operation, vec![input], limits).validate(heap)?;
    let candidate = bound.evaluate(bound.normalized_inputs()?)?;
    let outcome = bound.publish(candidate)?;
    Ok(outcome.output().first().ok_or("missing copy output")?.value())
}
```

`Heap::retire` can reclaim a stale derived base and all its companions and aliases. Retirement checks live storage ownership, formats, layouts, schemas and direct target/reverse edges through a private structural snapshot; it neither reads numerical entries nor authorizes stale mathematical evidence. Historical operation records remain retained. Current compaction refuses while an unreclaimed stale derived descriptor exists; retire those stale bundles before compacting the surviving current heap. Later kernel lanes may broaden relocation of stale storage without weakening evidence access.
